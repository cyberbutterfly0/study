## 概念卡

### for 循环的三段式

- 是什么: 圆括号里固定三段——初始化（进循环前一次）、继续条件（每圈开始前判）、更新（每圈末尾做）。
- 关键机制: 三段用英文 `;` 分隔，不是逗号；三段都可留空但两个分号必须都在，所以 `for( ; a<b ; a+=1)` 合法。顺序固定：第1段 → 判第2段 → 循环体 → 第3段 → 回判第2段。
- 最小示例:
  ```java
  for (int i = 0; i < 3; i++) { ... }
  for ( ; a < b ; a += 1) { ... }
  ```
- 坑: 把三段当逗号分隔的参数列表（`for(a<b,a+=1)`），漏掉初始化段。

### 循环条件对循环体的筛选

- 是什么: 第 2 段在循环体**之前**判断，不成立直接跳出，所以进到体内的变量已经被筛过一遍。
- 关键机制: 体内能看到的值一定满足继续条件——「循环条件 `a<b` + 体内 `if(a>b)`」永远是 false，换任何比较写法都没用。
- 坑: 以为逻辑不成立是表达式写错，想换个比较符号；病根在"什么时候问"和"循环允许变量走到哪"。

### if / else 在循环里（待验证）

- 是什么: `if` 条件是每执行到这一行时现算一次，循环里同一行在不同圈可能走不同分支。
- 关键机制: 条件恒 false 说明"能改变它的变量在判断点之前没变过"。
- 待验证: 同一个 `if` 在不同圈走不同分支——用户还没实测。

## 易错点

- **`for` 里用逗号** → IDEA 报 `';' expected`（同一行报两次）。三段是"有先后的三个阶段"，分号才对。
- **「条件 'a>b' 始终为 'false'」** → 循环条件已经先挡掉了 a>b 的取值，改成"改成 true"没用，要看清判断时机。
- **绕开而不是解决** → 遇到恒 false 就把 `if/else` 删掉，程序跑通了但分支一点没练。判别标志：程序能跑 ≠ 题目练到了。
- **把 for 三段当方法参数** → 方法参数是并列输入，for 三段是有时间顺序的三个阶段，顺序本身就是语义。

**选择题**

1. `for` 圆括号里的三段，应该用什么符号隔开？
   - A. 逗号 `,`
   - B. 分号 `;`
   - C. 空格
   - D. 冒号 `:`
   - 答案: B
   - 判定: B。三段是"有先后的三个阶段"，分号正好表示分隔；逗号是并列列表，语义就不对——这也正是 IDEA 报「应为 ';'」的直接原因。A 是刚学 for 时最常犯的错，把 `for` 当成方法调用那样列参数了。C、D 根本不是 Java 的分隔符。
   - 踩坑场景: 写成 `for(a<b,a+=1)`，IDEA 同一行报两次「应为 ';'」，还以为是括号不配对。

   **术语**

   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | 初始化段 | 第 1 段，进入循环前只执行一次 | 起跑前摆好起点 |
   | 继续条件 | 第 2 段，每圈开始前判断一次 | 每圈问一句还跑不跑 |
   | 更新段 | 第 3 段，每圈结尾执行 | 跑完一圈挪一步 |

2. `for (int i = 0; i < 3; i++)` 里，第 3 段 `i++` 到底什么时候执行？
   - A. 每圈一开始，在判断 `i < 3` 之前
   - B. 每圈结束时，在循环体跑完之后
   - C. 只在第一圈开头执行一次
   - D. 循环全部结束之后才执行一次
   - 答案: B
   - 判定: B。固定顺序是：第 1 段（一次）→ 判第 2 段 → 循环体 → 第 3 段 → 回判第 2 段……所以第一圈进循环体时 `i` 还是 0。A 错——如果先加再判，第一圈就从 1 开始了，会漏掉 0。C 描述的是第 1 段。D 错，第 3 段在每圈末尾都跑。
   - 踩坑场景: 以为 `i++` 是先加再看，手算循环次数老是差一圈，画表格对照才发现顺序反了。

   **术语**

   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | 执行顺序 | 循环四步（初始化/判断/体/更新）的固定先后 | 流水线的固定工序 |
   | 迭代 | 循环体执行一次叫一轮迭代 | 跑完一圈算一次 |
   | 循环体 | 花括号里那段被重复执行的代码 | 每圈重复做的动作 |

3. `for (;;) { ... }` 这种写法合法吗？
   - A. 不合法，三段都不能留空
   - B. 合法，等价于 `while (true)` 的死循环
   - C. 不合法，至少要继续条件这一段
   - D. 合法，但只会循环一次
   - 答案: B
   - 判定: B。三段的内容都可以留空，但两个分号一个都不能少。第 2 段留空视为恒为 true，所以是无条件死循环。A 错，Java 允许留空。C 错，条件也不是必需的。D 错，恒 true 就等于永远跑下去。
   - 踩坑场景: 想写死循环却写成 `for()`（漏掉两个分号），编译不过还找不到原因。

   **术语**

   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | 死循环 | 条件恒为 true、永不退出的循环 | 原地打转出不来 |
   | 空段 | for 里留空的某一段 | 那一格空着不填 |
   | 恒真条件 | 判断结果永远为 true 的表达式 | 每次问都说"继续" |

4. 设 `a = 1, b = 2`，执行 `for (; a < b; a += 1) { if (a > b) 打印"A"; else 打印"B"; }`，输出是什么？
   - A. 只有一次 `A`
   - B. 只有一次 `B`
   - C. 每圈都打印 `B`，共很多次
   - D. 一次都不打印
   - 答案: B
   - 判定: B。逐步走：第 2 段 `1 < 2` 成立 → 进循环体 → 此时 `1 > 2` 为 false → 打印 B → 本圈末尾 `a` 变成 2 → 回判 `2 < 2` 不成立 → 结束。总共只打印一次 B。A 错在循环条件已经先把 a>b 的取值全挡在门外了。C 错，a 只涨一次就退出。D 错，第一圈确实进去了。
   - 踩坑场景: IDEA 警告「条件 'a>b' 始终为 'false'」，误以为是符号写错，急着换个比较表达式——病根其实是循环条件早把不符合的取值筛掉了，体内那个 if 永远等不到 true。

   **术语**

   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | 筛选作用 | 循环条件先把不让进的取值挡在体外 | 门口保安先筛一遍 |
   | 恒 false | 判断结果永远为 false 的表达式 | 每次问都说不 |
   | 判断时机 | 条件在同一轮里被计算的那一刻 | 什么时候问这句话 |
