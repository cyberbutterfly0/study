## 概念卡

### for 循环的三段式

- 是什么: `for` 的圆括号里固定三段——初始化、继续条件、更新——作用分别是"进循环前做一次""每圈开始前判断""每圈结束时做"。
- 为什么: 三段都塞进一行是为了让"跑几圈"这件事一眼可见：起点（第1段）、终点（第2段）、步长（第3段）全在同一个括号里，读代码时不用去别处找。
- 关键机制: **三段之间用英文 `;` 分隔，不是逗号**；三段的内容都可以留空，但两个 `;` 必须都在，所以 `for( ; a<b ; a+=1)` 合法。判断顺序固定是 第1段 → 判第2段 → 循环体 → 第3段 → 再判第2段……（**第2段的判断在循环体之前，第3段在本圈末尾**，这个顺序是后面所有循环题的根）。
- 最小示例:
  ```java
  for (int i = 0; i < 3; i++) { ... }   // 第1段声明并初始化；第2段条件；第3段自增
  for ( ; a < b ; a += 1) { ... }        // 第1段留空（变量在外面已声明）；两个分号仍在
  ```
- 我的理解偏差: 一开始以为括号里各段是用逗号隔开的（写成 `for(a<b,a+=1)`），于是把"条件"和"更新"当成了逗号列表的两个元素，漏掉初始化段；也没意识到条件写在哪个位置决定它"每圈判一次"。

### if / else 的执行条件（待验证）

- 是什么: 按条件真假二选一执行。`if` 条件是每**执行到这一行时**现算一次，不是写死一次。
- 为什么: 循环里 `if` 的条件会随循环变量变化，所以同一个 `if` 在不同圈可能走不同分支。
- 关键机制: 条件为 `false` 时 `if` 体整个跳过、走 `else`；条件恒为 `false` 说明"能改变这个条件的变量在判断点之前没有变化"。
- 我的理解偏差（用户本轮的实际提法）: 问"我应该怎么替换这个 `a>b` 让逻辑成立"，预设了"换掉条件表达式就能让分支成立"。**实际是判断时机与变量取值的问题**——只要执行到那一行时 a 恒小于 b，换任何比较写法结果都一样。此偏差先记下，等用户自己撞到矛盾再确认。
- 待验证: 等循环改对之后，看同一个 `if` 在不同圈是否走到不同分支。

### 循环条件对循环体内的"筛选"作用

- 是什么: 循环体里能看到的变量，已经被第 2 段（继续条件）**筛过一遍**——凡是不让条件成立的那些取值，根本进不到循环体。
- 为什么: 第 2 段的判断发生在循环体**之前**，不成立就直接跳出，循环体一行都不执行。所以"循环体里 a 恒小于 b"不是巧合，是循环条件亲手写的。
- 关键机制: 这段代码的矛盾是**循环条件与体内判断方向相反**——第 2 段要求 `a < b` 才放行，体内第一个 `if` 却问 `a > b`。能进来的一定满足 a<b，所以那个 `if` 永远算不出 true。**换任何"a 大于 b"型的判断表达式都没用**：病根不在表达式，在"什么时候问"和"循环允许 a 走到哪"。
- 最小示例（手走一遍，a=1、b=2）:
  1. 判第 2 段：`1 < 2` 成立 → 进循环体
  2. 体内 `if` 取**当下**的值：`1 > 2` → false → 走 `else`，打印 `b>a`
  3. 本圈末尾执行第 3 段：a 变成 2
  4. 回到第 2 段：`2 < 2` 不成立 → 循环结束
  - 净结果：只打印 1 行 `b>a`；a 在整个循环体里始终是 1。
- 我的理解偏差: 以为"逻辑不成立"是表达式写错了，想给 `a>b` 换个替身。实际要动的是三选一——循环条件（允许 a 涨到超过 b）、判断发生的位置（在 a 增长之后再问）、或比较的对象。
- 待验证: 原计划的观察实验（循环体第一行打印 a、b 的当前值）**用户没做**——他直接把 `if / else` 删掉、改成 `for( ; a<=5; a+=1)` 打印 a（输出 1–5），等于绕开了这段矛盾。所以本卡的结论（"换表达式没用"）目前**还只是推演，没有被用户实际观测到**。

## 易错点

- **IDEA 报错原文**：第 5 行 `应为 ';'`（英文提示 `';' expected`），同一行报两次。**触发条件**：`for` 括号里用逗号分隔三段。**正确做法**：三段间用 `;`；若某段不需要就留空，但分号不能省。
- **IDEA 警告原文**：第 6 行 `条件 'a>b' 始终为 'false'`。**触发条件**：`a`、`b` 在进入该 `if` 前已有确定大小关系（a=1 < b=2），且判断前没有能翻转这个关系的操作。**正确做法**：先想清循环要让变量怎么变、`if` 想判断什么状态，再决定条件写在哪一步之后——**别把警告当成"改成 true 就行"**。
- **绕开而不是解决**（2026-10-15）：遇到"条件恒 false"的题，把出问题的 `if / else` 整段删掉、换成一个只打印循环变量的简单循环。程序跑通了（输出 1–5），但原题要练的分支判断一点没做。**判别标志**：程序能跑 ≠ 题目练到了。**做法**：把"让程序跑起来"和"把卡住的那一步弄明白"分开；后者靠观察实验（打印变量、看实际走哪一支）而不是删掉它。
- **概念混淆**：把 for 的三段理解成"逗号分隔的参数列表"（像方法调用那样）。区别：方法参数是并列的输入，for 三段是**有时间顺序的三个阶段**（前 / 每圈前 / 每圈后），顺序本身就是语义。
