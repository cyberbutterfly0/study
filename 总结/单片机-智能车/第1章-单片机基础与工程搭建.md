## 小节

### 1.1 为什么先配时钟

- 状态: 进行中（已考：4 题答对 3 题，第 2 题错了，已进错题本；桌面练习待做）

**讲解**

一、时钟是数字电路的节拍

- 单片机上所有数字电路都靠时钟节拍往前走：CPU 取指、总线传输、外设计数，都是"每个节拍动一下"。没有时钟，触发器不知道该在什么时候锁存数据。
- 时钟是一路方波。频率 = 每秒多少个节拍，周期 = 一个节拍多长。72 MHz 就是每个节拍 13.9 ns。
- 为什么不能用一个固定频率：不同外设需要不同速度（CPU 要快，I2C 只要几百 kHz），而且降频能降功耗。所以要有"可配的时钟"，这就是时钟树。

二、STM32F103 的时钟源

- **HSI**：内部 8 MHz RC 振荡器。上电复位后默认就用它。免费、不用外部元件，但受温度和电压影响，精度差（百分之几量级），做串口、定时会漂。
- **HSE**：外部晶振，一般 8 MHz。准（几十 ppm），要焊晶振和两个负载电容，起振需要时间（毫秒级）。
- **LSI**：内部 40 kHz 低速，独立看门狗用。
- **LSE**：外部 32.768 kHz，RTC 用。
- **PLL**：锁相环，把输入的 8 MHz 倍频到 72 MHz。它不是一个独立时钟源，是"频率放大器"。

三、时钟树（F103 的 72 MHz 标准配置，要能背出这条路径）

```
HSE 8MHz ──> PLL ×9 ──> SYSCLK 72MHz ──> AHB /1 ──> HCLK 72MHz
                                                    ├─> APB1 /2 ──> PCLK1 36MHz（上限 36MHz）
                                                    └─> APB2 /1 ──> PCLK2 72MHz（上限 72MHz）
```

- SYSCLK 是 CPU 和总线的根时钟；HCLK 是 AHB 总线时钟（CPU、内存、DMA 用）。
- APB1 和 APB2 是两条外设总线。APB1 挂的是"低速"外设：USART2/3、TIM2/3/4、I2C、SPI2、ADC 的部分控制逻辑。APB2 挂"高速"外设：GPIOA~E、USART1、SPI1、TIM1、ADC1/2 的时钟入口。
- APB1 最大只能 36 MHz，这是芯片设计的硬限制，超了外设行为不保证。所以 72 MHz 主频时 APB1 必须 /2。
- **关键陷阱（必考）**：定时器时钟不等于总线时钟。规则是——APB 预分频系数为 1 时，定时器时钟 = PCLK；预分频系数不为 1 时，定时器时钟 = PCLK × 2。所以 PCLK1 = 36 MHz、/2 分频时，TIM2/3/4 实际拿到 72 MHz 计数时钟。算定时器周期时用错这个，时间会差一倍。

四、时钟配置和外设时钟使能是两件不同的事

- 时钟树（CubeMX 的 Clock Configuration 页）决定"全系统跑多快"。
- 每个外设还有自己独立的**时钟使能位**，在 RCC 的 AHBENR / APB1ENR / APB2ENR 寄存器里。这是"门控"设计：不用的外设把门关掉，省动态功耗（CMOS 电路只在翻转时耗电）。
- 不开这个门，外设就是不工作的：寄存器写进去读回来还是 0，外设不动，不报错不提示。这是新手第一大坑，比接线错还难查，因为"什么都没发生"。
- HAL 里对应的就是 `__HAL_RCC_GPIOA_CLK_ENABLE()` 这一类宏；CubeMX 生成的 `MX_GPIO_Init()` 开头一定有它。
- 外设的实际工作频率都从 PCLK 推出来：串口波特率、定时器计数频率、ADC 采样时间。时钟配错，现象是"能跑但数字全不对"（波特率乱码、定时器周期差一截、ADC 采样率偏）。
- 上电复位后的默认状态：SYSCLK 来自 HSI 8 MHz。所以 HSE 没起振时，CubeMX 生成的 `SystemClock_Config()` 会走 `Error_Handler()` 死循环（LED 不闪），而不是偷偷降级跑 HSI——看见程序彻底不动，先量晶振有没有起振。

本节出现的术语都收在 [术语表](./术语表.md) 里（三列：术语 / 含义 / 通俗解释，`Ctrl+F` 能搜）。

**出处**：时钟树结构、外设时钟使能位、APB 预分频与"定时器时钟 ×2"规则出自 RM0008《STM32F10x 参考手册》的 Reset and clock control (RCC) 章；HSI/HSE 精度出自 F103 数据手册的 Clock characteristics 节。没对过具体节号，以手册原文为准。

**两侧落地**（两侧配置方式不同，机制相同）

- STM32（CubeMX + HAL）：在 Clock Configuration 页把 HSE 选作 PLL 源、PLL ×9、AHB /1、APB1 /2、APB2 /1。生成的 `SystemClock_Config()` 里，`HAL_RCC_OscConfig()` 开 HSE、配 PLL，`HAL_RCC_ClockConfig()` 切 SYSCLK 源并设各分频；实际 HCLK 值存进 `SystemCoreClock`，串口波特率等都用它算。外设时钟使能必须手写，如 `__HAL_RCC_GPIOA_CLK_ENABLE()`。
- MSPM0（SysConfig + DriverLib）：在 SysConfig 的 Clock 模块里选时钟源和分频，结果生成到 `SYSCFG_DL_init()`，外设时钟也由它统一打开，用户不手写。M0+ 的 MCLK 通常几十 MHz，具体看型号和配置。函数级细节待查到 SDK 的 sysctl 头文件后再补。
- 两边差异记在 [平台对照](./平台对照.md) 的「时钟」一节。

五、常见误解

- "CubeMX 生成完就能用"——生成的 `SystemClock_Config()` 只管频率，每个外设的时钟使能是各自初始化函数里开的；自己手写初始化时必须记得开。
- "主频越高越好"——功耗、发热、外设分频约束都要照顾；而且 for 循环凑出来的软件延时随主频变短，时间就不准了。
- "定时器时钟就是 PCLK"——错，见上面 ×2 规则。
- "外设不动是接线问题"——先查时钟使能，再查引脚和模式。

**选择题**

1. STM32F103 上电复位后，CPU 默认跑在哪个时钟上？
   - A. HSE 8 MHz
   - B. HSI 8 MHz
   - C. PLL 输出的 72 MHz
   - D. LSI 40 kHz
   - 答案: B
   - 判定: 复位后 RCC 默认选择 HSI 作为 SYSCLK，HSE 和 PLL 都没开。要跑到 72 MHz 必须由软件（CubeMX 生成的 `SystemClock_Config()`）依次使能 HSE、配置 PLL、切换 SYSCLK 源、再改 AHB/APB 分频。A 错在 HSE 复位后是关闭状态；C 错在 PLL 复位后关闭；D 是看门狗用的低速时钟，从不给 CPU 供时钟。
   - 踩坑场景: 以为上电就是 72 MHz，忘了自己没调 `SystemClock_Config()`，结果波特率、定时全按 72 MHz 算，实际 8 MHz，全错。

   **术语**

   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | HSE | High-Speed External，外部高速时钟源，接在 OSC_IN/OSC_OUT 的晶振 | 板子上焊的那颗晶振，一般 8 MHz |
   | HSI | High-Speed Internal，芯片内部 RC 振荡器，校准到 8 MHz | 芯片自带的小闹钟，不用外接元件 |
   | PLL | 锁相环倍频器 | 倍速器，8 MHz 进去、72 MHz 出来 |
   | SYSCLK | 系统主时钟 | CPU 真正在用的那个节拍 |
   | LSI | 内部低速时钟，约 40 kHz，主要给看门狗 | 慢速备用表，管"看门狗"这种慢活 |

2. 外部 8 MHz 晶振经 PLL ×9 到 72 MHz，AHB /1，APB1 /2，APB2 /1。挂在 APB1 上的 TIM3，计数时钟是多少 MHz？
   - A. 36 MHz
   - B. 72 MHz
   - C. 18 MHz
   - D. 8 MHz
   - 答案: B
   - 判定: PCLK1 = 36 MHz，但 APB1 预分频系数是 2（不为 1），按规则定时器时钟 = PCLK1 × 2 = 72 MHz。A 是把总线时钟直接当成定时器时钟，最典型的错。C 是又乘又除的胡乱推导。D 是错把 HSE 当计数源。
   - 踩坑场景: 按 36 MHz 算 PSC/ARR，实际定时器跑 72 MHz，周期整整差一倍，PID 采样周期跟着错。

   **术语**

   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | AHB / APB | 片上两条总线：AHB 接高速部件，APB 接外设 | 芯片里的一级公路和二级公路 |
   | PCLK1 | APB1 总线时钟 = HCLK / APB1 分频 | 外设总线的节拍，APB1 最高 36 MHz |
   | 预分频（Prescaler） | 把输入时钟按整数比例降频 | 把快节拍切成慢节拍 |
   | 计数时钟 | 定时器计数器每加一用的频率 | 秒表走一格的快慢 |
   | TIM3 | STM32 的通用定时器之一，挂在 APB1 上 | 三号秒表，走 APB1 这条线 |

3. 代码用 HAL 发串口字符串，程序确实在跑（LED 正常闪），但串口助手收到的全是乱码。最可能的原因？
   - A. RX/TX 两根线接反了
   - B. 算波特率时用的时钟频率和实际系统时钟不一致
   - C. 没开串口接收中断
   - D. 发送函数里数据长度传错了
   - 答案: B
   - 判定: 乱码但收到了数据，说明链路通、外设在工作，只是每一位的时间宽度对不上——这是波特率不匹配的典型特征。而波特率是拿 PCLK 算出来的，PCLK 错了波特率就错。A 会导致完全收不到数据（或只收到自己发的回环），不是乱码。C 只影响接收，不影响发送。D 一般表现为数据截断或混杂，不会整串都是乱码。
   - 踩坑场景: 改了 PLL 倍频或 APB 分频，忘了 CubeMX 里串口参数要重新生成/重算，串口助手还在用旧的波特率。

   **术语**

   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | 波特率 | 每秒传输的位数（bit/s），收发双方必须一致 | 说话的语速，两边不一样快就听成乱码 |
   | RX / TX | 接收引脚 / 发送引脚 | 一根耳朵一根嘴，要交叉接 |
   | 串口接收中断 | 收到数据时触发的接收中断，只影响接收路径 | 只负责"听"的那条路 |
   | PCLK | 串口所在总线的时钟，用来算波特率 | 算语速时用的节拍源 |

4. 为什么每个外设要有独立的时钟使能位，而不是像主频那样一个总开关？
   - A. 门控省功耗：没使能的外设时钟不翻转，几乎不耗动态功耗
   - B. 纯粹是历史设计遗留，没有实际好处
   - C. 防止外设之间互相干扰数据
   - D. 只有逐个使能才能把主频提上去
   - 答案: A
   - 判定: CMOS 电路的动态功耗和时钟频率成正比，一个不用的外设如果时钟一直喂着，它会一直翻转、一直耗电。门控（clock gating）是低功耗设计的基本手段，电池供电和小车这种靠电机电池供电的场景尤其重要。B 错在否认了真实收益；C 错在干扰靠的是地址空间和中断优先级，不是时钟门；D 跟主频没有任何关系。
   - 踩坑场景: 为省事把 RCC 所有外设时钟全开，待机电流下不来，查了半天以为是漏电。

   **术语**

   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | 时钟使能位 | RCC 寄存器里控制某个外设时钟开关的位 | 每个外设的独立电闸 |
   | 门控（Clock Gating） | 用使能位切断外设时钟，省电 | 不用就把电闸拉下 |
   | 动态功耗 | 电路翻转时消耗的功率，与时钟频率成正比 | 动起来才费电，动得越快越费 |
   | RCC | Reset and Clock Control，管复位与时钟的外设 | 总电闸加时钟分配器 |

5. F103 跑 72 MHz 主频时，APB1 必须做 /2 分频，根本原因是什么？
   - A. 为了让挂在 APB1 上的定时器拿到 72 MHz 计数时钟
   - B. APB1 总线本身最高只能跑 36 MHz，超了外设行为不保证
   - C. 降低功耗，频率越高越费电
   - D. 让 USART 的波特率算得更准
   - 答案: B
   - 判定: B 是芯片设计的硬限制，RM0008 里 APB1 的时钟上限就写死 36 MHz，所以 72 MHz 主频时只能 /2。A 是"后果"不是"原因"——×2 规则恰好让定时器在 /2 时补回 72 MHz，但分频的动机是总线上限，不是照顾定时器。C 功耗确实随频率升高，可 /2 并没有降低 SYSCLK，CPU 还是 72 MHz，省不了多少。D 波特率只要实际时钟确定就能算准，与分不分频无关；反而是分频算错才出乱码。
   - 踩坑场景: 为了让外设"全速跑"，给 APB1 填 /1，结果挂 APB1 的串口、定时器行为全乱，还以为是代码问题。

   **术语**

   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | APB1 / APB2 | F103 的两条外设总线，APB1 慢、APB2 快 | 两条不同限速的支路 |
   | 总线上限 | 该总线允许的最高工作频率 | 这条路限速多少 |
   | 硬限制 | 芯片设计决定、软件不能突破的边界 | 出厂就定死的规矩 |

6. 程序烧进板子后 LED 完全不闪、串口一个字都没有，看着像根本没跑起来。按本章的排障顺序，先查哪一项？
   - A. 先量 HSE 晶振有没有起振
   - B. 先把串口波特率从 115200 改成 9600
   - C. 先换一根 USB 线
   - D. 先把延时加大，可能是闪太快没看出来
   - 答案: A
   - 判定: A。`SystemClock_Config()` 里开 HSE 失败会直接跳进 `Error_Handler()` 死循环——LED 不闪正是它的典型表现，而且它不会偷偷降级去跑 HSI。B 波特率错只会收到乱码，LED 照样闪。C USB 线坏一般是连不上电脑、程序压根下载不进去，而不是"下载成功但不跑"。D 延时加大只会让闪烁变慢，LED 至少还会亮着，不会完全无反应。
   - 踩坑场景: 板子焊的是 12 MHz 晶振，工程里按 8 MHz 配的，HSE 起振失败卡死在 Error_Handler，查了一下午代码。

   **术语**

   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | Error_Handler | CubeMX 生成的错误陷阱函数，里面是死循环 | 出事就原地站住不动 |
   | 起振 | 晶振加上电后开始稳定振荡的过程 | 钟摆要推一下才越摆越稳 |
   | HSE 起振失败 | 外部晶振没正常振荡，时钟源拿不到 | 外面的钟没响 |

7. 自己手写 GPIO 初始化，写了 `GPIOA->CRL = ...` 配引脚，但漏了 `__HAL_RCC_GPIOA_CLK_ENABLE()`。运行时会看到什么？
   - A. 编译直接报错，说宏没定义
   - B. 运行时触发 HardFault，提示时钟未使能
   - C. 不报任何错，寄存器写进去读回来还是 0，引脚毫无反应
   - D. 引脚被锁在高电平，不受代码控制
   - 答案: C
   - 判定: C，这是本章第一大坑。时钟没开时该外设的寄存器根本不应答，写进去读回来是 0，外设不工作也不报错——"什么都没发生"正是它难查的原因。A 错，宏是编译期的，漏写只是少执行一条语句，不影响编译。B 错，访问未使能外设不会 HardFault，只会静默失败。D 错，引脚此时是复位后的默认态（多数是浮空输入），不是被锁死。
   - 踩坑场景: 接线查了三遍、电源量了两遍、换了一块板子，最后发现是少一行使能宏。

   **术语**

   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | 静默失败 | 写操作没生效，但既不报错也不异常 | 按了没反应，也不告诉你为什么 |
   | 复位默认态 | 芯片刚复位时引脚的初始状态 | 还没人管它时的样子 |
   | CRL | GPIO 端口配置低寄存器，配 0~7 号引脚 | 管前 8 根脚的模式开关 |

8. 时钟配置这一步，STM32（CubeMX + HAL）和 MSPM0（SysConfig + DriverLib）最本质的差别在哪？
   - A. STM32 还要在用户代码里为每个外设单独调时钟使能宏；MSPM0 由 SysConfig 生成的 `SYSCFG_DL_init()` 统一打开
   - B. 两边完全一样，都得在用户代码里手写使能
   - C. MSPM0 没有外设时钟使能这一层，不需要门控
   - D. STM32 的时钟树出厂固定，用户不能改
   - 答案: A
   - 判定: A。两边机制相同（都是时钟门控），落地方式不同：HAL 把使能宏暴露给用户，DriverLib 把它藏进工具生成的初始化。B 错，MSPM0 不用手写。C 错，M0+ 同样有门控，只是被工具包了一层。D 错，时钟树完全可配，CubeMX 的 Clock Configuration 页就是干这个的。
   - 踩坑场景: 从 STM32 转 MSPM0，满工程找 `__HAL_RCC_xxx_CLK_ENABLE()` 找不到，以为工具漏生成；反过来在 STM32 上以为 SysConfig 会自动开，结果外设不动。

   **术语**

   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | SysConfig | TI 的图形化配置工具，生成 MSPM0 初始化代码 | M0 版的可视化配置页 |
   | DriverLib | TI 的外设驱动库，类似 ST 的 HAL | M0 的一套底层函数 |
   | SYSCFG_DL_init | SysConfig 生成的系统初始化函数 | 芯片上电的"总装配"代码 |

9. 一段用 `for (int i = 0; i < 100000; i++);` 做的软件延时，把主频从 8 MHz 提到 72 MHz 后，实际延时大约怎么变？
   - A. 变长约 9 倍
   - B. 变短到大约原来的 1/9
   - C. 基本不变，循环次数又没改
   - D. 直接编译不过
   - 答案: B
   - 判定: B。软件延时是靠"跑多少条指令"堆出来的，每条指令耗时随主频升高而缩短，圈数不变时间就成比例变短。A 方向反了。C 错在把"循环次数"当成了"时间"——次数固定不代表耗时固定。D 错，这是完全合法的写法（编译器可能优化掉空循环，那是另一回事）。

### 1.2 GPIO 的八种模式

- 状态: 未开始

**讲解**

一、一个引脚背后有什么

引脚不是"一根能出高低电平的针"，是一个节点，背后连着两条路：

- **输出路径**：`ODR` 寄存器的某一位 → 输出控制 → 一对 MOS 管（上管接 VDD、下管接 GND）→ 引脚
- **输入路径**：引脚 → 施密特触发器（把缓慢变化的电压整形成干净的数字电平）→ `IDR` 寄存器

两条路之间还挂着上拉电阻、下拉电阻，以及一条把引脚交给外设的旁路（复用功能）。

"配 GPIO 模式"配的就是这些开关的组合：哪条路通、上下拉接不接、MOS 管怎么接。

二、推挽和开漏

- **推挽**：上管下管都在。写 1 时上管通、下管断，引脚被顶到 VDD；写 0 时反过来，被拉到 GND。高、低都能主动驱动，是 LED、继电器这类负载的默认选择。
- **开漏**：只有下管。写 0 拉到 GND；写 1 时下管断开，引脚悬空（高阻），必须靠**外部上拉电阻**才能回到高电平。

开漏唯一的存在理由是「线与」：多条开漏线接在一起，任何一条拉低，整条线就低。I2C 的 SDA/SCL 必须开漏，因为总线上挂着多个设备，从机要靠拉低时钟来流控（clock stretching）——如果大家都能主动输出高电平，两个设备一个想拉高一个想拉低，就是短路。

三、上下拉

引脚悬空时电压不确定，读出来是随机值。上拉/下拉电阻给它一个默认电平。

按键就是典型：一端接引脚、一端接 GND，引脚开**内部上拉** → 没按时读 1，按下读 0。

内部上拉大约 30–50 kΩ，按键够用。I2C 的外部上拉通常 4.7 kΩ，因为总线电容大，阻值大上升沿就爬得慢，高速率下会采样错。

四、八种模式速查

| 模式 | 用在哪 |
|---|---|
| 输入浮空 | 外部已有上下拉；或做模拟比较（现在少用） |
| 输入上拉 | 按键接地，悬空即高 |
| 输入下拉 | 按键接 VDD，悬空即低 |
| 模拟输入 | ADC 采样；也用于低功耗（关掉数字路径省电） |
| 输出推挽 | LED、继电器、要驱动能力的地方 |
| 输出开漏 | 线与、电平转换（3.3 V 驱动 5 V 器件） |
| 复用推挽 | 外设输出：PWM、UART TX、SPI |
| 复用开漏 | I2C 的 SDA/SCL |

记忆锚点：前四个是输入，后四个是输出；输出里带「复用」的是外设在用，不带的是软件写 `ODR` 控制。

五、两侧落地

**STM32F103**：每个引脚在 `GPIOx_CRL`（引脚 0–7）或 `GPIOx_CRH`（8–15）里占 4 bit，高 2 bit 是 `CNFy`（配置），低 2 bit 是 `MODEy`（速度/方向）。这 4 bit 的 16 种编码里有效的是那八种模式。

```c
GPIO_InitTypeDef g = {0};
g.Pin   = GPIO_PIN_13;
g.Mode  = GPIO_MODE_OUTPUT_PP;    // 推挽输出
g.Pull  = GPIO_NOPULL;
g.Speed = GPIO_SPEED_FREQ_LOW;
HAL_GPIO_Init(GPIOC, &g);         // 调用前要先使能 GPIOC 时钟
```

**MSPM0**：先 `IOMUX`（PINCM）选这个脚干什么，再 `GPIO` 设方向和上下拉，是两步。

```c
DL_GPIO_initDigitalOutput(GPIO_LEDS_USER_LED_1_IOMUX);
DL_GPIO_setPins(GPIO_LEDS_PORT, GPIO_LEDS_USER_LED_1_PIN);
DL_GPIO_enableOutput(GPIO_LEDS_PORT, GPIO_LEDS_USER_LED_1_PIN);
```

差异：STM32 一个 4 bit 字段把模式一次编完；MSPM0 拆成 IOMUX 选功能 + GPIO 设方向两步。查引脚分配时，STM32 看数据手册的「Pinouts and pin description」表，MSPM0 看 SysConfig 里的 PINCM 编号。

六、三个常见误解

- 「输出模式下不能读引脚」——错，`IDR` 一直在采样引脚实际电压，推挽输出时也能读回（可用来检测负载短路）。
- 「开漏写 1 就是高电平」——错，那是高阻，没外部上拉就是悬空。
- 「没配过的引脚也能用」——错，任何脚用之前都要使能端口时钟、配好模式。上电默认是浮空输入。

**选择题**

1. 一个 LED 接在 PA5，阳极接 VDD、阴极接 PA5（低电平点亮）。该引脚应配成什么模式？
   - A. 输入上拉
   - B. 推挽输出
   - C. 开漏输出
   - D. 模拟输入
   - 答案: B
   - 判定: LED 要的是"能主动输出低电平把电流灌进来"。推挽输出下管能主动拉低，正确。A 是输入，驱动不了。C 开漏确实能拉低，但没外部上拉时输出高电平就是悬空，灯会微亮或乱闪，不如推挽干脆。D 模拟输入根本不是输出。
   - 踩坑场景: 把 LED 配成开漏输出，烧录后发现灯一直微亮——因为引脚悬空时漏电流经 LED 走通了。

2. I2C 的 SDA 线为什么必须配成开漏，不能配推挽？
   - A. 开漏速度快
   - B. 开漏可以多个设备接在同一条线上，任何一个拉低整条线就低
   - C. 推挽不能输出低电平
   - D. 编译器要求
   - 答案: B
   - 判定: I2C 是多设备共享总线，主机要流控时也得拉低时钟。如果两个设备都用推挽，一个输出高一个输出低，就是上管对下管的直通短路。开漏只做"拉低"这一个动作，天然安全。A 错，开漏反而上升沿更慢（靠上拉电阻充总线电容）。C 错，推挽高低都能输出。
   - 踩坑场景: 自己接的 I2C 传感器读不到数据，示波器一看 SDA 一直是高电平——模式配成了推挽，从机想拉低被主机的上管顶回来了。

3. 按键一端接 PA0、一端接 GND，要求不按时读 1、按下读 0。模式怎么配？
   - A. 输入浮空
   - B. 输入上拉
   - C. 输入下拉
   - D. 输出推挽
   - 答案: B
   - 判定: 松手时引脚悬空，必须给一个默认高电平，所以上拉。按下时按键把引脚直接短到 GND，上拉电阻被压住，读到 0。A 浮空的话松手读数是随机噪声（手持板子时尤其明显）。C 下拉会让松手时读出 0，逻辑反了。
   - 踩坑场景: 不配上下拉，串口日志里按键状态疯狂跳变——浮空脚在采人体感应的电荷。

4. 引脚配成开漏输出，写 1，外部没有上拉电阻，用万用表测这脚电压大约是？
   - A. 3.3 V
   - B. 0 V
   - C. 不确定/接近 0，呈高阻
   - D. 5 V
   - 答案: C
   - 判定: 开漏写 1 只是"不拉低"，引脚进入高阻，不提供任何电压。实际读数由外部电路和万用表自身阻抗决定，一般飘在很低的值上。A 是最常见的想当然。B 是写 0 的结果。D 与电源电压无关。
   - 踩坑场景: 想用开漏脚驱动一个 MOS 管当高边开关，结果 MOS 管不导通——忘了加上拉电阻。

   **术语**
   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | 推挽 | 上下两个 MOS 管配合，能主动输出高也能主动输出低 | 既能往上推也能往下拉 |
   | 开漏 | 只有下拉管，写 1 是释放为高阻，靠外部上拉回高 | 只会踩刹车，想走要靠别人拉 |

   | 复用功能 | 把引脚从 GPIO 交给某个外设（定时器、串口）使用 | 这根针借出去干活 |

### 1.3 外部中断

- 状态: 未开始

**讲解**

一、轮询为什么不够

主循环里 `if (HAL_GPIO_ReadPin(...) == 0)` 一遍遍看按键，两个致命问题：

- 按键按下的一瞬间只有几毫秒，主循环若正忙着跑别的（比如等 100 ms 的延时），就漏掉了；
- CPU 一直在白白读寄存器，功耗和响应速度都浪费。

中断反过来：平时 CPU 干自己的事，硬件检测到电平跳变就把 CPU 拽过来执行一小段代码，完事再回去。**关键在"硬件检测"**——不靠软件轮询。

二、一次中断走完的完整路径

信号从引脚到你的回调函数，要过四道门：

1. **边沿检测**：EXTI 里有个触发器，盯着引脚电平，检测到指定的跳变（上升沿/下降沿/双边沿）就置位对应的**挂起位**（PR）。
2. **屏蔽检查**：挂起位还要和**中断屏蔽寄存器**（IMR）按位与。屏蔽位为 0 的那条线，挂起位照样置位（可以轮询 PR 看），但不会往后传。这让"同一条线既能查询又能中断"成为可能。
3. **NVIC 排队**：EXTI 把请求送到 NVIC，NVIC 按优先级决定立刻处理还是等当前中断执行完。高优先级可以打断低优先级（嵌套）。
4. **CPU 取向量**：CPU 保存现场（压栈 8 个寄存器），跳到向量表里对应的 ISR 地址。

回来后自动恢复现场。整个过程硬件完成，软件只需写 ISR。

三、EXTI 线的编号规则（最容易踩的坑）

STM32F103 的 EXTI 线只有 16 条（EXTI0–EXTI15），**按引脚编号分配，不按端口**：

- PA3、PB3、PC3 全都挂在 EXTI3 上，但同一时刻只能选一个。
- 选谁由 `AFIO_EXTICR` 寄存器决定（HAL 里是 `__HAL_AFIO_REMAP` 或 `HAL_GPIO_Init` 内部处理）。

所以"PA0 和 PB0 都要中断"是做不到的，得换成不同编号的引脚。

四、优先级：抢占和子优先级

Cortex-M3 的 8 bit 优先级字段，STM32 默认切成 4 bit 抢占 + 0 bit 子优先级（`NVIC_PRIORITYGROUP_4`）。数字越小优先级越高。

- **抢占优先级**不同：高的能打断正在执行的低的中断（嵌套）。
- **子优先级**不同、抢占相同：不能互相打断，同时挂起时子优先级高的先执行。

实战建议：跟时间强相关的放高抢占（比如编码器计数、串口收字节），人机交互的（按键、屏幕）放低。

五、ISR 三条铁律

1. **短**：里面不要有 `HAL_Delay`、不要 `printf`、不要跑浮点运算。这些会让别的中断和主循环全部停摆。
2. **标志要 `volatile`**：主循环里 `while (!flag);` 等中断置位，若 `flag` 没加 `volatile`，编译器会把它优化进寄存器，永远等不到。
3. **清标志**：ISR 结束前必须清掉外设的挂起位（EXTI 的 PR、定时器的 SR、串口的 SR），否则退出后立刻又进一次，形成"中断风暴"把 CPU 占满。

六、两侧落地

**STM32F103**：HAL 把 ISR 拆成"公共处理函数 + 回调"，你只写回调。

```c
// 配置（MX_GPIO_Init 里）
GPIO_InitTypeDef g = {0};
g.Pin  = GPIO_PIN_0;
g.Mode = GPIO_MODE_IT_FALLING;   // 下降沿触发
g.Pull = GPIO_PULLUP;            // 按键接地，上拉
HAL_GPIO_Init(GPIOA, &g);
HAL_NVIC_SetPriority(EXTI0_IRQn, 2, 0);
HAL_NVIC_EnableIRQ(EXTI0_IRQn);

// 回调：中断服务函数由 HAL 提供，你只实现这个
void HAL_GPIO_EXTI_Callback(uint16_t pin) {
  if (pin == GPIO_PIN_0) {
    flag_key = 1;        // 只置标志，干活留给主循环
  }
}
```

**MSPM0**：先配极性、清挂起、开中断，再在 IRQHandler 里按 IIDX 分发。

```c
DL_GPIO_setUpperPinsPolarity(GPIO_KEY_PORT, DL_GPIO_PIN_18_EDGE_FALL);
DL_GPIO_clearInterruptStatus(GPIO_KEY_PORT, GPIO_KEY_USER_BTN_PIN);
DL_GPIO_enableInterrupt(GPIO_KEY_PORT, GPIO_KEY_USER_BTN_PIN);
NVIC_EnableIRQ(GPIO_KEY_INT_IRQn);

void GROUP1_IRQHandler(void) {   // 注意是分组中断，多个外设共用一个入口
  switch (DL_Interrupt_getPendingGroup(DL_INTERRUPT_GROUP_1)) {
    case GPIO_KEY_INT_IIDX:
      if (DL_GPIO_getEnabledInterruptStatus(GPIO_KEY_PORT, GPIO_KEY_USER_BTN_PIN)) {
        DL_GPIO_clearInterruptStatus(GPIO_KEY_PORT, GPIO_KEY_USER_BTN_PIN);
        flag_key = 1;
      }
      break;
  }
}
```

差异：STM32 每个 EXTI 线编号基本对应一个 IRQ 入口（EXTI0、EXTI1、EXTI9_5、EXTI15_10 是共享的），HAL 已经用 `HAL_GPIO_EXTI_IRQHandler` 帮你清了标志；MSPM0 是"分组中断"，GPIO 全归 GROUP1，一个入口里要自己按 IIDX 分发、自己清标志。

七、三个常见误解

- 「中断优先级越高越好」——错，全设最高等于没有优先级，还会把低延迟的活儿饿死。
- 「中断里可以直接操作 LCD / 发串口」——要看情况，但绝大多数情况应该只置标志，主循环去做。
- 「不用清标志，退出时硬件会清」——错，除了少数外设，大部分中断标志必须软件明确清除。

**选择题**

1. 已经用 PA0 做外部中断，现在还想让 PB0 也触发外部中断，最可能的结果是？
   - A. 两个都能正常触发
   - B. 只能有一个生效，因为两者共用 EXTI0 线
   - C. 会触发硬件错误
   - D. 两个都失效
   - 答案: B
   - 判定: EXTI 线按引脚编号绑，PA0 和 PB0 都是 0 号，AFIO 只能选一个端口接上去。接上的那个正常，另一个请求根本进不来（不是报错，是静默不响应）。A 错，这正是这个设计最坑的地方——不报错，只是不响应。C 错，没有这种机制。D 也不对，选中的那个是好的。
   - 踩坑场景: 板子上 PA0 接编码器 A 相，后来又想加 PB0 接限位开关，结果限位开关完全没反应，查了半天接线。

2. 在中断服务函数里调用 `HAL_Delay(10)` 会发生什么？
   - A. 正常延时 10 ms
   - B. 可能永久卡死，因为 SysTick 中断优先级不比当前中断高
   - C. 延时变成 0
   - D. 编译报错
   - 答案: B
   - 判定: `HAL_Delay` 本质是 `while (uwTick - start < ms);`，靠 SysTick 中断累加 `uwTick`。SysTick 优先级通常是 15（最低），它打断不了正在执行的外部中断，`uwTick` 停止累加，死等。这是嵌入式里最经典的死锁之一。A 错。C 错。D 错，编译完全合法，运行时才炸。
   - 踩坑场景: 串口中断里加了 10 ms 延时做"消抖"，程序跑几分钟就整机卡死，复位才行——而且卡死的位置每次都不一样。

3. 中断里置 `flag = 1`，主循环 `while (!flag) {}` 却永远跳不出去，最可能的原因？
   - A. 中断没使能
   - B. `flag` 没加 `volatile`，编译器把它优化成寄存器缓存
   - C. 主循环优先级太低
   - D. 需要加延时
   - 答案: B
   - 判定: 优化器看到 `while (!flag)` 里没有修改 flag 的语句，就把 flag 读一次放进寄存器，之后只检查寄存器。加 `volatile` 是告诉编译器"每次都必须从内存重读"。A 也是一种可能，但太明显；题目问"最可能"且这是编译通过、逻辑看似正确的经典坑。C 错，主循环没有优先级概念。D 错，加了延时一样卡。
   - 踩坑场景: Debug 模式下（不开优化）一切正常，换成 Release 就卡死，查两小时代码找不到问题——典型的 volatile 缺失。

4. 机械按键做外部中断，按一次却触发了七八次，为什么？
   - A. 中断配置错了
   - B. 按键机械抖动产生多个边沿，都被当成有效触发
   - C. 引脚坏了
   - D. 中断优先级太高
   - 答案: B
   - 判定: 机械触点在闭合/断开的几毫秒内有多次通断，每次跳变都可能触发中断。解法：硬件加 RC 滤波，或软件延时消抖，或改用定时器轮询采样。A 错，配置本身没问题。C 错得太离谱。D 与抖动无关。
   - 踩坑场景: 按键计数器的值按一下跳 5–8，做菜单的时候选不中任何一项。

### 1.4 定时器与 PWM

- 状态: 未开始

**讲解**

一、定时器的本质：一个会自己加一的计数器

定时器核心就三样东西：

- **CNT**：计数器，每个时钟脉冲加 1（或减 1）。
- **PSC**：预分频器。定时器时钟先除以 `PSC+1`，再喂给 CNT。
- **ARR**：自动重装值。CNT 数到 ARR 时归零（向上计数），同时产生一个更新事件。

所以三个频率是层层相除的关系：

```
计数频率 = 定时器输入时钟 / (PSC + 1)
更新频率 = 计数频率 / (ARR + 1)
```

例：72 MHz 的定时器时钟，`PSC=71` → 计数频率 1 MHz（每 1 µs 加一）；`ARR=999` → 每 1000 个计数溢出一次 = 1 kHz = 1 ms 一次中断。

**先定周期再算分频**，反过来算容易乱。

二、PWM 就是"数到某个值就翻电平"

在计数器基础上加一个比较值 **CCR**。硬件不停地比较 CNT 和 CCR：

- CNT < CCR 时输出高（或低，取决于极性）
- CNT ≥ CCR 时反过来

于是占空比天然是 `CCR / (ARR + 1)`，频率只由 PSC 和 ARR 决定，两者互不干扰：

```
PWM 频率 = 定时器时钟 / ((PSC + 1) × (ARR + 1))
占空比   = CCR / (ARR + 1)
```

这就是为什么调亮度/调速度只改 CCR，不动 ARR——改 ARR 会连频率一起改掉。

三、定时器时钟的 ×2 规则（高频考点）

时钟树里已经讲过 APB1 上限 36 MHz。但定时器不是直接吃 PCLK：

- 如果 APB 预分频系数为 1，定时器时钟 = PCLK；
- **如果 APB 预分频系数不为 1，定时器时钟 = PCLK × 2**。

F103 跑 72 MHz 时 APB1 = 36 MHz（分频 2），所以 TIM2–TIM7 的实际时钟是 **72 MHz**，不是 36。同理 APB2 = 72 MHz（分频 1），TIM1/TIM8 时钟也是 72 MHz。

这条规则的存在是为了让定时器在这种分频配置下仍能拿到和 CPU 同频的时钟，精度不打折。

四、定时器的三个等级

| 类型 | 例子 | 多出来什么 |
|---|---|---|
| 基本定时器 | TIM6、TIM7 | 只有计数和中断，给 DAC 做触发 |
| 通用定时器 | TIM2–TIM5 | 4 个通道，输入捕获、输出比较、编码器接口 |
| 高级定时器 | TIM1、TIM8 | 再加互补输出、死区插入、刹车输入——专为电机驱动设计 |

智能车上的电机 PWM 用高级定时器（需要互补和死区），编码器计数用通用定时器（编码器模式），LED 呼吸灯随便一个通用定时器就够。

五、两侧落地

**STM32F103**：

```c
htim3.Instance           = TIM3;
htim3.Init.Prescaler     = 71;      // 72 MHz / 72 = 1 MHz
htim3.Init.Period        = 999;     // 1 MHz / 1000 = 1 kHz
htim3.Init.CounterMode   = TIM_COUNTERMODE_UP;
HAL_TIM_PWM_Init(&htim3);

TIM_OC_InitTypeDef oc = {0};
oc.OCMode     = TIM_OCMODE_PWM1;
oc.Pulse      = 250;                // 初始占空比 25%
oc.OCPolarity = TIM_OCPOLARITY_HIGH;
HAL_TIM_PWM_ConfigChannel(&htim3, &oc, TIM_CHANNEL_1);

HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);
__HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, 750);  // 运行中改占空比到 75%
```

**MSPM0**：SysConfig 里直接填目标频率和占空比，PSC/LOAD 由工具算出来。

```c
DL_TimerG_setLoadValue(PWM_0_INST, 999);           // ARR
DL_TimerG_setCaptureCompareValue(PWM_0_INST, 250, DL_TIMER_CC_0_INDEX);
DL_TimerG_startCounter(PWM_0_INST);
```

差异：STM32 要自己算 PSC/ARR 并写进结构体，改频率得重算；MSPM0 在 SysConfig 里填 Hz 和百分比，PSC/LOAD 自动生成，改频率只要改配置重新生成。

六、三个常见误解

- 「改 ARR 调亮度」——会把频率一起改掉，LED 可能开始闪。调占空比只改 CCR。
- 「PSC 填 72 就是除以 72」——寄存器值要减一，填 71 才是除以 72。差一错误在这里最常见。
- 「定时器时钟就是 PCLK」——分频系数不为 1 时要 ×2。

**选择题**

1. 定时器时钟 72 MHz，要输出 1 kHz、占空比 30% 的 PWM。PSC=71 时，ARR 和 CCR 约为？
   - A. ARR=999，CCR=300
   - B. ARR=1000，CCR=300
   - C. ARR=999，CCR=299
   - D. ARR=720，CCR=216
   - 答案: A
   - 判定: PSC=71 → 计数频率 1 MHz。要 1 kHz 就是每 1000 个计数一轮，ARR+1=1000 → ARR=999。占空比 30% → CCR = 1000×0.3 = 300。B 错，ARR 填 1000 会得到 1 MHz/1001 ≈ 999 Hz。C 错，CCR 不需要减一（它是比较值不是周期）。D 是没除分频的错误算法。
   - 踩坑场景: ARR 少减了 1，PWM 频率差 0.1%，电机转速轻微偏差，示波器测出来才发现。

2. APB1 预分频系数为 2、PCLK1 = 36 MHz，挂在上面的 TIM3 实际时钟是多少？
   - A. 36 MHz
   - B. 72 MHz
   - C. 18 MHz
   - D. 取决于 PSC 设置
   - 答案: B
   - 判定: APB 分频不为 1 时，定时器时钟自动 ×2 补偿。36×2=72 MHz。A 是最常见的想当然，直接按 PCLK 算，导致所有定时都慢一半。C 错。D 错，PSC 是定时器内部再分频，不影响输入时钟。
   - 踩坑场景: 按 36 MHz 算出来的 PSC/ARR，实际跑出来周期只有预期的一半，PWM 频率翻倍。

3. 运行中想把 LED 亮度从 50% 调到 25%，应该改哪个寄存器？
   - A. ARR
   - B. CCR
   - C. PSC
   - D. CNT
   - 答案: B
   - 判定: 占空比 = CCR/(ARR+1)，只改 CCR 不动频率。改 ARR 会同时改频率（可能降到可见闪烁的频段）。改 PSC 影响更大，整个时基都变了。改 CNT 只是强行改变当前计数值，下次溢出就被覆盖，没有意义。
   - 踩坑场景: 用改 ARR 的方式调亮度，调到很暗时 LED 开始肉眼可见地闪——因为频率掉进了几十 Hz。

4. PWM 引脚配置完，示波器上一点波形都没有，最不可能是哪个原因？
   - A. 定时器时钟没使能
   - B. PWM 通道没启动（没调 HAL_TIM_PWM_Start）
   - C. GPIO 没配成复用功能
   - D. 占空比设置成了 100%
   - 答案: D
   - 判定: 占空比 100% 是"一直高电平"，直流电平，示波器上看不到方波但也不是"一点波形都没有"（能测到稳定高电平）。A、B、C 都会导致引脚完全无输出，是真正的高频原因。这题的考点是分清"没有波形"和"波形不对"。
   - 踩坑场景: 折腾半天发现是忘了 `HAL_TIM_PWM_Start`——初始化都配好了，就是没启动。

   **术语**
   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | PSC | 预分频器，把定时器输入时钟再分频 | 粗调旋钮 |
   | ARR | 自动重装值，决定计数到多少归零 | 一个周期的长度 |
   | CCR | 比较值，决定 PWM 占空比 | 一个周期里高电平多长 |

### 1.5 ADC 与 DMA

- 状态: 未开始

**讲解**

一、ADC 怎么把电压变成数字：二分查找

STM32 用的是**逐次逼近型**（SAR）。内部有一个 DAC 和比较器，对未知电压 `Vin` 做二分：

1. 先试 `Vref/2`，比较器说"Vin 更高"→ 保留高半区，最高位记 1；
2. 再试高半区的中间值，如此重复 12 次；
3. 得到 12 bit 结果。

**采一次要 12 个时钟周期**，所以 ADC 时钟不能太快（F103 上限 14 MHz），采样率就是"12 个比较周期 + 采样时间"的倒数。

二、分辨率不是精度

12 bit → 4096 级。3.3 V 参考时每级 `3.3/4096 ≈ 0.806 mV`。这是**理论最小刻度**，不代表能测准到 0.8 mV——实际误差由参考电压稳定性、噪声、采样时间共同决定。

三、采样时间：新手最容易忽略的旋钮

ADC 内部有个小电容，每次采样要把外界电压"抄"到电容上。外部信号源有内阻，内阻越大充电越慢，采样时间太短就抄不准。

- 信号源阻抗小（运放输出）→ 采样时间可以短，采样率高；
- 信号源阻抗大（100 kΩ 电位器、光敏电阻分压）→ **必须加长采样时间**。

F103 的采样时间可选 1.5 / 7.5 / 13.5 / 28.5 / 41.5 / 55.5 / 71.5 / 239.5 个 ADC 时钟周期。智能车的电池电压检测（分压电阻很大）就该用最长的。

四、参考电压

转换的满量程是 `VREF+`，不是"3.3 V"这个数字。很多板子 VREF+ 直接接 VDDA（3.3 V），但如果你的板子接了外部基准芯片（比如 2.5 V），读数满量程就对应 2.5 V，按 3.3 算就全错。

电源电压波动也直接影响读数——电池供电时电压从 4.2 V 掉到 3.6 V，同样是 2048 读数，对应的实际电压变了。要精确测电压，要么用外部基准，要么先测一下 VDDA。

五、连续、扫描、单次

- **单次**：触发一次采一次，适合偶尔读一下。
- **连续**：一个通道不停采，适合实时监测。
- **扫描**：多个通道轮流采，每次触发把序列里的通道全过一遍。

六、DMA 为什么必须上

要采 1000 Hz、每次都要处理数据，用中断就是每秒进 1000 次 ISR，CPU 大半时间耗在进出中断上。

DMA 是"外设直接搬内存"，CPU 只在搬完一整块时才被打扰一次：

```
ADC 转换完成 → 硬件自动把结果写进内存数组 → 搬够 N 个 → 触发一次 DMA 中断
```

CPU 占用从 1000 次/秒降到 1 次/秒，中间可以做别的事。这是电机控制、音频采集的标准做法。

七、两侧落地

**STM32F103**：

```c
HAL_ADC_Start_DMA(&hadc1, (uint32_t *)adc_buf, BUF_LEN);   // 采满 BUF_LEN 个才中断
HAL_ADC_PollForConversion(&hadc1, 10);                      // 若要同步单次读也行
uint16_t v = HAL_ADC_GetValue(&hadc1);
```

**MSPM0**：ADC12 有多个结果寄存器（MEM0–MEM23），SysConfig 里把通道映射到 MEMx。

```c
DL_ADC12_enableConversions(ADC12_0_INST);
DL_ADC12_startConversion(ADC12_0_INST);
while (DL_ADC12_getStatus(ADC12_0_INST) & DL_ADC12_STATUS_CONVERSION_ACTIVE);
uint16_t v = DL_ADC12_getMemResult(ADC12_0_INST, DL_ADC12_MEM_IDX_0);
```

差异：STM32 的 ADC 结果只有一个 `DR` 寄存器，多通道要开 DMA 或扫描模式才能分开存；MSPM0 每个通道有独立的 MEM 结果寄存器，天生能分开读，简单场景不用 DMA。

八、三个常见误解

- 「读到 2048 就是 1.65 V」——前提是参考电压真的是 3.3 V。先确认 VREF+ 接的是什么。
- 「采样时间越短越快越好」——阻抗大的信号源会被采错，读数乱跳。
- 「用中断读 ADC 就行」——低频可以，上了几百 Hz 就该考虑 DMA。

**选择题**

1. 12 bit ADC、VREF = 3.3 V，读到 2048，对应输入电压约是多少？
   - A. 1.65 V
   - B. 2.048 V
   - C. 3.3 V
   - D. 0.806 V
   - 答案: A
   - 判定: 2048 是满量程 4096 的一半，电压也就是 3.3 V 的一半。B 是"把数字当伏特"的经典错误。C 是满量程。D 是最小刻度（1 LSB），不是 2048 对应值。
   - 踩坑场景: 编码器中点应该是 1.65 V，读出来是 2048 一切正常，换了块板子读出来还是 2048 但实际电压不对——那块板的 VREF 接了 2.5 V 基准。

2. 电位器 100 kΩ 接分压，ADC 读数跳动很大（±50 个码）。最有效的改法？
   - A. 加长采样时间
   - B. 提高 ADC 时钟频率
   - C. 把分辨率改成 8 bit
   - D. 换一个更快的 CPU
   - 答案: A
   - 判定: 高阻信号源给采样电容充电很慢，采样时间不够就是"没抄准就截止"。加长采样时间（比如设成 239.5 周期）让电容充满，读数就稳了。B 会让采样更快更不准。C 只是把噪声的绝对码数变小，本质没解决。D 与 ADC 无关。
   - 踩坑场景: 光敏电阻分压读数狂跳，加了无数次软件滤波效果都一般——根子在采样时间设成了 1.5 周期。

3. 每秒要采 1000 次电流做电机过流保护，用什么方式最合适？
   - A. 每次转换完成进中断
   - B. DMA 搬运，搬满一块再中断
   - C. 主循环里轮询
   - D. 用外部中断触发
   - 答案: B
   - 判定: 1000 次/秒的中断，CPU 大量时间在压栈出栈，还可能因为别的高优先级中断延迟处理。DMA 让硬件自己搬，CPU 每秒只被打扰一次。A 能用但浪费。C 完全不可控，主循环忙的时候就漏采样，过流保护失效是致命的。D 与 ADC 采样方式无关。
   - 踩坑场景: 用中断采样做电流环，电机一转起来主循环完全卡住——中断太频繁了。

4. ADC 读数与万用表测的真实电压始终差一个固定比例（比如读数偏大 20%），最可能的原因？
   - A. 采样时间不够
   - B. 代码里假设的参考电压与实际 VREF+ 不符
   - C. 地线没接
   - D. ADC 坏了
   - 答案: B
   - 判定: "固定比例偏差"是最典型的参考电压错误特征——你按 3.3 V 算，实际基准是 2.5 V，算出来的电压就系统性偏大。A 导致的是随机跳动不是固定比例。C 会导致读数漂移或为零。D 概率极低且通常表现为完全异常。
   - 踩坑场景: 自己画的板子 VREF+ 没有单独接，读出来的电压全都偏大，最后发现芯片内部 VREFINT 是 1.2 V 却按 3.3 算了。

   **术语**
   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | SAR | 逐次逼近型 ADC，用二分法逐步确定每一位 | 猜数字游戏 |
   | LSB | 最低有效位，ADC 能分辨的最小电压变化 | 一把尺子上最小的刻度 |

### 1.6 UART 打印调试

- 状态: 未开始

**讲解**

一、为什么调试先上串口

后面所有章节的调试都靠它：变量值、状态机走到哪一步、中断进没进，全打出来看。串口是单片机的"printf"，也是唯一能在不接仿真器时看到内部状态的通道。

**先把串口打通，再做别的**——这是嵌入式开发的第一原则。

二、异步串行：双方靠约定对时

UART 没有时钟线，收发双方各自按约定的**波特率**计时。发送方把每个比特按 `1/波特率` 的宽度摆到线上，接收方在自己的采样点去读。

一帧的结构：

```
空闲(高) | 起始位(低) | D0 | D1 | ... | D7 | [校验位] | 停止位(高) | 空闲
```

- **起始位**：从高电平拉到低，告诉对方"要开始了"，接收方靠这个下降沿对齐计时起点。
- **数据位**：通常 8 位，低位先发。
- **校验位**：可选，简单奇偶校验，错误率要求高才用。
- **停止位**：拉回高电平，至少 1 位。

因为没有时钟线，**波特率必须双方一致**。差太多就是乱码，差一点是偶发误码——很多芯片的容忍度是 2%~3%。

三、波特率怎么来

波特率是从 PCLK 分频出来的，写进 `BRR` 寄存器：

```
波特率 = PCLK / (16 × USARTDIV)
```

72 MHz、115200 bps → `USARTDIV = 39.0625`，整数部分 39、小数部分 0.0625×16 = 1，所以 `BRR = 0x271`。

**关键点**：算 BRR 用的那个 PCLK 必须和实际给外设的时钟一致。CubeMX 里改了时钟树但没重新生成代码，或者手算时把 APB1/APB2 搞混，就会出现"波特率参数写的是 115200，实际跑的是 9600"的乱码。

四、接线的三个检查（90% 的"收不到"都在这里）

1. **交叉**：A 的 TX 接 B 的 RX，A 的 RX 接 B 的 TX。TX 接 TX 永远收不到东西。
2. **共地**：两块板必须接同一根 GND。没有共地，双方对"高电平"的参考不一样，收到的全是噪声。
3. **电平**：3.3 V 和 5 V 系统直连可能烧引脚，要用电平转换或串电阻。

用 USB 转串口模块时还要注意：模块的 TX 接板子的 RX。模块上丝印经常是"对着模块自己"标的，很多人以为要接同名。

五、printf 重定向

标准库的 `printf` 最终会调 `fputc`（Keil/ARMCC）或 `_write`（GCC）。把这个函数改成走串口，`printf` 就直接打到串口上了。

**STM32F103（HAL + GCC）**：

```c
int _write(int fd, char *ptr, int len) {
  HAL_UART_Transmit(&huart1, (uint8_t *)ptr, len, HAL_MAX_DELAY);
  return len;
}
```

Keil 下则是实现 `fputc(int ch, FILE *f)`。两种写法目的相同：把字符送到 UART。

**MSPM0**：SysConfig 的 UART 配置页勾选 printf 支持后，生成的代码会带重定向；手动写就是：

```c
void uart_send(const char *s) {
  while (*s) DL_UART_Main_transmitDataBlocking(UART_0_INST, *s++);
}
```

差异：STM32 要在工程里自己实现 `_write` / `fputc` 并可能需要在链接选项里加 `-u _printf_float` 才能打印浮点；MSPM0 在 SysConfig 里勾一下自动生成重定向，浮点支持也在那里选。

六、三个常见误解

- 「波特率写 115200 就一定对」——外设时钟配错的话，实际波特率是另一个值。
- 「TX 接 TX 是直连」——串口必须交叉。
- 「用 printf 调试很快」——`printf` 内部有格式化开销，在中断里用会拖垮时序，高频路径要用自定义的轻量输出。

**选择题**

1. 串口助手收到一串乱码（比如 `烫烫烫` 或随机符号），最常见的原因？
   - A. 波特率不匹配
   - B. 数据位设错了
   - C. 没接共地
   - D. 串口助手版本太老
   - 答案: A
   - 判定: 波特率差一点就是"每一位都错位"，解出来就是随机符号。数据位设错（8 位当 7 位）也会乱，但表现是固定丢一位，不如波特率问题常见。没共地通常是收不到或全是 0。D 与硬件无关。
   - 踩坑场景: 代码里写的 115200，串口助手也设 115200，还是乱码——因为 APB1 时钟被改过，BRR 算错了，实际波特率是 76800。

2. 两块板子串口连好，A 发 B 完全收不到，测量 A 的 TX 有波形。最可能？
   - A. 波特率不一致
   - B. RX/TX 接成了同名对接
   - C. B 的串口中断没开
   - D. A 的发送函数有 bug
   - 答案: B
   - 判定: A 的 TX 有波形说明 A 在正常发。B 的 RX 没收到，最常见就是线接到了 B 的 TX 上（同名对接），B 的 RX 悬空。A 若波特率差得离谱也可能收不到，但通常表现为乱码。C 是可能原因之一但排在接线之后。D 与"TX 有波形"矛盾。
   - 踩坑场景: 按模块丝印同名相连，调试了两小时，最后拿万用表量通断才发现。

3. 在中断服务函数里调用 `printf` 打印调试信息，可能造成什么后果？
   - A. 没有影响
   - B. 占用大量 CPU 时间，拖慢中断响应甚至丢数据
   - C. 编译报错
   - D. 会自动关闭中断
   - 答案: B
   - 判定: `printf` 的格式化是软件计算，加上串口发送是阻塞的，115200 下发一个字符约 87 µs，一行 30 字符就是 2.6 ms。在 ISR 里这么干，其他中断全被挡住。A 错。C 错，编译合法。D 错，没有这种机制。
   - 踩坑场景: 编码器中断里加了 printf 看计数，结果电机一转就丢计数——ISR 太长了。

4. UART 用 115200、8N1 配置，一帧 10 位，传 100 字节数据大约需要多长时间？
   - A. 约 8.7 ms
   - B. 约 87 ms
   - C. 约 1 ms
   - D. 约 0.87 ms
   - 答案: A
   - 判定: 每帧 10 位（1 起始 + 8 数据 + 1 停止），100 字节 = 1000 位。115200 bps → 1000/115200 ≈ 8.68 ms。B 多了一位小数点。C、D 都算错了位数。
   - 踩坑场景: 评估"能不能用串口传实时波形数据"时算错量级，实际带宽根本不够。

   **术语**
   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | 波特率 | 每秒传输的位数 | 说话速度 |
   | 起始位 | 一帧开头的低电平，用来对齐计时 | 开口前的"喂" |
   | USARTDIV | 波特率分频值，写进 BRR 寄存器的核心参数 | 分频系数 |
   | 共地 | 两块板子共享同一个参考地 | 说同一种语言 |
   | 重定向 | 把标准库的输出改道到串口 | 换个出水口 |
   | 阻塞发送 | 发完才返回，占着 CPU 等 | 排队等窗口 |
