## 小节

### 2.1 光电传感器与循迹

- 状态: 未开始

**讲解**

一、传感器内部发生了什么

反射式光电把一只红外 LED 和一只光敏接收管并排封在一起，中间用挡光板隔开，防止发射光直接窜到接收端。LED 串限流电阻常亮，红外光打到赛道上：白底反射率高，大部分光折回来；黑线把红外吸收掉，回来的很少。

接收管（光敏三极管）反偏工作，光照越强光电流越大。于是「反射率」先被翻译成「电流」，再变成「电压」。它是反射式而不是对射式——收发在同一侧，靠反射光，所以离地高度和安装角度直接决定读数，这类模块的典型检测距离是 1–2 cm（TCRT5000 一类），装高了信号弱，装低了容易蹭赛道。

二、从光到 0/1：比较器与阈值

模块内部的电压比较器把接收管的电压和电位器分出来的参考电压比一比，输出干净的 0/1：白底一种电平、黑线另一种（哪边是高看模块，用之前拿万用表量一次）。

这就是数字输出：一根线、抗干扰、CPU 不用算；代价是只剩「是/不是」，强度信息在传感器内部就丢了，而且阈值由硬件定死，电位器一拧全组一起变，没法逐路微调。

模拟输出是把接收管分压点的电压直接引出来接 ADC：能拿到连续的反射强度，可以按强度算黑线落在两路之间的确切位置，也能随环境光自动改阈值；代价是每路占一个 ADC 通道、必须周期性采样、对电源纹波和环境光更敏感。

比较器本身带滞回（施密特特性），等于硬件先替你抖了一次；走模拟量，这份活要自己在软件里补。

三、数字口接 GPIO：电平与边沿

普通输入：定时器每 1 ms 回调里把 8 个引脚读一遍，拼成一个 8 位位图。这是对「已经压线」的稳态判断，循迹主循环就用它。

外部中断（EXTI）：把这路配成边沿触发，引脚跳变的那一瞬间进中断。它适合「车刚压线」这一刻——要记时间戳、或者要在压线瞬间立刻响应，而不是等到下一个采样点。但别拿它当循迹主循环：8 路带毛刺一起抖，1 ms 内能打断你几十次，采样节奏反而乱了。规矩是中断里只置标志、只记时间，偏差计算留给主循环。

模拟口接 ADC：定时器触发规则组扫描 8 通道，DMA 搬进数组，一次拿全一帧。采样时间加转换时间决定了你最快多久出一帧，这一条第 1 章已经算过。

四、多路排开：从「哪几路压线」到「偏了多少」

8 路等间距排开（间距常见 15 mm），编号 0–7，几何中心在 3.5。任意时刻通常只有 1–3 路压黑线。

最粗的算法是求压线通道编号的平均值再减 3.5，正数偏右、负数偏左。问题是黑线一宽，压线通道数就变，偏差被平均稀释，同一个位置能读出不同的数。

常用的是加权平均（重心法）：每路给一个权值 w_i，偏差 e = Σ(w_i·b_i) / Σ(b_i)，b_i 是「第 i 路压黑线」的 1/0。黑线正压在第 3、4 路之间时 e≈0，压在最左一路时 e≈−3.5，输出与位置一一对应，而且跟压了几路无关。走模拟量时把 b_i 换成实测强度 v_i，就是真正的重心：黑线跨在两路之间时两路都不到满值，按强度插值能把位置落到两路中间——这就是模拟口「亚像素」的来源。

边界情况：一路都没压（丢线）时分母为 0。做法是记住上一帧的 e，按上次的方向给满舵找线，同时把这一帧标记为无效。

五、阈值必须现场标定

改变读数的三个变量：环境光（顶灯、窗边太阳）、赛道材质（KT 板、PVC、打印纸黑度不同）、离地高度（电池电压降了车体下沉）。所以阈值不是一个常数，而是一组「在某块场地上成立」的数。

标定做法：把车停在白底上读一遍 8 路，再停到黑线上读一遍，逐路取两者中点做阈值——8 只管子的一致性没你想的好，共用一个阈值总有一两路先误判。模拟量还要看动态范围：白底 3000、黑线 500，阈值放 1700 很稳；白底 2000、黑线 1500，就别指望软件救，先查高度和供电。

六、车速决定了你能算多慢

车速 1 m/s、间距 15 mm，走完一个间距只要 15 ms；也就是说每隔十几毫秒，传感器底下的图样就完全换一次。采样周期必须明显小于这个时间（一般 1–2 ms 一轮），否则算出来的偏差描述的是「上一帧的车」。

单次读数不可信：黑线边缘毛刺、地面反光点、电机换向的电源纹波都能让它翻一下。三种去抖：连续 N 次一致才认（最简单，代价是延迟 N 个周期）；3 点中值滤波（抗单点毛刺最划算）；滞回区间（进黑线用一个阈值、出黑线用另一个阈值，专治边缘反复跳）。

最常见的翻车：在实验室调了一次阈值就上场，换到深灰底或顶灯变了，8 路一起判错，车一出发就冲出去找线。

**STM32F103**：CubeMX 里把 8 路数字口配成 GPIO_Input（模块是推挽输出就配浮空，是开漏输出才配上拉），需要「压线瞬间」的那一路选 GPIO_EXTIx 并开 NVIC。扫描放在定时器更新回调里，中断里只置标志。

```c
/* 8 路数字光电接 PB0..PB7；1 ms 定时器回调里统一采样 */
static uint8_t g_raw;
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    uint8_t m = 0;
    for (uint8_t i = 0; i < 8; i++)
        m |= (HAL_GPIO_ReadPin(GPIOB, (uint16_t)(1u << i)) == GPIO_PIN_SET) << i;
    g_raw = m;                     /* 去抖、算偏差留给主循环 */
}
/* 压线那一刻：只记时间戳，别在这里算 */
void HAL_GPIO_EXTI_Callback(uint16_t pin)
{
    if (pin == GPIO_PIN_3) g_edge_tick = HAL_GetTick();
}
```

**MSPM0**：SysConfig 的 GPIO 模块把 8 路设成输入、打开指定那一路的边沿中断，掩码和组中断入口都由它生成。DriverLib 按端口掩码一次读全组，比逐脚读省几个周期。

```c
/* 一次读回整组，掩码在 SysConfig 里生成 */
static uint8_t scan(void)
{
    return (uint8_t)DL_GPIO_readPins(GPIO_SCAN_PORT, GPIO_SCAN_ALL_PINS);
}
/* 组中断：查是哪一路，只置标志 */
void GROUP1_IRQHandler(void)
{
    switch (DL_GPIO_getPendingInterrupt(GPIO_SCAN_PORT)) {
    case GPIO_SCAN_EDGE_IIDX: g_edge_tick = tick_ms; break;
    default: break;
    }
}
```

差异：STM32 是 HAL 逐脚读、EXTI 按引脚号进同一个回调再自己判 pin；MSPM0 是 DriverLib 按端口掩码一次读全组，中断按端口成组进 `GROUP1_IRQHandler`，再用 `DL_GPIO_getPendingInterrupt` 查明来源。

**选择题**

1. 反射式光电传感器能区分黑线与白底，根本原因是
   - A. 黑线吸收了大部分红外光，反射回接收管的光弱、光电流小
   - B. 黑线含铁，模块内部有磁敏元件能检出
   - C. 黑线自身的红外热辐射比白底弱，接收管收到的是物体自身辐射
   - D. 黑线使发射管回路的限流电阻变大，LED 变暗
   - 答案: A
   - 判定: A 对，整条链是「反射率 → 光电流 → 电压 → 比较器/ADC」。B 错在反射式光电纯光学，没有磁敏元件，赛道胶带也不含铁。C 错在接收的是自己发出去又反射回来的光，不是物体热辐射，接收管前还常加滤光片专挑发射波长。D 错在限流电阻固定，LED 亮度只由供电和电阻决定，与底下是黑是白无关。
   - 踩坑场景: 用深蓝或红色胶带做赛道，红外反射率和白底差不多，阈值怎么调都飘，最后发现是颜色选错——红外对颜色不敏感，只对「黑不黑」敏感。

2. 一支队伍 8 路全用数字模块，想靠软件算出黑线落在两路传感器之间的确切位置，为什么做不到
   - A. 模块内部的比较器已经把连续强度量化成 1 bit，幅度信息在传感器里就丢了
   - B. 数字口只能配成外部中断，不能轮询
   - C. 加权平均要浮点运算，M0+ 算不动
   - D. 数字模块响应太慢，跟不上 1 m/s 的车
   - 答案: A
   - 判定: B 错，数字口既可轮询也可配中断，这是软件选择。C 错，权重法用整数加法和移位就能做，跟有没有 FPU 无关。D 错，模块响应在几十微秒量级，比 15 ms 的间距时间快两个数量级。真正卡住的是量化：两路同时压线时你只知道「都黑」，不知道哪边更黑，插值无从下手。
   - 踩坑场景: 嫌模拟口接线麻烦全换数字模块，偏差只剩 −3.5 到 3.5 的整数跳变，D 项一微分成了一排尖峰，车抖得像筛子。

3. 实验室调好的阈值，8 路读数正常；到比赛场地（顶灯换成暖光、地面铺深灰 KT 板）后串口打印出 8 路几乎全黑。最可能的原因
   - A. 比较器阈值没重新标定，深灰底反射也弱，被判成黑线
   - B. 传感器供电不足，LED 亮度下降
   - C. 定时器采样周期太长，读到了旧数据
   - D. 电机 PWM 干扰让 GPIO 电平翻转
   - 答案: A
   - 判定: A 对，数字模块的阈值是电位器定死的绝对电压，底材反射率一掉，白底那点反射也低于阈值，全组一起判黑。B 若真供电不足，读数会不稳、边沿乱跳，不会整齐全黑，而且第一步该量 VCC。C 采样慢只造成滞后，读到的仍是真实电平，不会把白判成黑。D 干扰是偶发毛刺，去抖能滤掉，不会持续一致。
   - 踩坑场景: 全场 8 路全黑，车判定自己在赛道外，满舵找线直接撞墙。重标一遍阈值只要三十秒。

4. 车 1.5 m/s，8 路间距 15 mm。要保证每走过一个间距就已经重新算过一次偏差，采样周期该取多少
   - A. 1–2 ms，留 5–10 倍余量
   - B. 10 ms，正好一个间距
   - C. 100 ms
   - D. 1000 ms
   - 答案: A
   - 判定: 通过一个间距的时间 t = 15 mm ÷ 1.5 m/s = 10 ms，这是极限值。B 取等于极限，等于每走一格才看一眼，采到的永远是上一个位置，边沿必漏。C 慢一个数量级，10 ms 内图样已换一次，车会画龙。D 一个周期车已跑 1.5 m，完全不可用。所以实际取 1–2 ms。
   - 踩坑场景: 把扫描放进 while 主循环又加了串口打印，一帧 30 ms，车看上去能走直，一进弯就冲出去——偏差永远是三十毫秒前的。

### 2.2 编码器与测速

- 状态: 未开始

**讲解**

一、编码器的信号从哪来：码盘加 A/B 两相

增量式编码器的码盘上刻着一圈均匀的栅格，一边是发光管、一边是接收管，盘一转，接收管就吐出一串方波。A、B 两路各有一套接收管，位置错开半个栅格，于是两路方波固定相差 90°。线数（PPR）指每转的栅格数，500 线就是转一圈吐 500 个周期。

单看一路脉冲，数得出“转了多少格”，数不出“往哪边转”。方向信息藏在相位先后里：正转时 A 先到、B 后到，反转就反过来了。这就是必须有 A、B 两相的原因。

二、正交解码与四倍频

把 A、B 当成两位二进制一起看，一转下来是 `00→01→11→10→00` 循环，反转时走反序。这套编码的好处是相邻状态每次只变一位，所以任何一个边沿都能唯一确定“加一还是减一”。

一个栅格周期里状态变了四次，四个边沿都能拿来计数，这就是**四倍频**：500 线的编码器，转一圈能数到 2000。倍频不增加信息量，只是把已有的边沿信息用满，分辨率变细，代价是噪声也被放大四倍。

三、Z 相：每转一次的基准点

Z 相（索引脉冲）每转只出一个脉冲，宽度通常和一路栅格一样。上电时 CNT 是随机的，谁也不知道转子停在哪；先慢慢转一圈碰到 Z，把计数清零，此后 CNT 就代表“从零点起转过的角度”，这是单圈定位的基准。

多圈定位 Z 相救不了——断电就丢了圈数，得靠绝对值编码器或者额外记圈。

四、让定时器去数：编码器接口模式

“看另一个相的电平决定加减”这套逻辑，通用定时器的硬件里已经做进去了：`TIMx_SMCR` 的 SMS 位选 001/010/011 就是编码器模式 1/2/3，模式 3 同时用 TI1、TI2 的边沿，正好是四倍频。CPU 完全不参与计数，需要时读一下 CNT 就行。

方向不用另读寄存器：CNT 差值的符号就是方向，`TIMx_CR1` 的 DIR 位是同一个信息的另一种读法，区别只在它要到计数发生之后才翻转。

拿外部中断数脉冲的代价可以用一个例子算出来：编码器装在电机轴上，每转 4000 个计数，电机 6000 RPM 就是每秒 40 万个边沿。72 MHz 的 M3 平均每 180 个周期就要进一次中断，中断里还要做乘除，采样周期立刻失去规律。同时 Cortex-M3 和 M0+ 都没有 FPU，中断里写浮点会走软件浮点库，一条除法几百个周期，测速本身就被自己拖歪了。

**中断只负责搬数，运算留给主循环**，这条在测速上尤其成立。

五、三种测速法的取舍

- **M 法（测频）**：固定闸门时间 T，数这段时间里来了多少脉冲 M，转速正比于 M/T。误差是 ±1 个脉冲：高速时 M 大，相对误差小；低速时 M 可能只有两三个，量化误差就占了百分之几十。
- **T 法（测周）**：直接测相邻两个边沿之间的时间 T，转速正比于 1/T。低速周期长、测得准；高速周期短，捕获时钟 ±1 个计数的误差占比变大。
- **M/T 法**：既数脉冲又测实际经过的时间，闸门不是固定的而是“数满 M 个脉冲为止”，两头都覆盖得住，代价是要两个定时器配合。

T 法和 M/T 法的落地手段是**输入捕获**：定时器在指定边沿上把当时的 CNT 抄进 CCR，读 CCR 得到时间戳，两次相减就是脉宽或周期。智能车上更常用 M 法——控制周期本来就是 10 ms 读一次速度，闸门时间天然存在。

纯 M 法在堵转和极低速时会读到 0，闭环分不清“停住了”和“转得很慢”，所以起步段常切成 T 法，或者干脆先给一小段开环把车推起来。

六、从计数到 RPM：一条换算链，两个必须处理的细节

```
每输出轴一圈的计数 = 线数 × 倍频 × 减速比
RPM = (Δcount ÷ 每圈计数) ÷ Δt(秒) × 60
```

500 线、四倍频、1:30、10 ms 内差 200：每圈 60000 计数，200/60000/0.01×60 = 20 RPM。

减速比是乘进去的，因为 1:30 意味着电机转 30 圈输出轴才转一圈，输出轴一圈自然要数 30 圈的脉冲。编码器要是直接装在输出轴上，这一项就是 1。

细节一，**回绕**。16 位 CNT 从 65535 加一就回到 0，直接比大小会把 5 当成比 65530 小。正确写法是算有符号差 `(int16_t)(now - last)`，只要一次采样内的变化不超过 ±32767，回绕就自动成立，连 if 都不用写。

细节二，**滤波**。读数量化本身有 ±1 的抖动，机械振动还会叠进来。一阶低通一行就够：`y = y + α(x - y)`，α 大则跟得快但毛刺照搬，α 小则平滑但滞后。10 ms 采样下一般取 0.1–0.3。滞后在闭环里是实打实的相位损失，所以 α 不是越小越好。采样周期也别贪快：10 ms 已经够 200 Hz 的观测带宽，缩到 1 ms 只会让 ±1 的量化噪声占比翻十倍。

**STM32F103**：CubeMX 里把定时器 Combined Channels 设成 Encoder Mode，两个通道极性都选 Rising，Encoder Mode 选 TI1 and TI2（四倍频），ARR 保持 65535 满量程。

```c
htim2.Instance = TIM2;
htim2.Init.Period = 65535;

TIM_Encoder_InitTypeDef enc = {0};
enc.EncoderMode = TIM_ENCODERMODE_TI12;        // TI1+TI2 双边沿，四倍频
enc.IC1Polarity = TIM_ICPOLARITY_RISING;
enc.IC2Polarity = TIM_ICPOLARITY_RISING;
HAL_TIM_Encoder_Init(&htim2, &enc);
HAL_TIM_Encoder_Start(&htim2, TIM_CHANNEL_ALL); // 必须启动，否则 CNT 不动

int16_t step = (int16_t)(__HAL_TIM_GET_COUNTER(&htim2) - last);
last += step;                                   // 回绕在这里自动处理掉了
```

**MSPM0**：SysConfig 里把 TIMG8 设成 QEI 模式，PHA/PHB 引脚和计数倍频都在配置页选，生成的 `ti_msp_dl_config.c` 里已经配完。


**选择题**

1. 增量式编码器为什么至少要有 A、B 两路信号？
   - A. 两路做差分传输，用来抵消线路上的共模干扰
   - B. 一路只能数转过的栅格数、判断不了转向；A、B 相差 90°，先 A 后 B 还是先 B 后 A 就代表了正反转
   - C. 两路是为了把分辨率提高一倍，跟方向无关
   - D. 定时器要求成对接入，两个通道必须都占上
   - 答案: B
   - 判定: B 对，方向编码在相位先后里，正交解码就是把这两位状态的变化翻成加减。A 错，差分对是 A 与 A̅ 一对互补线的事，正交编码器的 A、B 是两路独立信号，各占一根线，靠对地参考。C 错，分辨率来自边沿数（倍频），多一路信号本身不提高分辨率；只数 A 相上升沿就是一倍频，方向依然没有。D 错，接两个通道是正交解码后的结果，不是硬性前提——纯软件轮询两个 GPIO 也能解。
   - 踩坑场景: 图省事只接了 A 相。车在坡上往后溜了一下，程序照样在累加，积分项越滚越大，再起步时机子直接窜出去，撞了赛道的挡板。

2. 编码器模式 3（TI1 and TI2 双边沿）下，1000 线的编码器，电机轴转一圈 CNT 变化多少？
   - A. 1000
   - B. 2000
   - C. 4000
   - D. 由 ARR 决定，ARR 填 1000 就是 1000
   - 答案: C
   - 判定: C 对，模式 3 在两个通道的双边沿都计数，一个栅格周期四个边沿，1000×4=4000。A 是只数 A 相上升沿的结果（一倍频）。B 是只数两路上升沿的结果（二倍频），常见于模式 1 或模式 2 的配置。D 错，ARR 只决定数到多少溢出，不决定数多少个；编码器模式下 ARR 一般就设 65535，让它别那么早绕圈。
   - 踩坑场景: 换算系数按 1000 算，屏幕上的车速只有真实的四分之一。PID 一看“车才这么慢”，占空比一路顶到 100%，车冲出去还以为是 PID 参数有问题。

3. 车停着不动，串口打出来的速度却在小范围乱跳，偶尔蹦出个几百。下面哪个最不可能是原因？
   - A. A/B 输入没开内部上拉，静止时引脚悬空，被电机噪声触发
   - B. 两次采样直接拿 `uint16_t` 相减，反向或回绕时差值变成六万多
   - C. 编码器定时器没启动，CNT 停在 0，代码却把别的变量当成了计数
   - D. 减速比填成了 1:20，实际是 1:30
   - 答案: D
   - 判定: D 最不可能，减速比错只让整体比例差 1.5 倍，读数依然平滑、方向依然正确，不会乱跳。A 会有毛刺，因为悬空引脚会被噪声随机翻转，静止时也照样计数。B 的表现正是“偶尔蹦出极大值”，符号位一丢就变成六万多。C 会让读数恒为某个怪值或完全不动，容易被误当成乱跳，但它不会真的随机变化。
   - 踩坑场景: 抱着示波器调了一晚上滤波系数，α 从 0.5 试到 0.05 都没用，最后发现 A/B 线上少了两颗上拉电阻，手一靠近电机读数就跳。

4. 500 线编码器装在电机轴上，四倍频，减速比 1:30，控制周期 10 ms。某个周期读到计数差 200，输出轴转速约是多少？
   - A. 20 RPM
   - B. 600 RPM
   - C. 2400 RPM
   - D. 0.33 RPM
   - 答案: A
   - 判定: 每输出轴一圈 500×4×30 = 60000 个计数。200 个计数是 0.00333 圈，除以 0.01 s 得 0.333 圈每秒，乘 60 就是 20 RPM。B 漏了减速比：200/2000 = 0.1 圈每 10 ms，即 10 圈每秒 = 600 RPM。C 把倍频和减速比一起漏了：200/500 = 0.4 圈每 10 ms = 40 圈每秒。D 算到“圈每秒”就收了笔，忘了乘 60。
   - 踩坑场景: 公式里漏掉减速比，遥控器上显示 600 RPM，实车才 20 RPM。按 600 去调 PID，P 给到极小还是过冲，怎么调都不对——错的不是参数，是量纲。

**讲解**

一、MPU6050 是六轴 IMU，不是"角度传感器"

MPU6050 把三轴 MEMS 加速度计、三轴 MEMS 陀螺仪和一颗温度传感器封在一颗芯片里，通过 I2C 挂在单片机上，7 位地址默认 0x68（模块上 AD0 拉高则变 0x69）。MEMS 加速度计的核心是一片悬空的硅质量块，加速度让它偏移，差分电容随之变化，芯片把电容差解调成数字量；陀螺仪则先让质量块在驱动方向持续振动，芯片转动时科里奥利力把这份振动耦合到正交的检测方向，测到的耦合量正比于角速度。所以它给你的永远是六个原始读数——三个加速度、三个角速度，角度是单片机自己算出来的，芯片不会输出"我现在歪了 5 度"。那颗温度传感器也不是给你测气温的，它的用途是零偏的温度补偿。芯片坐标系按右手系定：模块平放、丝印朝上时，x、y 在板面内互相垂直，z 垂直板面向外，pitch 和 roll 的正负全看这个约定和实际装法。比它高一档的是九轴 IMU（多磁力计和气压计），智能车用不上：赛道是平的，磁力计还会被电机磁场带偏，多出来的轴只增加融合的麻烦。常见模块 GY-521 把芯片、3.3 V LDO、上拉电阻和去耦电容都做在板上，丝印写着 5 V 供电其实是喂给 LDO 的，I2C 上拉仍然接 3.3 V。安装位置尽量靠近车体重心并加减震垫，模块离电机越近，振动就越直接地变成加速度计的高频噪声。上电第一件事读 WHO_AM_I（0x75），返回 0x68 才说明地址对、线通、芯片活着；读回 0x00 或 0xFF，分别是根本没有应答和总线被拉死。

二、陀螺仪：角速度积分，漂移是结构性的

陀螺仪输出的量是角速度，单位 °/s，必须积分才能变成角度：angle_new = angle_old + gyro × dt。问题出在静止时它也不回零——零偏（bias）典型在 ±20 °/s 量级，个体差异、温度、供电电压、焊盘应力都会让它变。它是个近似常数的偏置，而积分对常数误差是纯累加：0.5 °/s 的零偏，一分钟就是 30°。所以"陀螺必然漂"不是精度不够，是积分这个运算把有界误差变成了无界误差，算得再准也只是把漂得慢一点。量程和分辨率是一对矛盾：±250 °/s 档的灵敏度是 131 LSB/(°/s)，±2000 °/s 档只剩 16.4 LSB/(°/s)，量程选大不容易削顶，但静止时的细微转动就分不出来了。漂移也不止零偏一种：白噪声积分形成角度随机游走，温漂则让零偏随着板子发热慢慢爬，前者靠滤波压，后者只能靠标定或恒温。常用对策是上电后让车静止几百毫秒，采几百个样本求平均当零偏减掉，但这样只压得住常温这一小段，跑热了又回来。判断"静止"不能只问陀螺——它正坚称自己在转——要看编码器速度为零、加速度计模长回到 1 g，两个条件都满足才敢采零偏。积分本身也有量化误差，但小到可以忽略：16.4 LSB/(°/s) 意味着 1 个 LSB 只有 0.06 °/s，落到 5 ms 的积分步长上是 0.0003°，比零偏小几个数量级，所以精度瓶颈永远是零偏，不是分辨率。还有一个隐形坑是 dt：积分用的时间必须来自真实定时器周期，如果 dt 是"循环跑一圈大概多久"估出来的，它的抖动会直接乘进角度里。正因为漂，单独的陀螺永远需要一个外部参考把它拉回来，这就是下一节加速度计的用处。

三、加速度计：测的是比力，静止时才等于重力

加速度计测的物理量叫比力（specific force），不是"运动加速度"：静止平放时它读到 +1 g（桌面给的支撑力），自由落体时读 0，加速时读数是重力与车体加速度的矢量和。正因为静止时它只感受到重力，才能用各轴分量反推倾角：pitch = atan2(-ax, √(ay²+az²))，roll = atan2(ay, az)，符号和轴序取决于模块怎么装、芯片坐标系怎么定，代码要按实际装法改。用 atan2 而不是 asin，是为了在 ±90° 附近仍然连续，也避开了除零；但它也只能算 pitch 和 roll，绕重力轴的 yaw 转动不改变重力在三个轴上的投影，加速度计根本看不见。三个轴还有一个免费的诊断量：读数矢量的模长应该接近 1 g，明显偏离就说明车正在加减速或刚被撞了一下，这一刻算出的 accAngle 根本不该信。它的毛病全在动态：车一加速、过弯、压过减速带，车体加速度混进重力里，算出的角度跟着假；电机和路面的振动又让它高频乱抖。所以它的可信区间在低频——长时间平均，它指向的确实是重力方向；瞬时值不能直接拿去做控制，否则车一给油，姿态角就跟着油门跳。

四、互补滤波：一个高通、一个低通，频段正好接上

两者的误差分布是互补的：陀螺短时准、长时漂，等效于高频可信、低频不可信；加速度计长时准、短时抖，等效于低频可信、高频不可信。于是一个高通、一个低通，频段正好拼成一条平坦的全通曲线：angle = α(angle + gyro·dt) + (1 - α)·accAngle。具体到实现，陀螺那一路是个带泄漏的积分器（每拍保留 α 份旧值，缓慢的零偏会一点点被衰减掉），加速度计那一路是被 (1 - α) 加权的低通，两者和一阶 RC 的高低通是同一个结构。α 常取 0.95–0.98，物理含义是时间常数 τ ≈ dt/(1 - α)：dt = 5 ms、α = 0.98 时 τ ≈ 0.25 s，对应 0.6 Hz 左右的分界，比这快的姿态变化信陀螺，比这慢的缓慢漂移交给加速度计拉回来。α 越大，输出越平滑、越抗振，代价是加速度计纠正得越慢，上电初始角和残余零偏要更久才收敛；α 太小，就把加速度计的抖动全放进来了，车一颠角度就跳。α 不能取 0.5，那等于每拍一半信加速度计，车的振动会原样搬进角度；也不能取到 0.99 以上，那几乎不听加速度计，零偏漂起来没人管。0.95–0.98 就是在"抗抖"和"纠漂"之间找的折中，具体值按车的振动强度试。上电时先用加速度计算出的角度给 angle 赋初值，再让陀螺接管，能省掉这段收敛。卡尔曼滤波干的是同一件事，区别在于它按噪声大小动态分配权重，还顺带给出估计的不确定度；互补滤波的权重是固定死的。智能车采样 100–200 Hz、姿态变化不剧烈，互补滤波够用，卡尔曼的 Q/R 反而难调。dt 必须和实际采样周期严格一致——放在固定周期的定时器中断里算，别把主循环里"大概隔了多久"当 dt 用。

五、I2C：两根开漏线，高电平靠上拉

I2C 只有两根线，SDA 和 SCL，都是开漏输出：器件只能把线拉低，不能主动推高，高电平完全靠外部上拉电阻（常用 4.7 kΩ）。于是总线上是"线与"逻辑——任何一个器件拉低，整条线就是低，不会出现两个器件对推烧引脚；也正因为线与，同一对线上可以挂 MPU6050、OLED、EEPROM 好几个从机而不打架。起始条件是 SCL 为高时 SDA 由高变低，停止条件是 SCL 为高时 SDA 由低变高；数据位只在 SCL 低电平期间允许改变，SCL 高电平期间被采样。一帧是 7 位地址加 1 位读写方向，第 9 个时钟由接收方把 SDA 拉低表示 ACK，不拉低就是 NACK——地址没人应答，或者主机读够了主动 NACK 表示"不要了"。HAL 的函数要传 8 位地址，所以 0x68 得左移一位写成 0xD0/0xD1，这是最常见的"代码看着没问题却一个字节都读不出"的原因。时钟拉伸是从机忙不过来时把 SCL 按在低电平不放，主机必须等它松手；上拉太弱、排线太长、速率拉到 400 kHz 以上，上升沿变慢（上升时间是上拉电阻乘总线电容），边沿就会被误判成起始或停止——4.7 kΩ 配一小段杜邦线余量很大，线一拉长、电容上到几百 pF，就开始丢包。真挂死了（从机一直把 SDA 拉低）可以手动发 9 个 SCL 时钟把它顶出来。另外 MPU6050 的 IO 是 3.3 V 电平，5 V 单片机直连会通过上拉往它灌电流，要加电平转换。

六、初始化和读数：四步配好，一次读 14 字节

MPU6050 上电默认处于睡眠态，第一步必须写 PWR_MGMT_1（0x6B）清掉睡眠位（bit6）把它唤醒，否则后面读什么都是死的。然后写 GYRO_CONFIG（0x1B）和 ACCEL_CONFIG（0x1C）选量程，FS_SEL 和 AFS_SEL 都在 bit4:3；写 SMPLRT_DIV（0x19）定采样率，DLPF 开启时输出速率 = 1 kHz / (1 + SMPLRT_DIV)，控制周期 5 ms 就把它配到 200 Hz 左右（SMPLRT_DIV ≈ 4）；最后读 WHO_AM_I 确认在线。顺序也有讲究：唤醒后留几十毫秒让内部振荡器稳下来再配量程，配完再读数据，否则开头几帧是垃圾。量程直接决定换算系数：±2000 °/s 档是 16.4 LSB/(°/s)，±2 g 档是 16384 LSB/g；量程选大了浪费分辨率，选小了急转弯或颠簸会削顶——读数卡在 ±32767 不动，滤波跟着发散。数据寄存器从 0x3B 起连续排列 14 个字节：加速度 6 + 温度 2 + 陀螺 6，一次连续读完，比按六个量零散读省掉十几次起始和地址开销，也保证六个量是同一时刻的快照；芯片读寄存器时地址会自动递增，所以不用重复发地址。拼字节时记得先转成有符号 16 位，raw 是补码，直接按无符号拼，负的角速度会变成 65000 多。温度那个值是顺带的，换算成摄氏度是 raw / 340 + 36.53，主要用来观察板子热了没有。INT 引脚可以接外部中断，数据就绪时再读，比在 main 里盲读省 CPU，也顺带把采样节拍钉死。智能车真正需要闭环的只有 pitch 和 roll（车身前后倾、左右倾），yaw 没有磁力计提供绝对参考，纯靠陀螺积分只会一直漂，干脆不用它。

**STM32F103**：CubeMX 里把 I2C1 配成 I2C（400 kHz），生成的 `hi2c1` 直接用；HAL 用"寄存器地址 + 连续读"封装，重复起始由驱动内部发，注意地址要左移。

```c
uint8_t who, b[14], c[2];
HAL_I2C_Mem_Read(&hi2c1, 0x68 << 1, 0x75, I2C_MEMADD_SIZE_8BIT, &who, 1, 50);   /* 回 0x68 才在线 */
c[0] = 0x6B; c[1] = 0x00; HAL_I2C_Master_Transmit(&hi2c1, 0x68 << 1, c, 2, 50); /* 清睡眠位 */
c[0] = 0x1B; c[1] = 0x18; HAL_I2C_Master_Transmit(&hi2c1, 0x68 << 1, c, 2, 50); /* ±2000 °/s */
c[0] = 0x1C; c[1] = 0x00; HAL_I2C_Master_Transmit(&hi2c1, 0x68 << 1, c, 2, 50); /* ±2 g */
HAL_I2C_Mem_Read(&hi2c1, 0x68 << 1, 0x3B, I2C_MEMADD_SIZE_8BIT, b, 14, 100);    /* 一次 14 字节 */
int16_t ax = (int16_t)(b[0] << 8 | b[1]), ay = (int16_t)(b[2] << 8 | b[3]);
int16_t az = (int16_t)(b[4] << 8 | b[5]), gx = (int16_t)(b[8] << 8 | b[9]);
float pitch = atan2f(-ax, sqrtf((float)ay * ay + (float)az * az)) * 57.2958f;
angle = 0.98f * (angle + gx / 16.4f * dt) + 0.02f * pitch;
```

**MSPM0**：SysConfig 的 I2C 模块里选 Controller、速率 400 kHz、引脚复用，生成 `I2C_0_INST`；DriverLib 只给"发起传输 + 塞 FIFO + 查状态位"的积木，重复起始和逐字节搬运得自己按顺序拼。

```c
/* 唤醒：先填 FIFO 再启动传输，7 位地址直接写 0x68 */
uint8_t tx[2] = {0x6B, 0x00};
DL_I2C_fillControllerTXFIFO(I2C_0_INST, tx, 2);
DL_I2C_startControllerTransfer(I2C_0_INST, 0x68, DL_I2C_CONTROLLER_DIRECTION_TX, 2);
while (DL_I2C_getControllerStatus(I2C_0_INST) & DL_I2C_CONTROLLER_STATUS_BUSY_BUS) {}
uint8_t reg = 0x3B;
DL_I2C_fillControllerTXFIFO(I2C_0_INST, &reg, 1);
DL_I2C_startControllerTransfer(I2C_0_INST, 0x68, DL_I2C_CONTROLLER_DIRECTION_TX, 1);
while (DL_I2C_getControllerStatus(I2C_0_INST) & DL_I2C_CONTROLLER_STATUS_BUSY_BUS) {}
DL_I2C_startControllerTransfer(I2C_0_INST, 0x68, DL_I2C_CONTROLLER_DIRECTION_RX, 14);
for (int i = 0; i < 14; i++) {
    while (DL_I2C_isControllerRXFIFOEmpty(I2C_0_INST)) {}
    b[i] = DL_I2C_receiveControllerData(I2C_0_INST);
}
```

差异：HAL 把"寄存器地址 + 连续读"封成一个 `HAL_I2C_Mem_Read`，地址要吃左移后的 8 位（0xD0），重复起始由驱动管；DriverLib 只给起始、塞 FIFO、查 BUSY 的积木，地址直接写 7 位 0x68，时序得自己一段段排。MSPM0 侧函数名以 SDK 的 `dl_i2c.h` 为准，各版本（Controller/Master 命名）略有出入，我没逐行验证过。

**选择题**

1. 关于 MPU6050 的陀螺仪输出，下列说法正确的是？
   - A. 直接输出机身倾角，单位是度，读出来就能用
   - B. 输出绕各轴的角速度，单位 °/s，乘采样周期累加才得到角度
   - C. 输出的是三轴线加速度，单位 g，和加速度计重复
   - D. 靠检测地磁场方向推算姿态，所以不怕漂
   - 答案: B
   - 判定: 陀螺仪是角速度传感器，±2000 °/s 档下 16.4 LSB 对应 1 °/s，角度是积分出来的，所以 B 对。A 错在把"积分后的结果"当成芯片输出，MPU6050 寄存器里没有角度这一项；C 把陀螺仪和加速度计搞混，加速度计才输出 g；D 描述的是磁力计，MPU6050 是六轴，没有磁力计，这也正是 yaw 会漂的根因。
   - 踩坑场景: 直接把陀螺的 raw 值当角度喂给 PID，车静止时 raw 在 0 附近抖，PID 以为车身正；车一转 raw 冲到几千，PID 输出瞬间打满，舵机"啪"地打死。

2. 陀螺积分出的角度会一直漂，加速度计算出的角度不会长期漂，根本原因是什么？
   - A. 陀螺仪的精度天生比加速度计低一个数量级
   - B. 陀螺的零偏是近似常数的误差，积分把它变成线性增长；加速度计长期均值始终对准重力方向
   - C. 加速度计内部有温度补偿，陀螺仪没有
   - D. 陀螺的采样率太低，漏掉了数据点
   - 答案: B
   - 判定: 漂移的机制是"常数误差经过积分变成斜坡"，而重力是天然的绝对参考，加速度计再怎么抖，长时间平均仍指向重力，所以 B 对。A 错在把机制问题说成精度问题——精度再高的陀螺，零偏也只是更小，积分照样线性发散；C 错在两颗传感器都受温度影响，MPU6050 的温度传感器就是给两者做补偿的；D 错在采样率低只会让积分粗糙，不会造成单向漂移。
   - 踩坑场景: 上电没做零偏校准就发车，前 3 秒看着还行，10 秒后 pitch 已经偏了 5°，车在直道上慢慢往一边斜，人以为是舵机中位没调好，调了一下午机械。

3. 车静止在桌上，互补滤波输出的 pitch 在 2 秒内从 0° 缓慢爬到 8°，而单独用加速度计算出的角度稳定在 0.5° 左右。最可能的原因？
   - A. I2C 上拉电阻没接，读到的陀螺数据恒为 0
   - B. 陀螺零偏没校准，0.98 的权重让积分漂移压不住
   - C. 加速度计量程设成 ±16 g，分辨率不够
   - D. α 设成了 0.5，太相信加速度计了
   - 答案: B
   - 判定: 加速度计角度稳、融合结果却单向爬，说明爬升来自陀螺那一路——零偏被积分，而 α = 0.98 时每拍只放 2% 的加速度计修正，τ ≈ 0.25 s 的纠正速度追不上持续注入的偏置，所以 B 对。A 若成立，陀螺项恒为 0，输出只会被加速度计拉向 0.5°，不会爬到 8°；C 只影响分辨率和噪声，量程再大也不会造成单向漂移；D 恰好相反，α = 0.5 时加速度计权重 50%，输出会紧紧贴着 0.5°，更不会爬。
   - 踩坑场景: 车在赛道上原地等发车，30 秒后姿态角已经偏了十几度，起步一瞬间舵机按错误的角度打了一把，车直接冲出赛道——问题不在控制参数，在上电那两秒没让车静止下来做零偏校准。

4. 陀螺量程 ±2000 °/s（16.4 LSB/(°/s)），本次读到 gx = 1640，采样周期 5 ms，α = 0.95，上一拍融合角 10.0°，本拍加速度计算出的 pitch 是 12.0°。本拍互补滤波输出约为？
   - A. 10.5°，因为加速度计那一路可以忽略
   - B. 10.6°
   - C. 10.9°
   - D. 12.0°，应该完全相信加速度计
   - 答案: B
   - 判定: 先换算角速度 1640 / 16.4 = 100 °/s，积分增量 100 × 0.005 = 0.5°，预测角 10.5°；再融合 0.95 × 10.5 + 0.05 × 12.0 = 9.975 + 0.6 = 10.575 ≈ 10.6°，B 对。A 是把 (1 - α) 项直接扔掉，短时间看差别小，但长期就没有东西把漂移拉回来了；C 通常来自 α 用反（0.05 × 10.5 + 0.95 × 12.0 ≈ 11.9，也不对）或把 0.5° 当成 0.6° 累加；D 是完全不用陀螺，等于放弃高频响应，车一抖角度就跳。
   - 踩坑场景: 量程配成 ±2000 °/s 却按 ±250 的 131 LSB/(°/s) 换算，算出的角速度大了 8 倍，互补滤波里陀螺项直接压过加速度计，车过弯时角度瞬间冲到几十度，PID 疯了一样修。

**讲解**

一、有刷电机为什么能转

永磁体在定子上造出恒定磁场，转子线圈通电后变成电磁铁，同极相斥、异极相吸，转子上就有了转矩——这就是「通电导体在磁场里受力」（F = BIL）的宏观样子。转矩大小 T ≈ Kt·I，正比于绕组电流，所以「控电机」本质是「控电流」，调电压只是间接手段。麻烦在于转子转到磁极对齐的位置，转矩归零，再往前只会被吸回去。所以必须有换向器：每转过半圈，电刷从一个换向片跳到下一个，把线圈里的电流方向翻过来，转矩方向不变，电机才能连续转。电刷跳片那一瞬间会短暂短接两个换向片，电流突变打火，这是车上干扰的老家。

空载时电流很小，转速由 V ≈ Ke·ω 决定；一加负载转速掉下来，反电动势变小，电流自动变大去顶住负载，这是有刷电机自带的自调节。刚上电那一瞬间转子还没转，反电动势为 0，电流只受绕组电阻限制，是额定电流的好几倍——这就是启动电流大、驱动容易过流保护的原因。

真实转子上不是一个线圈，而是三个（或更多）绕组均匀分布，换向片也按角度分成多片，每一刻只有处在磁场合适位置的绕组被通电。所以换向是一段一段发生的，转矩并不绝对平滑，低速时能感到轻微的顿挫。电刷是消耗品，跑久了会磨短、接触电阻变大，有刷电机的寿命基本由电刷决定——比赛后期同一组占空比感觉车速变慢，先怀疑电刷和电池，别先改 PID。

二、H 桥：四个 MOSFET 拼出四种状态

四个管子摆成 H：左边 Q1（上）Q2（下），右边 Q3（上）Q4（下），电机接在两个中点之间。

拆开看，H 桥就是两个半桥：每个半桥的上管接电源、下管接地，中点电压由这一侧的上管占空比决定。电机看到的是两个中点之间的电压差，所以正转时左半桥给占空比 D、右半桥给 0，电机两端就是 D×Vbus；想要反转就把两边对调。这也解释了换向为什么必须先降速：带着占空比直接掉头，等于把两个半桥的电压差瞬间反号。

- 正转：Q1 + Q4 导通，电流走「电源 → Q1 → 电机 → Q4 → 地」。
- 反转：Q3 + Q2 导通，电流反向。
- 刹车：Q2 + Q4 同时导通（下管双开），电机两端一起被短接到地，转子的反电动势变成制动电流，能量烧在绕组和管子电阻上，车停得快。此时电流不回流电源。
- 滑行：四管全关，电机两端悬空，只剩摩擦慢慢减速。

关键规律：能出力的组合永远是「一个上管 + 对侧下管」，同一侧的上下一起来就是短路。由此 H 桥能让电机跑在四个象限：正转出力、反转出力、正转制动、反转制动，智能车下坡时用制动象限限速就是这个道理。

还要记住关断那一下电流去哪了：正转时把 Q1、Q4 关掉，绕组电感不肯让电流突变，它会经 Q2、Q3 的体二极管继续流回电源。这条续流通路 H 桥天生就有，低压场合不用额外并二极管；只有电流大、压降不能忍时才换肖特基或做同步整流。

刹车很烫是有代价的：动能全变热。如果让运转中的电机直接切到反转组合，电源电压和反电动势串联加在绕组上，电流接近堵转电流，这叫反接制动——冲击极大，代码里不能从正转直接跳反转，中间至少插一段刹车或滑行。赛道上绝大多数减速其实是降占空比滑行，刹车只在急停或进弯前收速度时点一下，一直拿刹车当减速手段，电池的电就白充了。

三、直通与死区

同一桥臂的 Q1 和 Q2 同时导通，电源正极就经两个管子直接到地，回路里只剩几十毫欧的导通电阻，电流能冲到几十上百安，几微秒内管子就烧，铜箔都可能炸开。更隐蔽的是开关延迟：你让 Q1 关、Q2 开，Q2 已经导通时 Q1 还没关干净，照样直通。72 MHz 的 CPU 一条指令才 14 ns，而 MOSFET 关断要几十到几百 ns，软件里写「先关再开」根本来不及。

死区就是让定时器硬件在互补通道切换时自动插一段「上下管都关」的时间，等一边彻底关断再开另一边，典型几百 ns 到 1 µs。太小防不住直通，太大则吃掉有效占空比：20 kHz 时周期 50 µs，500 ns 只占 1%，影响不大；但占空比只有 2% 时一个周期的高电平才 1 µs，死区就吃掉半个脉冲，低速段明显失真，这也是很多车低速发抖的原因之一。另外互补输出还要把主输出使能（MOE）打开，否则 CH1N 一动不动。

死区时间不是随便填个数就行。以 F103 为例，`BDTR` 的 `DTG[7:0]` 被拆成四段编码：0–127 时死区 = DTG × tDTS；128–191 时 = (64 + DTG[5:0]) × 2tDTS；192–223 时 = (32 + DTG[4:0]) × 8tDTS；224–255 时 = (32 + DTG[4:0]) × 16tDTS。tDTS 是定时器时钟周期，72 MHz 下 13.9 ns，所以最细一档就是 13.9 ns，128 以上才开始大步长，覆盖到微秒量级（见 RM0008 高级控制定时器章）。

软件这边只剩两条防线：结构上不要自己拿两个 GPIO 去点同一桥臂的上下管；真要自己做方向切换，先把占空比降到 0，等一个周期再改方向。

四、PWM 调速的本质

占空比 D 决定平均电压 Vavg = D × Vbus（母线电压）。转速升高时反电动势 E = Ke·ω 顶上来，电流 I = (Vavg − E)/R 随之变小，空载时几乎 Vavg ≈ E，所以转速近似正比于占空比。

平均电压能当真电压用，是因为绕组是大电感，电流不能突变。PWM 开关被 L、R 低通滤成带纹波的直流，纹波 ΔI ≈ V·D(1−D)/(L·f)。频率越高纹波越小、转矩越平顺。

频率怎么选：低于 1 kHz 落在人耳 20 Hz–20 kHz 的听觉范围里，绕组会啸叫，纹波大、低速一顿一顿；高于 20 kHz 听不见了，但每次开关都要交开关损耗（正比于频率），栅极驱动电流也变大，驱动器跟不上。常用 10–20 kHz。

还有个容易被忽略的细节：PWM 关断期间电流靠体二极管续流，二极管压降约 0.7 V，1 A 就是 0.7 W 白烧；不少 H 桥在关断期改让下管导通做同步整流，压降变成 I×Rds(on)，效率差出一大截。

「占空比决定转速」只在电流连续时成立：断续时平均电压还没下来，实际电流却已经掉到 0，转速明显低于线性预期。电感越小、频率越低，断续出现得越早，这也是为什么小电机用低频 PWM 会明显发飘。轻载、低速时最容易碰到这个区，摩擦和齿槽转矩还会把曲线压弯，所以开环调占空比只能大致把车跑起来，最终一定要闭环。

五、电机是车上最大的干扰源

干扰有三个来源：电刷换向火花（宽带噪声，几十 MHz，直接窜进信号线）、绕组电感断电瞬间的 di/dt 尖峰（几十上百伏）、以及电机电流在地线内阻上的压降（电机一转，MCU 的 3.3 V 跟着抖）。

应对分四层：H 桥里必须有续流通路（MOSFET 体二极管或外接肖特基），否则电感电流硬断，尖峰会雪崩击穿管子；电机电源和 MCU 电源分开走线，电机端并 100–1000 µF 电解加 0.1 µF 陶瓷；两个地单点汇合；电机线远离编码器和传感器线，必要时用光耦或数字隔离器把两边地彻底分开。电源线上的差模毛刺靠电感和电容滤，电机线对地的共模噪声靠屏蔽和 Y 电容泄放，两者不是一回事。

最狠的情况是堵转或急换向：母线上会出现负向尖峰，把 3.3 V 稳压器拽下去，MCU 直接复位，表现出来就是车「跑到弯道突然重启」。稳压器前端加 TVS 和足够的输入电容，比事后改代码有用得多。编码器线是弱信号：双绞、远离电机线，必要时串 1 kΩ 电阻加对地小电容做 RC 滤波，别指望软件把毛刺滤干净。

判断方法很直接：一开电机就复位、串口乱码、编码器乱跳，停转就恢复，先查电源和地，别急着怀疑代码。手上没仪器时最快的验证是给电机单独供电，现象消失就锁定是电机这条路径。

六、驱动芯片怎么选

L298N 是双 H 桥，达林顿 BJT 输出，导通压降 2 V 上下，2 A 时几瓦全变成热，效率低；老模块便宜、资料多，只适合练手。TB6612FNG 是 MOSFET H 桥，Rds(on) 约 0.5 Ω，1.2 A 连续、3.2 A 峰值，PWM 频率上限几十到上百 kHz，发热小，智能车上最常见。DRV8871 是单 H 桥，3.6 A 峰值，用 ILIM 电阻设限流，自带过流过热保护，适合单电机大电流。选型只看三件事：持续电流、导通压降（决定发热）、PWM 频率上限；压降大的片子低占空比时几乎调不动电机。

还有两个隐性指标：栅极电荷 Qg 乘以频率就是驱动电流，频率越高驱动器越吃力；芯片内部有没有死区和交叉导通保护也要看，TB6612 这类集成驱动已经替你做掉，用分立 MOS 搭 H 桥才需要自己算。

集成的另一个好处是最小脉宽有保障：你给 1% 占空比，芯片内部的手册指标内也不会退化成直通。分立方案则要自己盯着驱动电阻和栅极波形，示波器上如果看到上升沿拖到微秒级，开关损耗就已经不可接受了。至于 L298N 模块上那块大散热片和 5 V 使能跳帽，本身就是效率低的证据：12 V 电池送到电机端只剩 10 V 左右。

**STM32F103**：电机 PWM 走 TIM1/TIM8，CH1 和 CH1N 是硬件互补对，死区写进 `BDTR` 的 `DTG[7:0]`，由 `HAL_TIMEx_ConfigBreakDeadTime()` 一并配置；`AutomaticOutput` 打开后主输出使能（MOE）由更新事件自动置位。

```c
TIM_OC_InitTypeDef oc = {0};
TIM_BreakDeadTimeConfigTypeDef bd = {0};
htim1.Instance = TIM1;
htim1.Init.Prescaler = 0;                /* 72 MHz 计数 */
htim1.Init.Period = 3599;                /* 72 MHz/3600 = 20 kHz */
HAL_TIM_PWM_Init(&htim1);
oc.OCMode = TIM_OCMODE_PWM1; oc.Pulse = 1800;    /* 50%，CH1 与 CH1N 互补 */
HAL_TIM_PWM_ConfigChannel(&htim1, &oc, TIM_CHANNEL_1);
bd.DeadTime = 36;                        /* 36 × 13.9 ns ≈ 500 ns */
bd.AutomaticOutput = TIM_AUTOMATICOUTPUT_ENABLE;
HAL_TIMEx_ConfigBreakDeadTime(&htim1, &bd);
HAL_TIM_PWM_Start(&htim1, TIM_CHANNEL_1);       /* CH1  */
HAL_TIMEx_PWMN_Start(&htim1, TIM_CHANNEL_1);    /* CH1N */
```

**MSPM0**：互补 PWM 只有 TIMA 支持，TIMG 没有。死区不写寄存器，在 SysConfig 的 Timer 模块里选 Complementary、填 Dead Band 时间，生成到 `ti_msp_dl_config.c` 的初始化里，用户只负责改占空比和启动（见 SLAU846 的 TIMA 一节；具体函数名以 SDK 的 `dl_timera.h` 为准）。

```c
/* SysConfig：TimerA 选 Complementary PWM，Dead Band 填 500 ns */
DL_TimerA_setLoadValue(PWM_0_INST, 3599);        /* 20 kHz */
DL_TimerA_setCaptureCompareValue(PWM_0_INST, 1800, DL_TIMER_CC_0_INDEX);
DL_TimerA_startCounter(PWM_0_INST);
```

差异：STM32 要自己算 PSC/ARR、手填 DTG 并额外启动互补通道；MSPM0 把互补和死区放进 SysConfig 自动生成，但这套互补加死区只有 TIMA 才有。

**选择题**

1. 直道末端要让车快速停住，而不是滑行，H 桥上应该让哪组管子导通？
   - A. Q1 + Q4（左上 + 右下）
   - B. Q2 + Q4（左下 + 右下）
   - C. Q1 + Q2（左侧上下）
   - D. Q3 + Q4（右侧上下）
   - 答案: B
   - 判定: B 对——两个下管同时导通，把电机两端一起短接到地，转子残余动能靠反电动势在绕组里发热消耗，是电动刹车，且制动电流不经过电源。A 是对角导通，等于正转出力，车只会继续往前冲。C 是左半桥上下管一起开，把电源正负极短路。D 是右半桥上下管一起开，同样短路——两者都不是刹车，是炸管子。
   - 踩坑场景: 想在代码里「刹车」，把四个管子全关了当作停住，结果车靠惯性滑出半米撞上赛道边线——滑行没有制动转矩，减速只靠摩擦。更惨的是把刹车写成 Q1+Q2，上电一瞬间「啪」一声，驱动板冒烟。

2. 互补 PWM 里插入死区，最根本的目的是什么？
   - A. 让电机在每个开关周期短暂断电，减少电刷火花
   - B. 给反电动势提供泄放通路，防止母线电压被抬高
   - C. 压低有效占空比，实现低速段的精细调速
   - D. 给正在关断的 MOSFET 留出关断时间，避免同一桥臂上下管短暂同时导通
   - 答案: D
   - 判定: D 对——MOSFET 关断有延迟（栅极放电、米勒平台），软件写「先关再开」的间隔只有几十 ns，硬件死区把两管都关的时间保证在几百 ns 到 1 µs。A 错，电刷火花来自换向器机械换向，死区在驱动器侧，管不到电刷，短暂断电只是副作用。B 错，泄放反电动势靠续流二极管或体二极管，死区不负责这件事。C 错，死区确实吃掉一点占空比、低速时让波形畸变，但那是代价不是目的。
   - 踩坑场景: 想把占空比榨干，把死区设成 0，电机一转起来驱动芯片几分钟就烫手，最后烧掉——直通电流根本不走电机，全在管子上变热。

3. 车一给电机上电，串口就开始乱码、MPU6050 读数乱跳，电机停转后一切正常。最可能的原因？
   - A. PWM 频率设成了 10 kHz，正好落在电机的机械共振点
   - B. 换向火花和电机电流突变通过电源、地线耦合进了 MCU 的供电和信号回路
   - C. 死区太短，H 桥处于直通状态
   - D. 占空比超过 80%，电机反电动势顶穿了驱动芯片
   - 答案: B
   - 判定: B 对——「只在电机转的时候出现、停转就恢复」是传导和辐射干扰的典型特征，火花是宽带噪声，地线压降还会把 MCU 的地抬起来。A 错，机械共振表现为车身抖动或啸叫，不会让串口数据错乱。C 错，直通会烧管子，现象是驱动板过热或保护，不是 MCU 侧数据错。D 错，反电动势顶穿的是驱动管耐压，通常直接烧器件，也不存在「一开就乱、一停就好」的对应关系。
   - 踩坑场景: 换了三块 MPU6050、改了两次 I2C 时序都没用；最后在电机电源并了 470 µF、电机地和 MCU 地单点接、电机线挪开 5 cm，干扰立刻消失。

4. F103 的 TIM1 时钟 72 MHz，`BDTR` 的 DTG 配成 36（落在 0–127 区间），插入的死区时间约为多少？
   - A. 36 ns
   - B. 5 µs
   - C. 0.5 µs
   - D. 72 ns
   - 答案: C
   - 判定: C 对——DTG ≤ 127 时死区 = DTG × tDTS，tDTS = 1/72 MHz ≈ 13.9 ns，36 × 13.9 ≈ 500 ns，正好是典型值。A 错，把 DTG 直接当纳秒数，忘了乘时钟周期。B 错，差一个数量级，通常是把 13.9 ns 记成 139 ns，或者选错了 DTG 的分段（192–223 段是 ×8、224–255 段是 ×16）。D 错，拿 72 这个数字硬凑，72 MHz 的周期是 13.9 ns 不是 72 ns。
   - 踩坑场景: 按「DTG 填几就是几 µs」的直觉填了 1，以为死区 1 µs，实际只有 13.9 ns，等于没加；满载跑一会儿驱动芯片温度明显比预期高。

**术语**

| 术语 | 含义 | 通俗解释 |
|---|---|---|
| 换向器（Commutator） | 有刷电机转子上随角度切换绕组电流方向的机械开关，与电刷配合 | 转子自带的换向开关，每半圈把电流掉个头 |
| H 桥 | 四个开关管组成的桥式电路，能让电机两端电压反向，实现正反转与制动 | 四个闸门摆成 H，电机架在中间那道横杠上 |
| 直通（Shoot-through） | 同一桥臂上下管同时导通，电源经两管直接短路 | 正负极被一根导线连起来，等于把电池短路 |
| 死区（Dead Time） | 互补输出切换时插入的短暂全关时间，防止上下管同时导通 | 换向时留的安全间隙，否则短路 |
| 反电动势（Back-EMF） | 电机转动时绕组切割磁感线产生的电压，方向与供电相反，E = Ke·ω | 电机自己发的电，专门跟电源对着干 |
| 续流二极管 | 为电感电流提供通路的二极管，H 桥里常用 MOSFET 体二极管 | 电感电流的泄洪道，不然压力全憋在管子上 |
