# 第3章 核心控制算法

> 状态: 进行中
> 最后更新: 2026-10-22

## 本章目标

把第2章拿到的三路信息（赛道位置、车速、姿态角）变成电机能执行的指令：先学会从编码器计数算出真实速度、从光电读出差偏方向，再把它们塞进一个能稳、能快、不发散的控制器里。学完应该能说清楚 PID 三个参数各自在补什么、为什么调参要按顺序、以及车为什么会抖。

## 小节

### 3.1 PID 与调参

- 状态: 未开始

**讲解**

一、开环为什么一定会跑偏

开环就是"我认定占空比 40% 对应 2 m/s，于是写死 40%"。这个对应关系只在某一瞬间成立：电池从 8.4 V 掉到 7.2 V，同样 40% 的占空比加在电机上的平均电压就低了，转速跟着低；地面从瓷砖换到地毯，摩擦变大，转速再低一截；车重、坡度、轮胎磨损也都在变。这些变化没有一个是你能提前算出来的，开环的车就是拿一个固定答案去应万变的题。

有人会想：那给电机建个数学模型，反解出"要 2 m/s 该给多少伏"不就行了。问题是电机参数随温度漂、齿轮箱有间隙、轮胎会打滑，模型标定一次管不了三天；而 PID 根本不需要模型，它只看"现在还差多少"。这是它能在智能车上活几十年的原因——它把"预测"换成了"纠正"。

闭环的思路就是：不去猜，每 10 ms 量一次实际速度，和目标相减得到误差，按误差去出力。误差是唯一输入，扰动一出现误差就变大，出力自动加大，把速度拽回来。闭环不消除扰动本身，它让扰动的影响被反馈吃掉。代价有三个：要多一个能测速度的传感器，算力要跟得上采样周期，参数调不好会比开环更糟——一辆在原地震荡的车，还不如一辆匀速慢跑的车。

PID 之所以长成这个样子，是因为它面对的对象就长这样：被控量（轮速）能测，但测出来的数带噪声；执行器（PWM 占空比）有死区、有上限；从改占空比到轮速真的变，中间隔着电机电感、齿轮间隙和整车的质量，天然带延迟。对"有惯性、有延迟、模型还不准"的对象，算误差、按误差修正，比反解模型靠谱得多，前提是你得接受它只能"纠偏"、不能"预知"。

二、P：力度正比于误差

误差 e = 目标 − 实测，P 项的输出是 Kp × e，Kp 的含义是"每 1 个单位误差给多少出力"，功能上相当于一根弹簧：拉得越开，回弹越猛。Kp 大，误差刚冒头就猛给油，响应快；但车有质量、有传动间隙，出力到得太猛会冲过目标，然后反向修，来回震荡。Kp 小，出力温柔，可弯道来了它反应不过来，速度一直落后。Kp 大到过头时还有个好认的症状：车停着不动却发出高频啸叫、轮子原地抖，那是出力在目标附近来回横跳。判断 Kp 够不够，给一个阶跃目标看它几次回到目标附近：两次以内有点过冲算好，来回四五次就是大了。实际调的时候别一次跳一大档，从 0 起步、每次乘 1.5 到 2 倍往上试，看到车在目标附近持续小幅摆动，就退回上一档。

纯 P 一定有稳态误差，这不是参数没调好，是结构决定的：电机要维持转速就必须持续有输出，而 P 的输出只来自误差，稳态时输出非零就意味着误差非零。想让车既转得稳、误差又归零，只能靠 I 项把"历史上一直欠着的量"补上。

还有一个绕不开的坑是死区：占空比低于 8% 左右电机根本不转，P 算出来的小出力被白白吃掉，误差就卡在那里不再缩小。所以输出要加一个最小占空比（死区补偿），否则 Kp 怎么加，低速段都会留一段永远追不上的盲区。反过来，当 Kp 大到占空比已经长期顶在 100%、车还在加速时，再往上加只是让轮胎打滑，这时候该怀疑的是电源和机械，不是参数。

三、I：把欠的账累加起来

I 项把每次误差乘上采样周期再累加，输出加 Ki × sum。只要还剩一点点静差，sum 就一直朝一个方向涨，直到误差被压到 0 才停手——这正是消静差需要的。它相当于在问"过去这段时间我总共欠了多少力"，欠得越久补得越狠，所以误差再小也迟早会被推平。工程上也常把 Ki 写成 Kp / Ti，Ti 叫积分时间，物理意义是"把当前这份 P 出力攒满需要多长时间"：Ti 短，补得急，消差快但容易震荡；Ti 长，补得慢，稳但拖。

代价有两个：一是积分自带惯性，误差早就反向了它还在往上加，响应变慢、容易震荡；二是积分饱和（windup）：车顶住墙、起步堵转、或者输出被限幅时，误差长时间不消，sum 会涨到一个远超电机能力的巨大数值，等障碍消失，这个数还得慢慢"退"回来，表现就是车猛地冲出去、半天收不住。

三条常用对策：输出限幅，占空比封顶，先让 sum 涨不上去；积分分离，误差绝对值大于阈值时干脆不积分，先靠 P 把误差拉进小范围；反向积分，输出已经饱和时，只允许积分往回调的方向走。

四、D：看趋势，提前松脚

D 项看的是误差变化的速度：(e − e_last) / dt。车快到目标时 e 在快速变小，D 项为负，等于提前松油门，把冲过头的趋势刹住，效果相当于给系统加阻尼，超调随之变小。P 和 D 分工不同：P 管"现在差多少"，D 管"正在以多快的速度靠近"。光有 P 像踩着油门撞线，加了 D 才是提前收油滑过去。换个角度看，D 项是在做外推：照当前的变化速度，下一个采样周期误差会变成多少，提前按那个值出力，所以它天生是"刹车"而不是"油门"。

它的代价很直接：差分把噪声一起放大了。编码器一个计数抖动、光电传感器一次误判，e 就会跳一下，被很小的 dt 一除就成了很大的数，D 项瞬间给出一下猛打，车开始抖、电机开始嗡。另一个隐雷是目标值突变：手动把目标从 0 跳到 100 的那一拍，误差瞬间跳 100，D 项会给出一个巨大的冲击，所以工程上常让 D 只对测量值求差分，而不对误差求，专门绕开这种跳变。

所以传感器毛刺多的时候宁可不用 D；真要用，就先给测量值加低通滤波，或者做"不完全微分"，让 D 项自己也滤一道再输出。智能车队那句"先 P 后 I，D 慎用"就是从这儿来的，不是 D 没用，是它对测量质量太挑。判断标准很土：不加 D 过冲明显、一加 D 就抖，先修测量（滤波、换编码器分度）；只有过冲明显而且测量干净，D 才值得留。

五、位置式与增量式

位置式直接算出输出的绝对值：u = Kp·e + Ki·Σe + Kd·(e − e_last)，每个周期把占空比设成 u。它要维护历史累加，积分饱和最严重，重启或切模式时输出会突然跳变。

增量式算的是"这次比上次多给多少"：Δu = Kp(e − e1) + Ki·e + Kd(e − 2e1 + e2)，然后 u += Δu。这个式子不是另起一套，就是把位置式的第 k 拍减去第 k−1 拍：两次相减时 Σe 消掉了，剩下的正好是当前误差和两个误差的差。增量式天然抗饱和，因为积分项就是当前这个 e，不会攒出一个巨大的历史值；输出本来就是累加的，正好对上 PWM 比较值一个周期改一次；手自动切换时也没有跳变。所以速度环、电机 PWM 这种"输出要一点一点推上去"的场合多用增量式；方向环那种"直接算出该打多少度"的场合，位置式读起来更直观。

它的弱点是一次采样出错会永久留在累加结果里，不像位置式那样有个绝对值能把它拉回来。离散化的写法说到底就两句：积分变成累加 sum += err，微分变成差分 (err − err_last)，剩下的都是系数怎么折。把同类项合并，增量式还能写成 Δu = A·e − B·e1 + C·e2，A、B、C 由三个参数直接算出来，现场只调这三个数也很常见。

六、采样周期、调参顺序与串级

代码里的 Ki、Kd 是按"每次中断算一次"生效的，而手册和直觉里的参数是按秒的。定时器从 10 ms 改成 5 ms，同样一行 Ki × e 每秒执行的次数翻倍，等效积分强度直接翻倍；只改定时器不改参数，等于偷偷把 PID 重调了一遍。所以改任何参数之前，先确认中断周期是多少，这是最容易白调半天的地方。

周期本身也在影响稳定性。采样太慢，两拍之间车已经跑出去一段，反馈回来的是旧信息，等效于给系统加了延迟；延迟一大，原本调好的 Kp 也会把车推成震荡。采样太快，D 项被噪声占满，算力也白花。速度环一般取 5–10 ms，也就是 100–200 Hz。

调参按固定顺序走：先把 I、D 清零，Kp 一点点加到车开始等幅震荡（临界震荡），然后退到一半；再加 Ki，把剩下的静差消掉；最后加一点 Kd 压超调，一抖就减。

方向不是一个个环独立调的，而是串级：外环拿偏差算出"我该用多快的速度过这个弯"，把这个值当内环的目标，内环只管把速度跟上。必须先调内环再调外环——内环跟不准，外环给出的目标值再对也没意义，而且外环会一直以为是自己没调好。内环响应要比外环快三到五倍，两级才不会互相打架。举个具体节奏：内环 200 Hz（5 ms 一拍）跟速度，外环 50 Hz（20 ms 一拍）算方向，外环每算一次，内环已经跟了四拍。

**STM32F103**：TIM3 每 10 ms 进一次更新中断，中断里把整套算法算完，直接把比较值写进 TIM1 的 CCR。这里给的是位置式，注意那行反向积分——输出已经到 0 还在往下压时，把这一拍的 e 从 sum 里退回去。F103 是 Cortex-M3，没有 FPU，float 的乘加全走软件库，100 Hz 的中断里跑得动，周期再短就得考虑改成整数运算。

```c
/* TIM3 更新中断 10 ms：72MHz / 7200 / 100 = 100 Hz；Ki、Kd 已折进 dt */
float Kp = 3.0f, Ki = 0.6f, Kd = 0.0f;

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
    static float sum = 0, last = 0;
    float e = target - actual;                /* actual 由编码器算出 */
    sum += e;
    float u = Kp * e + Ki * sum + Kd * (e - last);
    last = e;
    if (u > 1000) u = 1000;                   /* 输出限幅：占空比 0~1000 */
    if (u < 0) { u = 0; sum -= e; }           /* 反向积分：饱和了别再攒 */
    __HAL_TIM_SET_COMPARE(&htim1, TIM_CHANNEL_1, (uint32_t)u);
}
```

**MSPM0**：在 SysConfig 里把 TIMA0 配成 10 ms 周期并打开零事件中断，算法一个字不用改，只有写比较值的那句换成 DriverLib。一外设一个中断向量，所以函数名就是 `TIMA0_IRQHandler`，索引常量是 `DL_TIMER_CC_0_INDEX`（具体函数名以 SDK 的 `dl_timera.h` 为准，我按这个记）。

```c
void TIMA0_IRQHandler(void) {
    static float sum = 0, last = 0;
    float e = target - actual;
    sum += e;
    float u = Kp * e + Ki * sum + Kd * (e - last);
    last = e;
    if (u > 1000) u = 1000;
    if (u < 0) { u = 0; sum -= e; }
    DL_TimerA_setCaptureCompareValue(TIMA0, (uint32_t)u, DL_TIMER_CC_0_INDEX);
    DL_TimerA_clearInterruptStatus(TIMA0, DL_TIMERA_INTERRUPT_ZERO_EVENT);
}
```

差异：STM32 侧周期靠 PSC/ARR 手算、中断入口在回调里自己分派，MSPM0 侧周期和中断都在 SysConfig 里定、一外设一向量；浮点能力上两块板其实都没单精度 FPU——F103 是 Cortex-M3、MSPM0 是 Cortex-M0+，都是整数核，float 全走软件库，MSPM0G 系列多出来的 MATHACL 是三角函数、除法这类数学加速器，不是 FPU，所以两边真正该省的都是"别在 1 ms 中断里做浮点"，要更快就改整数增量式。

**选择题**

1. 一台电机用纯 P 控制速度，Kp 从 1 加到 20，静差从 1.2 m/s 缩到 0.05 m/s，但始终不为零。最准确的解释是？
   - A. Kp 还不够大，继续加大一定会归零
   - B. 电机维持转速必须持续有出力，而 P 的出力只来自误差，误差为 0 就没有出力，稳态必然留一点误差
   - C. 是编码器分辨率不够，测不出 0.05 m/s
   - D. 是缺了 D 项，加上 D 就能消掉
   - 答案: B
   - 判定: A 错在 Kp 要趋于无穷误差才趋于零，实际会在某个 Kp 上先震荡，根本过不去。B 对，这是结构性的稳态误差：稳态输出 u = Kp × e，u 必须非零，e 就必然非零，加大 Kp 只是把同一份出力摊到更小的误差上，不是消除它。C 错在分辨率影响的是测量精度，换个高分辨率编码器，静差照样在。D 错在 D 项只看误差的变化率，稳态时误差不变、变化率为 0，D 项贡献正好是 0。静差要清零必须靠 I 项。
   - 踩坑场景: 直道上车永远比目标慢 0.05 m/s，你以为调参不到位，把 Kp 从 20 一路加到 60，车开始一顿一顿地窜、轮胎打滑，静差是没了但换成了震荡。正确动作是加 Ki，重新从小往大调。

2. 车迎面顶住墙，轮子空转三秒，你把车拿开，车"嗖"地窜出去撞了另一面墙。最可能的原因是？
   - A. Kp 太大，拿开瞬间误差突然变大
   - B. 堵转三秒里误差一直不消，积分项 sum 涨到远超电机能力的值，障碍消失后这个数要很久才退回来，输出长时间顶着饱和
   - C. 电池电压堵转时被拉低，拿开后电压反弹
   - D. 编码器堵转时没有脉冲，速度被算成了一个很大的值
   - 答案: B
   - 判定: A 错在 P 项是瞬时量，误差一缩小它立刻缩小，且拿开瞬间的误差量级撑不住"持续几秒满速"的表现。B 对，这就是积分饱和：被卡住的每一拍都在 sum += e，三秒就是三十拍大误差全部攒下。C 是真实存在的次要效应，但电压反弹最多让加速略快，解释不了冲出去后还收不住。D 错，堵转时编码器无脉冲，算出来是 0，误差最大但方向是对的（该加速），问题出在把这三秒都当成"欠账"累加了。
   - 踩坑场景: 社团调试，车顶住桌腿两秒，你手一松它直接飞到地上，重烧程序照样复现，因为每次堵转都在往 sum 里攒。加上积分分离（|e| 超过阈值就不积分）后现象消失，你才第一次直观看到"历史"能有多大。

3. 只用 P 已经把直道调好，加上 Kd = 0.5 后车在直道上高频抖动，电机发出嗡嗡声，速度读数在目标附近小幅跳。最该先怀疑的是？
   - A. Kp 太大
   - B. D 项把速度测量的毛刺放大了：差分除以很小的 dt，一个计数的抖动就变成很大的瞬时输出
   - C. 积分饱和
   - D. PWM 频率太低，电机本来就会叫
   - 答案: B
   - 判定: A 错，加 D 前后 Kp 没动过，病因是新加的那一项，先别急着改 Kp。B 对，D 项 (e − e_last)/dt 在 10 ms 的 dt 下，1 个计数差被放大 100 倍，编码器或光电的毛刺直接变成一顿猛打。C 错，积分饱和的表现是持续单向超调、冲过头收不住，不是高频抖动。D 错，PWM 频率低确实有固定音调的啸叫，但它不会让速度读数跟着跳，也不会只在加 D 之后出现。
   - 踩坑场景: 你在示波器上看不到问题，因为抖动是软件里算出来的；把 D 降到 0.1 会好一点但没根治，直到给测速加了一阶低通滤波、并把 D 改成对测量值求差分（不对误差求），抖动才真正消失。

4. 增量式 PID：Δu = Kp(e − e1) + Ki·e + Kd(e − 2e1 + e2)，取 Kp = 4、Ki = 0.2、Kd = 0.5，三个系数都已按"每次采样"折算好、不再除 dt。本次 e = 30、上次 e1 = 20、上上次 e2 = 10。本次 Δu 是多少？
   - A. 46
   - B. 51
   - C. 42
   - D. 40
   - 答案: A
   - 判定: P 项 4 × (30 − 20) = 40；I 项 0.2 × 30 = 6；D 项二阶差分 30 − 40 + 10 = 0，贡献 0；合计 40 + 6 + 0 = 46。B 是把 D 项错用一阶差分：40 + 6 + 0.5 × 10 = 51。C 是把 I 项错乘成增量：40 + 0.2 × 10 = 42。D 只算了 P 项，漏了 I 和 D。这题 D 项恰好为 0，是因为误差在等速下降（二阶差分为零），不是公式抄错——这一点正好可以用来校验自己的公式。
   - 踩坑场景: 你拿手算表推调参过程，D 项一直按一阶差分算，纸上每次都比实际多算一截，上板后车总是先冲过去再被拉回来，你以为是 Kp 大了，把 Kp 一降再降，结果车变得又慢又软——公式抄错，参数怎么调都是错的。

**术语**

| 术语 | 含义 | 通俗解释 |
|---|---|---|
| 开环 / 闭环 | 开环按预设输出、不检测结果；闭环测量实际值，与目标比较后按误差修正 | 蒙着眼按秒表走路 vs 睁眼看路走 |
| 稳态误差 | 系统进入稳态后，输出与目标之间残余的差值 | 永远差一口气到不了终点 |
| 积分饱和（windup） | 误差长期存在使积分项累加到远超执行机构能力的程度，退出饱和滞后 | 攒了一笔还不上的账，工资到账先还债 |
| 位置式 PID | 直接计算控制量绝对值 u 的形式 | 每拍报"现在该给多少" |
| 增量式 PID | 计算控制量增量 Δu，u 由累加得到的形式 | 每拍报"比上次多加多少" |
| 串级控制 | 两级闭环，外环的输出作为内环的设定值 | 领队定配速，队员照配速跑 |
