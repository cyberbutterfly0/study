# 第4章 配置体系

## 一、三层叠加

```text
application.yml               公共配置（服务名、激活哪个 profile、Nacos 地址）
  ↓ 被覆盖
application-{profile}.yml     环境专属（端口、数据源、Redis、日志级别）
  ↓ 再覆盖
Nacos 里的 dataId 配置         zhiwei-gateway-dev.yaml 等，运行时从配置中心拉
```

## 二、四个关键机制

### 1. profile 切换

`application.yml` 里的 `spring.profiles.active: dev` 决定加载哪个环境文件。

IDEA 里可以不加环境变量，因为 `application.yml` 里已经写了默认值；但**团队约定是显式在 Run Configuration 里加** `spring.profiles.active=dev`，避免不同人本地配置不一致。

### 2. Nacos 配置导入（2025.x 的写法）

Spring Cloud 2025.x 废除了 `bootstrap.yml`，改成在 `application.yml` 里显式写：

```yaml
spring:
  config:
    import: nacos:zhiwei-gateway-${spring.profiles.active}.yaml
```

以前靠 `bootstrap.yml` 自动去 Nacos 拉配置，现在必须手写 import，不写就不会拉。

### 3. 缺配置不致命

Nacos 里没有对应的 dataId 时**不会启动失败**，只打 WARN：

```text
NacosConfigDataLoader - config[dataId=...] is empty
```

所以首次启动前不用先去 Nacos 建配置文件，但业务参数会缺失。

### 4. 环境变量带默认值

```yaml
url: ${DB_HOST:127.0.0.1}
```

冒号前是环境变量名，后面是默认值——没设这个变量时用 `127.0.0.1`。

## 三、profile 对应的文件

| 文件 | 用途 |
|---|---|
| `application.yml` | 公共配置 + 激活 dev |
| `application-dev.yml` | 本地开发，连 PolarDB |
| `application-test.yml` | 测试环境 |
| `application-prod.yml` | 生产环境，变量无默认值 |

## 四、日志配置

`logback-spring.xml` 在 infra-server 和 system-server 的 `src/main/resources` 下，走 Spring Boot 的 logback 集成，按 profile 切日志级别和输出位置。
