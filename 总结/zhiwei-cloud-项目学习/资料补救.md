## 小节
### 1. 容器（Docker）到底是什么

**你当时看到**：`docker run -d --name zhiwei-mysql ... mysql:8.4` 一条命令，MySQL 就有了。

**为什么是这样**：容器 = 一个打包好的迷你系统，里面已经装好了 MySQL。不是你自己download安装配环境，而是拿一个成品直接跑。
- **镜像（image）** = 出厂模板，`mysql:8.4` 就是「MySQL 8.4 的模板」
- **容器（container）** = 照着模板跑起来的那一份

**一句话记住**：镜像是模板，容器是照着模板跑起来的那一台。

---

### 2. 为什么 Nacos 还要单独一个库

**你当时看到**：建了 `zhiwei` 库之外，还要 `CREATE DATABASE nacos_dev`。

**为什么是这样**：Nacos 是注册中心，它自己也有东西要存——哪些服务注册了、配置项是什么、集群节点有哪些。这些存在它自己的表里，所以需要一个独立的库。

**一句话记住**：业务数据进 `zhiwei`，Nacos 自己的台账进 `nacos_dev`。

---

### 3. 容器里的 `127.0.0.1` 不是你的电脑

**你当时看到**：Nacos 配 `MYSQL_SERVICE_HOST=127.0.0.1` 一直 `Connection refused`，改成 `host.docker.internal` 就好了。

**为什么是这样**：每个容器都有自己的「本机」。Nacos 在容器里说「127.0.0.1」，指的是**容器自己**，不是你的 Windows。你的 MySQL 跑在 Windows 上，容器看不到它。
`host.docker.internal` 是 Docker 提供的一个固定名字，专门用来在容器里指「宿主机」。

**一句话记住**：容器里的 localhost 是容器自己的家，不是你电脑的家。

---

### 4. 环境变量为什么能盖住 yml

**你当时看到**：yml 里写死了阿里云地址，只设了 `$env:SPRING_DATASOURCE_URL` 就改成连本地了。

**为什么是这样**：Spring 取配置有优先级，**环境变量 > 配置文件**。所以同一个名字，环境变量有值就用环境变量，没有才去 yml 里找。

**一句话记住**：环境变量优先级最高，临时改配置不用动文件。

---

### 5. 启动成功 ≠ 能连数据库

**你当时看到**：system-server 明明 `Started SystemServerApplication`，一登录就 500。

**为什么是这样**：Hikari 连接池是**懒加载**——启动时只把池子建好，不真的去连。第一次有查询（登录查 `sys_user`）才真连，连不上就 500。
所以「启动成功」只证明代码没问题，不证明数据库通。

**一句话记住**：启动成功只说明程序跑起来了，第一次查库才知道数据库通不通。

---

### 6. 19 位 ID 为什么变成 `...5000`

**你当时看到**：`2124463696932474881` 拿去 `update`，报 404。

**为什么是这样**：JS 的数字只能精确到 `2^53`（约 9 千兆），雪花 ID 是 2×10^18，超了就被截断成 `2124463696932475000`。
所以前端、脚本、curl 里，19 位 ID 必须当**字符串**处理。

**一句话记住**：19 位 ID 当字符串传，别当数字。

---

### 7. 权限码怎么进 token

**你当时看到**：`sys_menu` 插了 5 个按钮，接口还是 403；补了 `sys_role_menu` 才好。

**为什么是这样**：登录时系统按这条链路查：**人 → 角色 → 角色挂的菜单 → 菜单上的权限码**，把这些权限码塞进 JWT。
所以只插菜单不绑角色，等于「有这个权限，但没人有」。

**一句话记住**：权限码是「角色 → 菜单」查出来塞进 token 的，不是写在代码里的。

---

### 8. 为什么 `count(*)` 是 1，`page` 是 0

**你当时看到**：库里明明有 1 行，接口返回 `total: 0`。

**为什么是这样**：`count(*)` 数的是**物理行**；`page` 走 MyBatis-Plus，`@TableLogic` 会自动加 `deleted = 0` 条件。
那条记录 `deleted` 等于自己的 id，是**逻辑删除态**——还在表里，但所有查询都跳过它。

**一句话记住**：逻辑删除 = 记录还在，但查询自动跳过。

---

### 9. `python3` 为什么是假的

**你当时看到**：门禁 7 项全 FAIL，明明代码没问题。

**为什么是这样**：Windows 的 `C:\Users\...\WindowsApps\python3.exe` 是微软商店的**占位程序**，执行没有任何输出。真的命令叫 `python`。
项目脚本写的是 `PY=${PYTHON:-python3}`，没设 `PYTHON` 就拿到假的那个。

**一句话记住**：Windows 上 `python3` 可能是空壳，用 `python`。

---

### 10. IDEA 红叉，命令行却能编译

**你当时看到**：Services 面板 4 个应用全红，`mvn compile` 却 exit 0。

**为什么是这样**：IDEA 用自己维护的模块索引（`.idea/` 里的东西）判断依赖，索引坏了就红；命令行走 Maven，完全不经过 IDEA。
所以红叉多半是 IDE 的问题，不是代码的问题。

**一句话记住**：IDEA 红叉先拿命令行验一遍，别急着改代码。
