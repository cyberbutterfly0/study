# 第2章 启动流程

## 一、前置检查

```powershell
java -version        # 要 JDK 27（不是 17）
mvn -v               # 要 Maven 3.9+
docker --version     # Docker Desktop 已启动
```

### 先有 `.env`

2026-11-03 的 `0d75bc6` 把 `.env` 移出版本控制，仓库里只剩 `.env.example`。新 clone 下来第一件事：

```powershell
cd E:\study\zhiwei-cloud
Copy-Item .env.example .env
# 然后编辑 .env，把 DB_HOST / DB_USER / DB_PASS 等换成自己的真实值
```

项目里**没有 dotenv 依赖**，`.env` 不会被 Spring 自动读。它实际的作用：

- 给 `docker compose` 读 `MYSQL_SERVICE_*` 等变量（compose 会自动读同目录 `.env`）
- 给 test / prod profile 提供 `${DB_HOST}` 这类占位符的值
- **dev profile 用不到**：`application-dev.yml` 里数据源仍是硬编码 PolarDB 地址 + 明文密码（注释写着“临时硬编码”），所以本地跑 dev 不配 `.env` 也能连上


## 二、第一步：起中间件

```powershell
cd E:\study\zhiwei-cloud
docker compose up -d
docker compose ps
```

`docker-compose.yml` 里只有两个服务：

- `zhiwei-redis` → `redis:7.4-alpine`，映射 6379
- `zhiwei-nacos` → `nacos/nacos-server:v3.3.0-RC`，映射 8848（Server OpenAPI）、9848（客户端 gRPC）、18080（控制台，容器内 8080）

**MySQL 不在 compose 里**，Nacos 和业务都连外部阿里云 PolarDB（见第 3 章）。Nacos 的连接参数从环境变量读，没设置时回退到本机 `127.0.0.1:3306` / `root/root`。

**Nacos 3.x 和 2.x 的差别**（起容器前容易懵）：

- 控制台从 `8848/nacos` 拆成独立端口 `8080`，本机映射为 **http://localhost:18080/**（不带 `/nacos` 路径）
- 8848 不再是管理界面，只提供 OpenAPI
- 3.3 默认开启客户端鉴权，本项目 compose 里显式 `NACOS_AUTH_ENABLE=false` 关掉——否则 Java 侧只写了 `server-addr`、没配账号密码，注册服务会报 `NacosException: Code: 401, Message: User not found!`
- `NACOS_AUTH_TOKEN` 等在 3.3 是启动必填项，为空容器直接 exit 255

判断起好没有：`docker compose logs -f nacos`，看到 `Nacos started successfully` 即可。

Nacos 里自己的库是 `nacos_ming`（不是业务库 `test_ming_study`），建表脚本 `sql/nacos-mysql-schema.sql` 已是 3.x 版（16 张表）。

## 三、第二步：构建

```powershell
cd E:\study\zhiwei-cloud
mvn clean install -DskipTests
```

首次要下几百 MB 依赖，慢是正常的。`target` 目录出现即成功。

## 四、第三步：启动服务

**顺序**：system-server → infra-server → gateway（gateway 最后，它只负责转发）。

### 方式 A（推荐）：IDEA 里跑主类

- `cloud.zhiwei.system.SystemServerApplication`
- `cloud.zhiwei.infra.InfraServerApplication`
- `cloud.zhiwei.gateway.GatewayApplication`

每个都要在 Run Configuration 的 Environment variables 里加 `spring.profiles.active=dev`。

dev profile 的数据源是写死的 PolarDB 地址，**不需要**再配 `.env` 里的 `DB_*`；等切到 test/prod 才需要。

### 方式 B：命令行

**坑**：各 pom 没声明 `spring-boot-maven-plugin`，所以 `mvn spring-boot:run` 会报 `No plugin found for prefix 'spring-boot'`。要用全限定坐标：

```powershell
cd zhiwei-module-system\zhiwei-module-system-server
mvn org.springframework.boot:spring-boot-maven-plugin:4.1.2:run
```

## 五、第四步：验证

```powershell
# 系统服务
curl http://localhost:48081/api/system/health
# → {"httpCode":200,"code":0,"data":"system-server is running",...}

# 基础设施服务
curl http://localhost:48082/api/infra/health
# → infra-server is running

# Feign 跨服务调用（infra 调 system）
curl http://localhost:48082/api/infra/call-system

# 走网关（发现路由自动转发）
curl http://localhost:48080/zhiwei-system-server/api/system/health
```

四个都通 = 注册、路由、服务间调用、统一返回全都正常。

**注意 401 是正常的**：当前代码里没有自定义 `SecurityConfig`，Spring Security 默认拦截所有未认证请求，所以三个健康接口在未登录时都会返回 **HTTP 401**（浏览器里会跳 `/login` 登录页）。

- 401 = 服务活着：Tomcat 已在监听、Spring 已启动，不是启动失败
- 想拿到 JSON 结果：用默认账号 `user` + 控制台里 `Using generated security password` 打印的密码登录一次
- 只要三个端口都 `LISTENING`、三个地址都返回 401，就说明启动成功

**实测记录（2026-10-28）**：

```text
48080 LISTENING  48081 LISTENING  48082 LISTENING
http://localhost:48081/api/system/health  -> HTTP 401
http://localhost:48082/api/infra/health    -> HTTP 401
http://localhost:48080/zhiwei-system-server/api/system/health -> HTTP 401
```

启动日志开头的 `sun.misc.Unsafe`、`final field mutation` WARNING 是 JDK 27 对 Nacos client / Jackson 的弃用提示，不是错误，可以忽略。
