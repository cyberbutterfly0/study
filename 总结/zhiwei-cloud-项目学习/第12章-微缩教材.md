## 小节
### 1.1 【工具】Spring 是什么

**一句话**：Spring（应用框架）是 Java（编程语言）的「对象大管家 + Web（网页应用）工具箱」。

**它替你干了什么**：创建对象、把对象互相塞好（依赖注入）、接 HTTP（超文本传输协议）请求、管事务、做权限检查。你没写的那些 `new`，它在背后替你做了。

**人话比喻**：你开一家店，Spring（应用框架）是「店长 + 后勤」。你只管业务（接单、算账），缺人手、收货、收银台它都安排好。

**项目里在哪**：`zhiwei-framework/` 下每个 starter（启动组件）都是项目自己封装的 Spring（应用框架）组件（web、mybatis、security、redis、biz-tenant）。

**记住**：Spring（应用框架）= 管对象、管请求的工具箱。

**关联 / 参考**：→ 第 1.2 节「Spring Boot（快速启动框架）」、第 3.1 节「IoC（控制反转）/ DI（依赖注入）」；[Spring（应用框架）IoC（控制反转）与 DI（依赖注入）通俗讲解（阿里云开发者社区）](https://developer.aliyun.com/article/929449)

### 1.2 【工具】Spring Boot 是什么

**一句话**：Spring Boot（快速启动框架）让 Spring（应用框架）「开箱即用」。

**它替你干了什么**：以前用 Spring（应用框架）要写一堆 XML（可扩展标记语言）配置，Spring Boot（快速启动框架）改成「加个依赖、写几行 `yml` 配置就能跑」，还自带内嵌 Tomcat（网页服务器）。

**人话比喻**：Spring（应用框架）是零件包，Spring Boot（快速启动框架）是「已经按说明书拼好的套装」，插电就用。

**项目里在哪**：每个 `*-server` 模块的启动类 `XxxApplication`，`mvn spring-boot:run` 跑的就是它。

**记住**：Spring Boot（快速启动框架）= 自动配好的 Spring（应用框架）。

**关联 / 参考**：→ 第 2 章「启动流程」、第 3.5 节「自动配置」

---

### 1.3 【工具】Spring Cloud 是什么

**一句话**：Spring Cloud（微服务协作框架）是给「一堆 Spring Boot（快速启动框架）服务」配的协作套装。

**它替你干了什么**：服务怎么互相找到（Nacos，服务注册与配置中心）、请求怎么统一入口（Gateway，网关）、服务之间怎么调用（Feign，服务调用组件）、多个实例怎么分流量（LoadBalancer，负载均衡器）。

**人话比喻**：Spring Boot（快速启动框架）是一家家分店，Spring Cloud（微服务协作框架）是「总部的调度系统」——分店登记、客人进门先到总台、总台按区域指路。

**项目里在哪**：`zhiwei-gateway`（总台）+ 各服务的 `spring-cloud-starter-alibaba-nacos-discovery` 依赖。

**记住**：Spring Cloud（微服务协作框架）= 服务之间的「调度系统」。

**关联 / 参考**：→ 第 6 章「网关与 Feign（服务调用组件）」、第 4.1–4.3 节

### 1.4 【工具】MyBatis-Plus 是什么

**一句话**：MyBatis-Plus（数据库操作增强框架）帮你省掉 90% 的增删改查 SQL（结构化查询语言）。

**它替你干了什么**：继承 `BaseMapper<T>` 就白得 `insert / selectById / updateById / deleteById / selectPage`；`@TableLogic` 自动拼逻辑删除条件；`LambdaQueryWrapper` 用方法引用写条件，字段写错编译期就报错。

**人话比喻**：以前你要手写「去仓库几号货架拿什么」，现在你说「拿 id=1 的会员」，它自己去翻译成 SQL（结构化查询语言）。

**项目里在哪**：`MemberInfoMapper extends ZhiWeiBaseMapper<MemberInfo>`，`MemberInfoServiceImpl` 里的 `selectPage`、`logicDeleteById`。

**记住**：MyBatis-Plus（数据库操作增强框架）= 不用写 SQL（结构化查询语言）的数据库操作层。

**关联 / 参考**：→ 第 11 章第 5 批 Service（业务层）、第 5.1–5.4 节；[MyBatis-Plus（数据库操作增强框架）官方快速开始](https://baomidou.com/getting-started/)、[MyBatis（数据库操作框架）与 MyBatis-Plus（数据库操作增强框架）区别](https://developer.aliyun.com/article/1677767)

### 1.5 【工具】Maven 是什么

**一句话**：Maven（构建与依赖管理工具）是 Java（编程语言）的「构建 + 依赖管理」工具。

**它替你干了什么**：
- 依赖：你在 `pom.xml` 写「我要 mybatis-plus 3.5.18」，它去仓库下载 jar（程序归档包），连带把 mybatis-plus 依赖的别的 jar（程序归档包）也下下来
- 构建：`compile` 编译、`package` 打包、`install` 装进本地仓库
- 多模块：一个根 `pom.xml` 管 10 个子模块，能一起编

**人话比喻**：Maven（构建与依赖管理工具）是「采购 + 装配车间」。你报清单（`pom.xml`），它去买料（下 jar，即程序归档包）、按图纸组装（编译打包）、把成品放进仓库（`install`）。

**项目里在哪**：根 `pom.xml` + 每个模块的 `pom.xml`；本地仓库在 `E:\study\m2repo`（不是默认的 `~/.m2/repository`）。

**记住**：Maven（构建与依赖管理工具）= 报清单、买料、组装。

**关联 / 参考**：→ 第 2 章「`mvn clean install` 为什么必须先跑」、第 7 章坑 #27、第 6.1–6.5 节

### 1.6 【工具】Docker 是什么

**一句话**：Docker（容器工具）把「程序 + 它要的环境」打包成一个盒子，到哪都能跑。

**它替你干了什么**：你本机不用装 MySQL（关系型数据库）、不用装 Nacos（服务注册与配置中心），拉一个镜像跑起来就行；团队里所有人的环境一模一样。

**人话比喻**：
- **镜像（image）** = 出厂模板 / 菜谱加食材包
- **容器（container）** = 照着模板跑起来的那一份 / 按菜谱炒出来的那盘菜
- **仓库（registry）** = 模板商店（Docker Hub，镜像仓库网站）

**项目里在哪**：`docker-compose.yml` 一次起 Redis（内存数据库）+ Nacos（服务注册与配置中心）；你手动 `docker run` 起的 `zhiwei-mysql`。

**记住**：镜像是模板，容器是跑起来的那一份。

**关联 / 参考**：→ `资料补救` 第 1 节、第 3 节，第 8.1 节「docker-compose（容器编排配置）」；[Docker（容器工具）基本介绍（阿里云）](https://developer.aliyun.com/article/904506)、[镜像与容器：菜谱与菜](https://bbs.huaweicloud.com/blogs/532970)

### 1.7 【工具】Nacos 是什么

**一句话**：Nacos（服务注册与配置中心）是服务的「通讯录 + 公告板」。

**它替你干了什么**：
- 注册中心：每个服务启动后去登记「我叫 zhiwei-member-server，我在 10.150.222.232:48083」
- 配置中心：把 `yml` 配置放它那，改完不用重启（`spring.config.import: optional:nacos:...`）
- 网关按名字找到服务（`lb://zhiwei-member-server`），靠的就是它

**人话比喻**：Nacos（服务注册与配置中心）是公司前台。新员工来了先到前台登记工位（注册），找人先问前台（发现），公司通知贴在前台公告板（配置）。

**项目里在哪**：`docker-compose.yml` 的 nacos 容器；每个服务 `application.yml` 里的 `spring.cloud.nacos.discovery`。

**记住**：Nacos（服务注册与配置中心）= 服务通讯录 + 配置公告板。

**关联 / 参考**：→ 第 6 章、第 3.6 节「`spring.config.import`」、第 4.1–4.2 节

### 1.8 【工具】Redis 是什么

**一句话**：Redis（内存数据库）把数据放在内存里，快。

**它替你干了什么**：存登录态、缓存热点数据、做分布式锁。项目里 `zhiwei-redis` 容器，端口 6379。

**人话比喻**：MySQL（关系型数据库）是仓库（大、慢），Redis（内存数据库）是办公桌上的便签（小、快）。

**项目里在哪**：`zhiwei-framework/zhiwei-spring-boot-starter-redis`；`application-dev.yml` 的 `spring.data.redis`。

**记住**：Redis（内存数据库）= 内存里的快取。

**关联 / 参考**：→ 第 8.1 节「docker-compose（容器编排配置）」、第 1.6 节「Docker（容器工具）」

### 1.9 【工具】Knife4j / Swagger 是什么

**一句话**：Knife4j（接口文档界面）和 Swagger（接口文档规范与工具）组成自动生成的「接口说明书 + 在线调试器」。

**它替你干了什么**：扫描你所有 `@RestController`，把每个接口的路径、参数、返回列成网页，还能直接点「发送」测试。

**人话比喻**：你写代码时顺手写了「接口菜单」，Knife4j（接口文档界面）把菜单排成一本能点菜的册子。

**项目里在哪**：`http://127.0.0.1:48083/doc.html`（member）、`48081/doc.html`（system）。

**记住**：只扫本进程的 `Controller`，不扫 Feign（服务调用组件）接口，所以每个服务各看各的。

**关联 / 参考**：→ 第 11 章「Swagger（接口文档规范与工具）调通」、第 2.4 节「序列化」

### 1.10 【工具】MapStruct 是什么

**一句话**：MapStruct（对象转换代码生成器）在编译期帮你生成「对象转对象」代码。

**它替你干了什么**：你写个接口 `MemberInfoRes toRes(MemberInfo)`，加 `@Mapper`，编译时它自动生成实现类 `MemberInfoConverterImpl`，把同名字段一个个赋值。

**人话比喻**：你写「把 A 的这几个字段抄到 B」，它把抄写活儿替你干了，而且抄错字段编译期就报错。

**项目里在哪**：`MemberInfoConverter`，产物在 `target/generated-sources/annotations/.../MemberInfoConverterImpl.java`。

**记住**：MapStruct（对象转换代码生成器）的 `@Mapper` 和 MyBatis（数据库操作框架）的 `@Mapper` 是两个东西，只是同名。

**关联 / 参考**：→ 第 7 章坑（两个 @Mapper）、第 7.1 节「Converter（转换器）」

### 2.1 【Java】泛型（Generics）

**一句话**：`<>` 里写类型，让容器/方法「知道装的是什么」。

**它替你干了什么**：`List<String>` 就是「只能装字符串的列表」，`Ret<MemberInfoRes>` 就是「data 部分是 MemberInfoRes 的响应」。没有泛型，取出来都得强制转换，容易错；它把类型约束写在声明里，少让你猜。

**人话比喻**：像贴好标签的收纳盒：标了「只装书」，就不会把水杯塞进去，取书也不用再猜里面是什么。

**项目里在哪**：`Ret<T>`、`IPage<T>`、`BaseMapper<T>`、`List<MemberInfo>`。

**记住**：尖括号 = 告诉它装什么类型。

**关联 / 参考**：→ 第 1.4 节「MyBatis-Plus（数据库操作增强框架）」、第 5.4 节「分页」

### 2.2 【Java】枚举（enum）

**一句话**：一组固定取值的常量集合。

**它替你干了什么**：`status` 只有 1/2/3/4 四种，用枚举写就是 `Status.NORMAL`，比裸写 `1` 可读。member 的这类业务状态字段目前用 `Integer` + 常量，不代表整个项目都不用枚举。

**人话比喻**：像只能选固定选项的菜单：`Status.NORMAL` 是选项名，不是随手填的数字。

**项目里在哪**：`ErrorCode` 是枚举，`SUCCESS(0)`、`NOT_FOUND(404)`。

**记住**：枚举 = 有名字的固定选项。

**关联 / 参考**：→ 第 7.2 节「HTTP（超文本传输协议）状态码」中的 `ErrorCode`

### 2.3 【Java】LocalDate / LocalDateTime

**一句话**：新的日期/时间类型，替代老的 `java.util.Date`。

**它替你干了什么**：`LocalDate` 只有年月日（生日）；`LocalDateTime` 带时分秒（创建时间）。老的 `Date` 线程不安全、时区麻烦，新项目一律用这两个。

**人话比喻**：`LocalDate` 像日历上的一天，`LocalDateTime` 像日历再加时钟；生日只看日历，创建时间还要看到几点几分。

**项目里在哪**：`MemberInfo.birthday` 是 `LocalDate`，`createTime` 是 `LocalDateTime`（在 `BaseEntity`）。

**记住**：日期用 `LocalDate`，日期时间用 `LocalDateTime`。

**关联 / 参考**：→ 第 5.1 节「ORM（对象关系映射）」中的 `BaseEntity` 公共字段

### 2.4 【Java】序列化（Serialization）

**一句话**：对象 ↔ 文本/字节流的互转。

**它替你干了什么**：你 `create` 时发的 JSON（轻量数据文本格式），Spring（应用框架）用 Jackson（对象与文本互转的库）把它「反序列化」成 `MemberInfoCreateReq` 对象；返回时再「序列化」成 JSON（轻量数据文本格式）。数据库里存的是另一种序列化（`tags` 字段存 JSON（轻量数据文本格式）文本）。

**人话比喻**：像寄包裹：寄出前把物品装箱（序列化），收到后拆箱取出物品（反序列化），箱内还是同一份数据。

**项目里在哪**：`@RequestBody`（反序列化）、`Ret.ok(...)` 返回时序列化。

**记住**：进 = 反序列化，出 = 序列化。

**关联 / 参考**：→ 第 1.9 节「Knife4j（接口文档界面）/ Swagger（接口文档规范与工具）」、第 7.1 节「Converter（转换器）」

### 3.1 【Spring】IoC / DI（控制反转 / 依赖注入）

**一句话**：对象不自己 `new`，由 Spring（应用框架）创建好塞给你。

**它替你干了什么**：`MemberInfoServiceImpl` 需要 `MemberInfoMapper`，传统写法是 `new MemberInfoMapperImpl()`；IoC（控制反转）写法是 `private final MemberInfoMapper mapper`，Spring（应用框架）启动时把它创建好、通过构造器塞进来。控制权从「你」反转到了「容器」，所以叫控制反转。

**人话比喻**：像装修队领工具：工人只声明需要电钻，仓库配好并递过来，不让工人自己临时造一把。

**项目里在哪**：`@RequiredArgsConstructor` + `private final` 字段（Lombok（构造器代码生成工具）生成构造器，Spring（应用框架）用构造器注入）。

**记住**：别自己 new，声明成 final 字段让 Spring（应用框架）塞。

**关联 / 参考**：→ 第 1.1 节「Spring（应用框架）」；[Spring（应用框架）IoC（控制反转）与 DI（依赖注入）（阿里云）](https://developer.aliyun.com/article/929449)、[IoC（控制反转）容器与 Bean（受管对象）（腾讯云）](https://cloud.tencent.cn/developer/article/2313472)

### 3.2 【Spring】Bean

**一句话**：Bean（受管对象）是被 Spring（应用框架）管理的对象。

**它替你干了什么**：你给类加 `@Service`、`@RestController`、`@Component`，Spring（应用框架）启动时就会创建它的实例并管起来，这个实例就叫 Bean（受管对象）。默认单例（全局一个）。

**人话比喻**：像公司统一登记的员工：登记后由公司安排和管理，不是你临时拉来的帮手。

**项目里在哪**：`MemberInfoServiceImpl`（`@Service`）、`MemberInfoController`（`@RestController`）、`MemberInfoMapper`（`@Mapper` 扫描后注册的代理 Bean（受管对象））。

**记住**：加了注解、被 Spring（应用框架）管着的对象 = Bean（受管对象）。

**关联 / 参考**：→ 第 3.1 节「IoC（控制反转）/ DI（依赖注入）」、第 1.1 节「Spring（应用框架）」

### 3.3 【Spring】事务 `@Transactional`

**一句话**：一组数据库操作，要么全成功，要么全回滚。

**它替你干了什么**：把同一个方法里的多次数据库写操作绑成一组；加了 `@Transactional(rollbackFor = Exception.class)`，中间抛异常时，已执行的写操作会回滚。查重只是查询，本身不会留下需要回滚的修改。

**人话比喻**：像一次转账：扣款和入账必须一起完成，中间出错就两边都恢复原样。

**项目里在哪**：`MemberInfoServiceImpl` 的 `createMemberInfo / updateMemberInfo / deleteMemberInfo`。

**记住**：写操作加 `@Transactional`，出错整体撤销。

**关联 / 参考**：→ 第 1.4 节「MyBatis-Plus（数据库操作增强框架）」、第 5.3 节「逻辑删除」

### 3.4 【Spring】`@PreAuthorize`（方法级权限）

**一句话**：调这个方法前，先检查当前用户有没有这个权限码。

**它替你干了什么**：`@PreAuthorize("hasAuthority('member:info:page')")` 的意思是「token 里得有 `member:info:page` 这个权限，否则 403」。权限码从哪来？登录时按「人 → 角色 → 菜单」查出来塞进 token 的。

**人话比喻**：像办公楼门口的闸机：门卡里要有这间房的权限，闸机才放行。

**项目里在哪**：`MemberInfoController` 五个方法各一条；`SecurityAutoConfiguration` 里 `@EnableMethodSecurity` 开了这个能力。

**记住**：权限码是查出来的，不是写死的。

**关联 / 参考**：→ `资料补救` 第 7 节、第 7.2 节「HTTP（超文本传输协议）状态码」

### 3.5 【Spring】自动配置（Auto-configuration）

**一句话**：Spring Boot（快速启动框架）按「你 `classpath`（类路径）里有什么 jar（程序归档包）」自动装好对应功能。

**它替你干了什么**：你引了 `starter-web`，它就自动配好 Tomcat（网页服务器）和 Spring MVC（请求处理框架）；引了 `starter-mybatis`，它就自动配好数据源和 Mapper（数据访问接口）扫描。不需要你写 XML（可扩展标记语言）。

**人话比喻**：像成套工具箱：你选了哪套，里面对应的工具就按默认位置摆好，不用你逐个设计摆放方案。

**项目里在哪**：`zhiwei-framework/*-starter` 每个模块的 `META-INF/spring/...AutoConfiguration.imports`。

**记住**：引了依赖，功能就自动装好。

**关联 / 参考**：→ 第 1.2 节「Spring Boot（快速启动框架）」、第 1.1 节「Spring（应用框架）」

### 3.6 【Spring】`spring.config.import`

**一句话**：让 `yml` 去「读另一个地方的配置」。

**它替你干了什么**：`spring.config.import: optional:file:.env[.properties]` 表示「顺便把 `.env` 文件里的键值也读进来」；`optional:nacos:...` 表示「顺便从 Nacos（服务注册与配置中心）拉配置」。`optional` 表示找不到也不报错。

**人话比喻**：像文档开头的「另见附件」：正文配置之外，再把指定附件的内容并进来；写了 `optional`，附件缺席也能继续读。

**项目里在哪**：三个服务的 `application.yml` 开头。

**记住**：`import` = 把别的配置源拼进来。

**关联 / 参考**：→ 第 1.7 节「Nacos（服务注册与配置中心）」、第 4.2 节「配置中心」、第 8.2 节「profile（环境配置）」

### 4.1 【Spring Cloud】注册中心

**一句话**：服务启动后去登记，别人按名字找得到它。

**它替你干了什么**：`zhiwei-member-server` 启动时告诉 Nacos（服务注册与配置中心）「我在 10.150.222.232:48083」。网关要转发时，问 Nacos（服务注册与配置中心）「member 在哪」，拿到地址再转发。这样服务换了 IP（网络地址）也不用改配置。

**人话比喻**：像员工到前台登记分机号：别人只报名字，前台查出当前分机，再替双方转接。

**项目里在哪**：启动日志 `nacos registry, DEFAULT_GROUP zhiwei-member-server ... register finished`。

**记住**：登记名字，不问 IP（网络地址）。

**关联 / 参考**：→ 第 1.7 节「Nacos（服务注册与配置中心）」、第 4.3 节「负载均衡」

### 4.2 【Spring Cloud】配置中心

**一句话**：配置放远端，改完不用重新打包。

**它替你干了什么**：`optional:nacos:zhiwei-member-server-dev.yaml` 表示「去 Nacos（服务注册与配置中心）拉这个配置」。Nacos（服务注册与配置中心）控制台改完，服务刷新就生效。

**人话比喻**：像共享公告板：各服务看同一块板，公告更新后刷新读取，不必重印整本手册。

**项目里在哪**：`application.yml` 的 `spring.config.import` 第三行；Nacos（服务注册与配置中心）控制台「配置管理」。

**记住**：配置能放远端，改完不用重发版。

**关联 / 参考**：→ 第 3.6 节「`spring.config.import`」、第 1.7 节「Nacos（服务注册与配置中心）」

### 4.3 【Spring Cloud】负载均衡

**一句话**：同一个服务起了多个实例时，挑一个发请求。

**它替你干了什么**：member 起了 3 台，网关写 `lb://zhiwei-member-server`，`lb` 就是 load balance（负载均衡），它按轮询/随机挑一台。你只写服务名，不写具体 IP（网络地址）。

**人话比喻**：像一家店开了三个收银台：顾客只说到这家店结账，分流员挑一个收银台，不必指定具体店员。

**项目里在哪**：`zhiwei-gateway/src/main/resources/application.yml` 的 `uri: lb://zhiwei-member-server`。

**记住**：`lb://` 开头 = 按名字负载均衡。

**关联 / 参考**：→ 第 1.3 节「Spring Cloud（微服务协作框架）」、第 4.1 节「注册中心」

### 5.1 【MyBatis-Plus】ORM

**一句话**：ORM（对象关系映射）是 Java（编程语言）对象 ↔ 数据库表的对应关系。

**它替你干了什么**：`MemberInfo` 类 ↔ `member_info` 表，`nickname` 字段 ↔ `nickname` 列。ORM（对象关系映射）框架替你把这层转换做了，你操作对象就等于操作表。

**人话比喻**：像表格和档案卡之间的对照表：卡片上的「姓名」对应表格里的「姓名列」，照着对照表填取。

**项目里在哪**：`@TableName("member_info")` + 类字段 + `BaseEntity` 公共字段。

**记住**：一个类 = 一张表，一个字段 = 一列。

**关联 / 参考**：→ 第 1.4 节「MyBatis-Plus（数据库操作增强框架）」、第 2.3 节「LocalDate / LocalDateTime」

---

### 5.2 【MyBatis-Plus】雪花算法（Snowflake）

**一句话**：分布式下生成不重复的 19 位数字 ID（标识）。

**它替你干了什么**：自增 ID（标识）在分库分表时会撞车，所以用「时间戳 + 机器号 + 序列号」拼成一个 64 位整数。`BaseEntity` 的 `@TableId(type = IdType.ASSIGN_ID)` 就是它。

**人话比喻**：像每张票据都盖上「时间 + 窗口号 + 流水号」，多台机器同时开单也不容易撞号。

**项目里在哪**：`member_info` 每行的 `id`，如 `2124463696932474881`。

**记住**：19 位、全局唯一、**当字符串传**（JS（前端脚本语言）处理会丢精度）。

**关联 / 参考**：→ `资料补救` 第 6 节、第 5.1 节「ORM（对象关系映射）」

---

### 5.3 【MyBatis-Plus】逻辑删除

**一句话**：不真删，把 `deleted` 字段改成记录自己的 id。

**它替你干了什么**：`delete` 时执行 `UPDATE member_info SET deleted = id WHERE id = ?`；查询时 `@TableLogic` 自动加 `WHERE deleted = 0`。所以数据还在表里，但所有查询都看不见它。

**人话比喻**：像把档案放进「作废」抽屉而不是烧掉：日常查档跳过它，纸质档案仍在柜里。

**项目里在哪**：`ZhiWeiBaseMapper.logicDeleteById`、`BaseEntity.deleted`。

**记住**：记录还在，查询跳过；`count(*)` 数物理行，`page` 数逻辑行。

**关联 / 参考**：→ `资料补救` 第 8 节、第 3.3 节「事务」

---

### 5.4 【MyBatis-Plus】分页

**一句话**：只查第 N 页、每页 M 条。

**它替你干了什么**：前端传 `page=1&pageSize=10`，后端 `new Page<>(1, 10)` 传给 `selectPage`，MyBatis-Plus（数据库操作增强框架）自动拼 `LIMIT`，返回 `IPage`（里面带 `total` 总数、`records` 本页数据）。

**人话比喻**：像按页翻名册：一次只拿当前这一页，同时告诉你全册共有多少条。

**项目里在哪**：`MemberInfoServiceImpl.getMemberInfoPage`、`MemberInfoPageReq`。

**记住**：`Page` 进，`IPage` 出。

**关联 / 参考**：→ 第 2.1 节「泛型」、第 1.4 节「MyBatis-Plus（数据库操作增强框架）」

### 6.1 【构建】`pom.xml`

**一句话**：`pom.xml` 是 Maven（构建与依赖管理工具）的项目配置单。

**它替你干了什么**：里面写三件事：这个项目是谁（坐标）、依赖哪些 jar（程序归档包）（dependencies）、怎么打包（build/plugins）。父 `pom.xml` 里还写「有哪些子模块」。

**人话比喻**：像一张项目总单：抬头写项目身份，中间列要买的材料，末尾写装配方法。

**项目里在哪**：根 `pom.xml` + 每个模块各一份。

**记住**：`pom.xml` = 项目身份证 + 采购清单 + 打包说明。

**关联 / 参考**：→ 第 1.5 节「Maven（构建与依赖管理工具）」、第 6.2 节「依赖坐标」

### 6.2 【构建】依赖坐标

**一句话**：一个 jar（程序归档包）的唯一身份，`groupId + artifactId + version` 三段。

**它替你干了什么**：`org.projectlombok:lombok:1.18.48` 就是「Lombok（代码生成工具）这个组织（`groupId`）、lombok 这个项目（`artifactId`）、1.18.48 这个版本」。Maven（构建与依赖管理工具）按这三段去仓库里找。

**人话比喻**：像快递地址：组织、项目、版本三段合起来，仓库才知道要取哪一件货。

**项目里在哪**：每个 `<dependency>` 块。

**记住**：三段定位一个 jar（程序归档包），缺一段就找不着。

**关联 / 参考**：→ 第 6.1 节「`pom.xml`」、第 1.5 节「Maven（构建与依赖管理工具）」

### 6.3 【构建】本地仓库

**一句话**：下载的 jar（程序归档包）存在本机哪个目录。

**它替你干了什么**：默认 `~/.m2/repository`，你这个项目改成了 `E:\study\m2repo`（在 `~/.m2/settings.xml` 里配的）。`mvn install` 会把本项目模块的 jar（程序归档包）也装进去。

**人话比喻**：像家里的储物柜：外面买来的材料和自家做好的成品都放进去，下次装配先到这里找。

**项目里在哪**：`E:\study\m2repo\cloud\zhiwei\` 下 33 个构件目录。

**记住**：`-pl` 单独构建前，必须先 `mvn install` 过，否则依赖的模块 jar（程序归档包）找不到。

**关联 / 参考**：→ 第 7 章坑 #27、第 6.4 节「多模块工程」

### 6.4 【构建】多模块工程（reactor）

**一句话**：一个根 `pom.xml` 管一堆子模块，能一起编。

**它替你干了什么**：`zhiwei-cloud` 根目录下一个 `pom.xml`，下面 `zhiwei-module-member`、`zhiwei-common`、`zhiwei-framework` 等 10 个模块。`mvn install` 在根目录跑，会按依赖顺序把所有模块编一遍。

**人话比喻**：像总装车间排工序：先造零件，再装部件，最后总装，顺序由依赖关系决定。

**项目里在哪**：根 `pom.xml` 的 `<modules>`。

**记住**：根 `pom.xml` 是总调度，子模块按依赖顺序编。

### 6.5 【构建】依赖范围 `scope`

**一句话**：这个依赖在哪些阶段可见。

**它替你干了什么**：`compile`（默认，编译+运行都用）、`provided`（编译用，运行时由容器提供，如 lombok、servlet-api）、`test`（只测试用）。写错会导致运行时报 `ClassNotFoundException`。

**人话比喻**：像施工材料分入场时段：有的全程在场，有的只施工时用、正式使用由现场另备，有的只在检测时出现。

**项目里在哪**：`<dependency>` 里的 `<scope>`；member-api 的 lombok 是 `provided`。

**记住**：`provided` 的 jar（程序归档包）不会打进包里。

**关联 / 参考**：→ 第 6.2 节「依赖坐标」、第 1.5 节「Maven（构建与依赖管理工具）」

### 7.1 【数据接口】Converter（转换器）

**一句话**：Converter（转换器）负责 Entity（数据库实体）和 Res（响应对象）互转。

**它替你干了什么**：Entity（数据库实体）跟表走，带 `deleted`、`orgId`、`operatorId` 这些不该给前端的字段；Res（响应对象）只放要展示的字段。Converter（转换器）负责把 Entity（数据库实体）转成 Res（响应对象）。

**人话比喻**：像内外两套登记表：库房表记录内部信息，访客表只留可公开栏目，中间按规则誊写。

**项目里在哪**：`MemberInfoConverter`（MapStruct（对象转换代码生成器）生成实现）。

**记住**：Entity（数据库实体）给数据库看，Res（响应对象）给前端看，Converter（转换器）中间转。

**关联 / 参考**：→ 第 1.10 节「MapStruct（对象转换代码生成器）」、第 2.4 节「序列化」

### 7.2 【数据接口】HTTP 状态码

**一句话**：HTTP（超文本传输协议）状态码用一个数字告诉前端这次请求怎么样了。

**它替你干了什么**：
- `200` 成功
- `400` 参数不对
- `401` 没登录 / token 无效
- `403` 登录了但没权限
- `404` 找不到（记录不存在、路径写错）
- `500` 服务器内部错误

**人话比喻**：像快递回执上的结果码：签收、地址有误、无权收件、查无此件、分拣异常，各自对应一种处理办法。

**项目里在哪**：`Ret` 里的 `httpCode` 和 `code`；`ErrorCode` 枚举。

**记住**：401 找登录，403 找权限，404 找数据，500 看日志。

**关联 / 参考**：→ 第 2.2 节「枚举」、第 3.4 节「`@PreAuthorize`」、第 8.3 节「日志」

### 8.3 【部署】日志（log / slf4j）

**人话比喻**：像值班记录本：日常巡岗记一笔，出了故障把现场情况记下来，排查时按时间回看。

### 8.4 【部署】重启

**一句话**：改了 Java（编程语言）代码，必须重启服务才生效。

**它替你干了什么**：Spring Boot（快速启动框架）跑的是编译后的 `class`（类文件），你改了 `.java` 文件不重启，跑的还是旧的。改配置（Nacos（服务注册与配置中心））可以刷新不重启，改代码不行。

**人话比喻**：像印刷好的书：改写手稿后，不重新印刷，架上那本仍是旧内容。

**项目里在哪**：`Ctrl+C` 停掉 `mvn spring-boot:run`，再跑一次。

**记住**：改代码 → 重启；改远端配置 → 刷新。
