## 一、先搞懂这些工具是干什么的

> 先把「工具」认全，再看细节。看不懂报错，多半是不知道哪个工具在说话。

### 1.1 Spring 是什么

**一句话**：Java 的「对象大管家 + Web 工具箱」。

**它替你干了什么**：创建对象、把对象互相塞好（依赖注入）、接 HTTP 请求、管事务、做权限检查。你没写的那些 `new`，它在背后替你做了。

**人话比喻**：你开一家店，Spring 是「店长 + 后勤」。你只管业务（接单、算账），缺人手、收货、收银台它都安排好。

**项目里在哪**：`zhiwei-framework/` 下每个 starter 都是项目自己封装的 Spring 组件（web、mybatis、security、redis、biz-tenant）。

**记住**：Spring = 管对象、管请求的工具箱。

**参考**：[Spring IoC 与 DI 通俗讲解（阿里云开发者社区）](https://developer.aliyun.com/article/929449)

---

### 1.2 Spring Boot 是什么

**一句话**：让 Spring「开箱即用」的脚手架。

**它替你干了什么**：以前用 Spring 要写一堆 XML 配置，Spring Boot 改成「加个依赖、写几行 yml 就能跑」，还自带内嵌 Tomcat。

**人话比喻**：Spring 是零件包，Spring Boot 是「已经按说明书拼好的套装」，插电就用。

**项目里在哪**：每个 `*-server` 模块的启动类 `XxxApplication`，`mvn spring-boot:run` 跑的就是它。

**记住**：Spring Boot = 自动配好的 Spring。

**关联**：→ 第 2 章「启动流程」

---

### 1.3 Spring Cloud 是什么

**一句话**：给「一堆 Spring Boot 服务」配的协作套装。

**它替你干了什么**：服务怎么互相找到（Nacos）、请求怎么统一入口（Gateway）、服务之间怎么调用（Feign）、多个实例怎么分流量（LoadBalancer）。

**人话比喻**：Spring Boot 是一家家分店，Spring Cloud 是「总部的调度系统」——分店登记、客人进门先到总台、总台按区域指路。

**项目里在哪**：`zhiwei-gateway`（总台）+ 各服务的 `spring-cloud-starter-alibaba-nacos-discovery` 依赖。

**记住**：Spring Cloud = 服务之间的「调度系统」。

**关联**：→ 第 6 章「网关与 Feign」

---

### 1.4 MyBatis-Plus 是什么

**一句话**：操作数据库的库，帮你省掉 90% 的增删改查 SQL。

**它替你干了什么**：继承 `BaseMapper<T>` 就白得 `insert / selectById / updateById / deleteById / selectPage`；`@TableLogic` 自动拼逻辑删除条件；`LambdaQueryWrapper` 用方法引用写条件，字段写错编译期就报错。

**人话比喻**：以前你要手写「去仓库几号货架拿什么」，现在你说「拿 id=1 的会员」，它自己去翻译成 SQL。

**项目里在哪**：`MemberInfoMapper extends ZhiWeiBaseMapper<MemberInfo>`，`MemberInfoServiceImpl` 里的 `selectPage`、`logicDeleteById`。

**记住**：MyBatis-Plus = 不用写 SQL 的数据库操作层。

**参考**：[MyBatis-Plus 官方快速开始](https://baomidou.com/getting-started/)、[MyBatis 与 MyBatis-Plus 区别](https://developer.aliyun.com/article/1677767)

**关联**：→ 第 11 章第 5 批 Service

---

### 1.5 Maven 是什么

**一句话**：Java 的「构建 + 依赖管理」工具。

**它替你干了什么**：
- 依赖：你在 `pom.xml` 写「我要 mybatis-plus 3.5.18」，它去仓库下载 jar，连带把 mybatis-plus 依赖的别的 jar 也下下来
- 构建：`compile` 编译、`package` 打包、`install` 装进本地仓库
- 多模块：一个根 pom 管 10 个子模块，能一起编

**人话比喻**：Maven 是「采购 + 装配车间」。你报清单（pom），它去买料（下 jar）、按图纸组装（编译打包）、把成品放进仓库（install）。

**项目里在哪**：根 `pom.xml` + 每个模块的 `pom.xml`；本地仓库在 `E:\study\m2repo`（不是默认的 `~/.m2/repository`）。

**记住**：Maven = 报清单、买料、组装。

**关联**：→ 第 2 章「`mvn clean install` 为什么必须先跑」、第 7 章坑 #27

---

### 1.6 Docker 是什么

**一句话**：把「程序 + 它要的环境」打包成一个盒子，到哪都能跑。

**它替你干了什么**：你本机不用装 MySQL、不用装 Nacos，拉一个镜像跑起来就行；团队里所有人的环境一模一样。

**人话比喻**：
- **镜像（image）** = 出厂模板 / 菜谱加食材包
- **容器（container）** = 照着模板跑起来的那一份 / 按菜谱炒出来的那盘菜
- **仓库（registry）** = 模板商店（Docker Hub）

**项目里在哪**：`docker-compose.yml` 一次起 Redis + Nacos；你手动 `docker run` 起的 `zhiwei-mysql`。

**记住**：镜像是模板，容器是跑起来的那一份。

**参考**：[Docker 基本介绍（阿里云）](https://developer.aliyun.com/article/904506)、[镜像与容器：菜谱与菜](https://bbs.huaweicloud.com/blogs/532970)

**关联**：→ `资料补救` 第 1 节、第 3 节

---

### 1.7 Nacos 是什么

**一句话**：服务的「通讯录 + 公告板」。

**它替你干了什么**：
- 注册中心：每个服务启动后去登记「我叫 zhiwei-member-server，我在 10.150.222.232:48083」
- 配置中心：把 yml 配置放它那，改完不用重启（`spring.config.import: optional:nacos:...`）
- 网关按名字找到服务（`lb://zhiwei-member-server`），靠的就是它

**人话比喻**：Nacos 是公司前台。新员工来了先到前台登记工位（注册），找人先问前台（发现），公司通知贴在前台公告板（配置）。

**项目里在哪**：`docker-compose.yml` 的 nacos 容器；每个服务 `application.yml` 里的 `spring.cloud.nacos.discovery`。

**记住**：Nacos = 服务通讯录 + 配置公告板。

**关联**：→ 第 6 章

### 1.8 Redis 是什么

**一句话**：把数据放在内存里的数据库，快。

**它替你干了什么**：存登录态、缓存热点数据、做分布式锁。项目里 `zhiwei-redis` 容器，端口 6379。

**人话比喻**：MySQL 是仓库（大、慢），Redis 是办公桌上的便签（小、快）。

**项目里在哪**：`zhiwei-framework/zhiwei-spring-boot-starter-redis`；`application-dev.yml` 的 `spring.data.redis`。

**记住**：Redis = 内存里的快取。

---

### 1.9 Knife4j / Swagger 是什么

**一句话**：自动生成的「接口说明书 + 在线调试器」。

**它替你干了什么**：扫描你所有 `@RestController`，把每个接口的路径、参数、返回列成网页，还能直接点「发送」测试。

**人话比喻**：你写代码时顺手写了「接口菜单」，Knife4j 把菜单排成一本能点菜的册子。

**项目里在哪**：`http://127.0.0.1:48083/doc.html`（member）、`48081/doc.html`（system）。

**记住**：只扫本进程的 Controller，不扫 Feign 接口，所以每个服务各看各的。

**关联**：→ 第 11 章「Swagger 调通」

---

### 1.10 MapStruct 是什么

**一句话**：编译期帮你生成「对象转对象」代码的工具。

**它替你干了什么**：你写个接口 `MemberInfoRes toRes(MemberInfo)`，加 `@Mapper`，编译时它自动生成实现类 `MemberInfoConverterImpl`，把同名字段一个个赋值。

**人话比喻**：你写「把 A 的这几个字段抄到 B」，它把抄写活儿替你干了，而且抄错字段编译期就报错。

**项目里在哪**：`MemberInfoConverter`，产物在 `target/generated-sources/annotations/.../MemberInfoConverterImpl.java`。

**记住**：MapStruct 的 `@Mapper` 和 MyBatis 的 `@Mapper` 是两个东西，只是同名。

**关联**：→ 第 7 章坑（两个 @Mapper）

## 二、Java 语言本身

### 2.1 泛型（Generics）

**一句话**：`<>` 里写类型，让容器/方法「知道装的是什么」。

**人话解释**：`List<String>` 就是「只能装字符串的列表」，`Ret<MemberInfoRes>` 就是「data 部分是 MemberInfoRes 的响应」。没有泛型，取出来都得强制转换，容易错。

**项目里在哪**：`Ret<T>`、`IPage<T>`、`BaseMapper<T>`、`List<MemberInfo>`。

**记住**：尖括号 = 告诉它装什么类型。

---

### 2.2 枚举（enum）

**一句话**：一组固定取值的常量集合。

**人话解释**：`status` 只有 1/2/3/4 四种，用枚举写就是 `Status.NORMAL`，比裸写 `1` 可读。本项目没用枚举，用 `Integer` + 常量代替（历史选择）。

**项目里在哪**：`ErrorCode` 是枚举，`SUCCESS(0)`、`NOT_FOUND(404)`。

**记住**：枚举 = 有名字的固定选项。

---

### 2.3 LocalDate / LocalDateTime

**一句话**：新的日期/时间类型，替代老的 `java.util.Date`。

**人话解释**：`LocalDate` 只有年月日（生日）；`LocalDateTime` 带时分秒（创建时间）。老的 `Date` 线程不安全、时区麻烦，新项目一律用这两个。

**项目里在哪**：`MemberInfo.birthday` 是 `LocalDate`，`createTime` 是 `LocalDateTime`（在 `BaseEntity`）。

**记住**：日期用 `LocalDate`，日期时间用 `LocalDateTime`。

---

### 2.4 序列化（Serialization）

**一句话**：对象 ↔ 文本/字节流的互转。

**人话解释**：你 `create` 时发的 JSON，Spring 用 Jackson 把它「反序列化」成 `MemberInfoCreateReq` 对象；返回时再「序列化」成 JSON。数据库里存的是另一种序列化（`tags` 字段存 JSON 文本）。

**项目里在哪**：`@RequestBody`（反序列化）、`Ret.ok(...)` 返回时序列化。

**记住**：进 = 反序列化，出 = 序列化。

---

## 三、Spring 框架

### 3.1 IoC / DI（控制反转 / 依赖注入）

**一句话**：对象不自己 `new`，由 Spring 创建好塞给你。

**人话解释**：`MemberInfoServiceImpl` 需要 `MemberInfoMapper`，传统写法是 `new MemberInfoMapperImpl()`；IoC 写法是 `private final MemberInfoMapper mapper`，Spring 启动时把它创建好、通过构造器塞进来。控制权从「你」反转到了「容器」，所以叫控制反转。

**项目里在哪**：`@RequiredArgsConstructor` + `private final` 字段（Lombok 生成构造器，Spring 用构造器注入）。

**记住**：别自己 new，声明成 final 字段让 Spring 塞。

**参考**：[Spring IoC 与 DI（阿里云）](https://developer.aliyun.com/article/929449)、[IoC 容器与 Bean（腾讯云）](https://cloud.tencent.cn/developer/article/2313472)

---

### 3.2 Bean

**一句话**：被 Spring 管理的对象。

**人话解释**：你给类加 `@Service`、`@RestController`、`@Component`，Spring 启动时就会创建它的实例并管起来，这个实例就叫 Bean。默认单例（全局一个）。

**项目里在哪**：`MemberInfoServiceImpl`（`@Service`）、`MemberInfoController`（`@RestController`）、`MemberInfoMapper`（`@Mapper` 扫描后注册的代理 Bean）。

**记住**：加了注解、被 Spring 管着的对象 = Bean。

---

### 3.3 事务 `@Transactional`

**一句话**：一组数据库操作，要么全成功，要么全回滚。

**人话解释**：`create` 里先查重、再插入；如果插入到一半抛异常，查重那步不应该留下痕迹。加了 `@Transactional(rollbackFor = Exception.class)` 就会整体回滚。

**项目里在哪**：`MemberInfoServiceImpl` 的 `createMemberInfo / updateMemberInfo / deleteMemberInfo`。

**记住**：写操作加 `@Transactional`，出错整体撤销。

---

### 3.4 `@PreAuthorize`（方法级权限）

**一句话**：调这个方法前，先检查当前用户有没有这个权限码。

**人话解释**：`@PreAuthorize("hasAuthority('member:info:page')")` 的意思是「token 里得有 `member:info:page` 这个权限，否则 403」。权限码从哪来？登录时按「人 → 角色 → 菜单」查出来塞进 token 的。

**项目里在哪**：`MemberInfoController` 五个方法各一条；`SecurityAutoConfiguration` 里 `@EnableMethodSecurity` 开了这个能力。

**记住**：权限码是查出来的，不是写死的。

**关联**：→ `资料补救` 第 7 节

---

### 3.5 自动配置（Auto-configuration）

**一句话**：Spring Boot 按「你 classpath 里有什么 jar」自动装好对应功能。

**人话解释**：你引了 `starter-web`，它就自动配好 Tomcat 和 Spring MVC；引了 `starter-mybatis`，它就自动配好数据源和 Mapper 扫描。不需要你写 XML。

**项目里在哪**：`zhiwei-framework/*-starter` 每个模块的 `META-INF/spring/...AutoConfiguration.imports`。

**记住**：引了依赖，功能就自动装好。

---

### 3.6 `spring.config.import`

**一句话**：让 yml 去「读另一个地方的配置」。

**人话解释**：`spring.config.import: optional:file:.env[.properties]` 表示「顺便把 `.env` 文件里的键值也读进来」；`optional:nacos:...` 表示「顺便从 Nacos 拉配置」。`optional` 表示找不到也不报错。

**项目里在哪**：三个服务的 `application.yml` 开头。

**记住**：`import` = 把别的配置源拼进来。

---

## 四、Spring Cloud / 微服务

### 4.1 注册中心

**一句话**：服务启动后去登记，别人按名字找得到它。

**人话解释**：`zhiwei-member-server` 启动时告诉 Nacos「我在 10.150.222.232:48083」。网关要转发时，问 Nacos「member 在哪」，拿到地址再转发。这样服务换了 IP 也不用改配置。

**项目里在哪**：启动日志 `nacos registry, DEFAULT_GROUP zhiwei-member-server ... register finished`。

**记住**：登记名字，不问 IP。

---

### 4.2 配置中心

**一句话**：配置放远端，改完不用重新打包。

**人话解释**：`optional:nacos:zhiwei-member-server-dev.yaml` 表示「去 Nacos 拉这个配置」。Nacos 控制台改完，服务刷新就生效。

**项目里在哪**：`application.yml` 的 `spring.config.import` 第三行；Nacos 控制台「配置管理」。

**记住**：配置能放远端，改完不用重发版。

---

### 4.3 负载均衡

**一句话**：同一个服务起了多个实例时，挑一个发请求。

**人话解释**：member 起了 3 台，网关写 `lb://zhiwei-member-server`，`lb` 就是 load balance，它按轮询/随机挑一台。你只写服务名，不写具体 IP。

**项目里在哪**：`zhiwei-gateway/src/main/resources/application.yml` 的 `uri: lb://zhiwei-member-server`。

**记住**：`lb://` 开头 = 按名字负载均衡。

## 五、MyBatis-Plus / 数据库访问

### 5.1 ORM

**一句话**：Java 对象 ↔ 数据库表的对应关系。

**人话解释**：`MemberInfo` 类 ↔ `member_info` 表，`nickname` 字段 ↔ `nickname` 列。ORM 框架替你把这层转换做了，你操作对象就等于操作表。

**项目里在哪**：`@TableName("member_info")` + 类字段 + `BaseEntity` 公共字段。

**记住**：一个类 = 一张表，一个字段 = 一列。

---

### 5.2 雪花算法（Snowflake）

**一句话**：分布式下生成不重复的 19 位数字 ID。

**人话解释**：自增 ID 在分库分表时会撞车，所以用「时间戳 + 机器号 + 序列号」拼成一个 64 位整数。`BaseEntity` 的 `@TableId(type = IdType.ASSIGN_ID)` 就是它。

**项目里在哪**：`member_info` 每行的 `id`，如 `2124463696932474881`。

**记住**：19 位、全局唯一、**当字符串传**（JS 处理会丢精度）。

**关联**：→ `资料补救` 第 6 节

---

### 5.3 逻辑删除

**一句话**：不真删，把 `deleted` 字段改成记录自己的 id。

**人话解释**：`delete` 时执行 `UPDATE member_info SET deleted = id WHERE id = ?`；查询时 `@TableLogic` 自动加 `WHERE deleted = 0`。所以数据还在表里，但所有查询都看不见它。

**项目里在哪**：`ZhiWeiBaseMapper.logicDeleteById`、`BaseEntity.deleted`。

**记住**：记录还在，查询跳过；`count(*)` 数物理行，`page` 数逻辑行。

**关联**：→ `资料补救` 第 8 节

---

### 5.4 分页

**一句话**：只查第 N 页、每页 M 条。

**人话解释**：前端传 `page=1&pageSize=10`，后端 `new Page<>(1, 10)` 传给 `selectPage`，MyBatis-Plus 自动拼 `LIMIT`，返回 `IPage`（里面带 `total` 总数、`records` 本页数据）。

**项目里在哪**：`MemberInfoServiceImpl.getMemberInfoPage`、`MemberInfoPageReq`。

**记住**：`Page` 进，`IPage` 出。

---

## 六、构建与依赖

### 6.1 `pom.xml`

**一句话**：Maven 的项目配置单。

**人话解释**：里面写三件事：这个项目是谁（坐标）、依赖哪些 jar（dependencies）、怎么打包（build/plugins）。父 pom 里还写「有哪些子模块」。

**项目里在哪**：根 `pom.xml` + 每个模块各一份。

**记住**：pom = 项目身份证 + 采购清单 + 打包说明。

---

### 6.2 依赖坐标

**一句话**：一个 jar 的唯一身份，`groupId + artifactId + version` 三段。

**人话解释**：`org.projectlombok:lombok:1.18.48` 就是「Lombok 这个组织（groupId）、lombok 这个项目（artifactId）、1.18.48 这个版本」。Maven 按这三段去仓库里找。

**项目里在哪**：每个 `<dependency>` 块。

**记住**：三段定位一个 jar，缺一段就找不着。

---

### 6.3 本地仓库

**一句话**：下载的 jar 存在本机哪个目录。

**人话解释**：默认 `~/.m2/repository`，你这个项目改成了 `E:\study\m2repo`（在 `~/.m2/settings.xml` 里配的）。`mvn install` 会把本项目模块的 jar 也装进去。

**项目里在哪**：`E:\study\m2repo\cloud\zhiwei\` 下 33 个构件目录。

**记住**：`-pl` 单独构建前，必须先 `mvn install` 过，否则依赖的模块 jar 找不到。

**关联**：→ 第 7 章坑 #27

---

### 6.4 多模块工程（reactor）

**一句话**：一个根 pom 管一堆子模块，能一起编。

**人话解释**：`zhiwei-cloud` 根目录下一个 pom，下面 `zhiwei-module-member`、`zhiwei-common`、`zhiwei-framework` 等 10 个模块。`mvn install` 在根目录跑，会按依赖顺序把所有模块编一遍。

**项目里在哪**：根 `pom.xml` 的 `<modules>`。

**记住**：根 pom 是总调度，子模块按依赖顺序编。

---

### 6.5 依赖范围 `scope`

**一句话**：这个依赖在哪些阶段可见。

**人话解释**：`compile`（默认，编译+运行都用）、`provided`（编译用，运行时由容器提供，如 lombok、servlet-api）、`test`（只测试用）。写错会导致运行时报 `ClassNotFoundException`。

**项目里在哪**：`<dependency>` 里的 `<scope>`；member-api 的 lombok 是 `provided`。

**记住**：provided 的 jar 不会打进包里。

---

## 七、数据与接口

### 7.1 Converter（转换器）

**一句话**：Entity 和 Res 互转的那一层。

**人话解释**：Entity 跟表走，带 `deleted`、`orgId`、`operatorId` 这些不该给前端的字段；Res 只放要展示的字段。Converter 负责把 Entity 转成 Res。

**项目里在哪**：`MemberInfoConverter`（MapStruct 生成实现）。

**记住**：Entity 给数据库看，Res 给前端看，Converter 中间转。

---

### 7.2 HTTP 状态码

**一句话**：一个数字告诉前端这次请求怎么样了。

**人话解释**：
- `200` 成功
- `400` 参数不对
- `401` 没登录 / token 无效
- `403` 登录了但没权限
- `404` 找不到（记录不存在、路径写错）
- `500` 服务器内部错误

**项目里在哪**：`Ret` 里的 `httpCode` 和 `code`；`ErrorCode` 枚举。

**记住**：401 找登录，403 找权限，404 找数据，500 看日志。

---

## 八、运行与部署

### 8.1 docker-compose

**一句话**：用一份 yml 一次起多个容器。

**人话解释**：`docker-compose.yml` 里写「redis 用哪个镜像、映射哪个端口、nacos 用哪个镜像、环境变量是什么」，一条 `docker compose up -d` 全起来。

**项目里在哪**：仓库根 `docker-compose.yml`（Redis + Nacos）。

**记住**：compose = 一次编排多个容器。

---

### 8.2 profile（dev / test / prod）

**一句话**：同一套代码，不同环境用不同配置。

**人话解释**：`application-dev.yml` 连本地库，`application-prod.yml` 连生产库，启动时 `--spring.profiles.active=dev` 选一个。

**项目里在哪**：每个服务的 `application-dev.yml`，`application.yml` 里 `profiles.active: dev`。

**记住**：一份代码，多份环境配置，启动时选。

---

### 8.3 日志（log / slf4j）

**一句话**：程序运行时打的记录，出问题先看它。

**人话解释**：`@Slf4j` 给你一个 `log` 对象，`log.info(...)` 打普通信息，`log.error(...)` 打错误。级别从细到粗：`TRACE < DEBUG < INFO < WARN < ERROR`。

**项目里在哪**：每个类的 `@Slf4j`；`application-dev.yml` 里 `logging.level.cloud.zhiwei: DEBUG`。

**记住**：DEBUG 看得最细，ERROR 才是真错。

---

### 8.4 重启

**一句话**：改了 Java 代码，必须重启服务才生效。

**人话解释**：Spring Boot 跑的是编译后的 class，你改了 `.java` 文件不重启，跑的还是旧的。改配置（Nacos）可以刷新不重启，改代码不行。

**项目里在哪**：`Ctrl+C` 停掉 `mvn spring-boot:run`，再跑一次。

**记住**：改代码 → 重启；改远端配置 → 刷新。

---
