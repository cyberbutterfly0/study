## 一、会议讲了什么

### 1. 网关是唯一入口（21:18–21:21）

- 网关（Gateway）只做外层流量转发，本身不处理业务逻辑。
- 所有外部请求必须先经过网关，它是流量的唯一入口；网关监听 480 或 48080（本项目实际 **48080**）。
- 子服务（如 member）的访问路径建立在网关转发之上，形成「网关 → 子服务」两级结构。
- 开发调试时可以直接访问后端接口，**不用启动前端**——这也是这阶段用 Swagger 调接口的原因。

要记的概念：**先网关后服务**。请求先到网关端口，网关按路由规则转发到对应子服务。网关和子服务地址的对应关系错了，接口就是 404/502。

### 2. Swagger 调接口与认证（21:21–21:35）

- 接口路径 = 基础地址 + 具体路径；本地调试基础地址是 `localhost`（纪要口述端口 8081，本项目实际端口见第五节口径差异）。
- Swagger 里每个接口预置好参数位置，填参数直接发请求；没通过权限校验的请求会被后端拦截。
- 登录拿 Token：默认账号 `admin` / 密码 `123456`，请求成功返回的响应里有一串 Token，那串字符就是登录凭证。
- 全局授权：Swagger 全局配置里参数名填 `Authorization`，值填 `Bearer <空格>Token`；配置完后续请求自动带认证信息。
- 排查：带了 Token 还报「用户没找到」，可能是 ID 无效，也可能是系统语言导致提示是英文；加请求头 `language: zh-CN` 试一下中文提示。Swagger 本质是生成 HTTP 指令，也可以用命令行复现；双击 Shift 可以快速搜接口。

### 3. 数据类型与查询（21:35–21:42）

- Java 常用四种类型：`Long`（数值参数，传非数字直接报错）、`Int`、`String`（实际开发大部分场景是 Long 和 String）、`Date`（时间）。
- 查不到数据先查 SQL 条件：`org_id=0` 这类条件不匹配，或者记录被软删除。
- 软删机制：被软删的记录还在表里、只是界面不显示，字段值不为 0 就查不到，改回 0 才能重新查到。纪要说字段叫 `is_delete`，项目里实际叫 `deleted`。
- 定位方法：把接口实际执行的 SQL 复制出来手动跑，分清是「ID 不存在」「条件不匹配」还是「被软删」。

### 4. 更新操作与分工（21:42–21:49）

- 通过调试工具直接发请求就能修改库里的数据，不需要前端界面。演示：把 ID 10002 的用户昵称改成讲师的名字、邮箱改成 `7783@qq.com`，发完刷新查库确认已同步。
- 每个 Controller（如 `SysUserController`）对应一组 API：创建、删除、更新状态、重置密码等；方法通过映射注解挂到具体地址，GET 或 Create 请求触发对应逻辑。
- 新增接口时接口名必须唯一（示例 `create1`），并在实现类里完成逻辑后重启项目才生效。
- 讲师强调：**先掌握基础编码逻辑和手动调试方法**，后面再学用 AI 串联开发；现阶段用调试工具验证代码，确保理解底层实现原理。
- 分工：

### 5. 代码结构与建表（21:49–21:54）

标准五层，一一对应：

| 层 | 职责 |
|---|---|
| Controller | 接收请求、处理响应 |
| Service | 核心业务逻辑 |
| Entity | 对象实体（对应一张表） |
| Mapper | 数据库映射操作 |
| API / Req / Res | 定义接口请求参数（Req）和返回结果（Res） |

- **一表一模块**：一套完整的 API、POJO 和分层代码只维护一张数据库表，保证模块独立与清晰。
- 参考实现策略：先拉现有代码体验，再照抄成熟模块的结构（BIZ 基础表或 Member 表路径）。
- 彭婧茹 BizInfo：构建业务信息表 + 对应 API 接口；**讲师协助建表**，她只需把建好的表结构拷进项目。
- 伊藤眠 Member：构建会员信息表（MemberInfo），支持用户注册；**是后续「预约医生」等业务的前置条件**（先注册会员才能预约）；需要**独立完成该表的数据库连接与创建**。
- 环境：讲师给新的数据库连接地址（从阿里切到腾讯），库名保持 `test-16`；建议先启动项目、把运行环境调通，再逐步加业务代码；讲师协助建表的模块执行 SQL 脚本后刷新就能看到空表。
