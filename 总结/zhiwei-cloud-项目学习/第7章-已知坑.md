# 第7章 已知坑

按踩到的概率排。

## 1. 没有 spring-boot-maven-plugin

各 pom 都没声明，`mvn spring-boot:run` 报：

```text
No plugin found for prefix 'spring-boot'
```

要么用全限定坐标：

```powershell
mvn org.springframework.boot:spring-boot-maven-plugin:4.1.2:run
```

要么直接在 IDEA 里跑主类。

## 2. 目录名笔误

- `zhiwei-module-member/zhiwei-module-member-seven` 应该是 `-server`
- `zhiwei-module-booking/zhiwei-module-booking-sever` 应该是 `-server`

改名会影响根 pom 的 `<module>` 和 IDE 配置，**动之前先问负责人**。

## 3. dev 配置里密码是明文

`application-dev.yml` 写死了 PolarDB 密码，赶工阶段可以，但推到公共仓库前要意识到这是敏感信息。

## 4. Nacos 缺配置只 WARN

首次启动不用先去 Nacos 建配置文件，但业务参数会缺失，后面要补：

- `zhiwei-gateway-dev.yaml`
- `zhiwei-system-server-dev.yaml`
- `zhiwei-infra-server-dev.yaml`

## 5. docker-compose 不含 MySQL

只起 Redis + Nacos，业务库用外部 PolarDB。别去找 MySQL 容器。

## 6. .flattened-pom.xml

`flatten-maven-plugin` 的构建产物，`mvn` 跑过就在模块根目录出现。`.gitignore` 已忽略，**不要提交**。

## 7. .mvn 目录

Maven Archetype 生成模块时的副产物，`maven.config` / `jvm.config` 都是空文件，对构建无影响。

## 8. 依赖下载慢

仓库配了阿里云镜像（`~/.m2/settings.xml`），首次 `mvn clean install` 仍要下几百 MB，耐心等。

## 9. PolarDB 白名单

连不上数据库先查 IP 白名单，出口 IP 变了要加白。报错 `Connection timed out` 或 `Access denied`。

## 10. IDEA 的 SDK 要指到 JDK27

本机已只留 `E:\JDK27`。如果 IDEA 提示 SDK 无效，去 Project Structure 选 27。

## 11. JDK 解压后的文件完整性标签是 Low（本次排查最耗时的一个）

症状：`mvn` 写本地仓库报 `AccessDeniedException`、Tomcat 报 `Unable to create tempDir`、`javac` 报「写入 xxx 时出错」、IDEA 报 `configuration.crc` AccessDenied——但目录 ACL 全正常、PowerShell 手动建文件没问题，只有 java 进程不行。

查：`icacls "E:\JDK27\bin\java.exe"`，出现 `Mandatory Label\Low Mandatory Level:(I)(NW)` 即中招。

修：

```powershell
icacls 'E:\JDK27' /setintegritylevel '(OI)(CI)M' /T
```

原理：Windows UIPI 机制，Low 完整性进程不能往 Medium（默认）目录写。JDK 从下载/解压工具继承了 Low 标签。别先去查 ACL、杀软、Defender、组策略，先查这一行。

## 12. IDEA 的 .idea/modules.xml 损坏导致 ClassNotFoundException

症状：命令行 `mvn clean install` 成功，IDEA 里运行报 `ClassNotFoundException`，或启动时缺某个依赖类。

查：`.idea\modules.xml` 里登记了几个模块、引用的 `.iml` 是否存在——正常应与项目模块数一致。

修：Maven 面板 🔄「重新加载所有 Maven 项目」；不行就关 IDEA → 备份删 `modules.xml` → 重开按提示从 pom 导入。

## 13. target/classes 只有 resources 没有 .class

构建报"成功"但 `target\classes` 里只有 `application-*.yml`、`logback-spring.xml`，没有编译出的 class → IDEA 运行时必然 ClassNotFound。

查：

```powershell
Test-Path 'zhiwei-module-system\zhiwei-module-system-server\target\classes\cloud\zhiwei\system\SystemServerApplication.class'
```

修：回项目根重跑 `mvn clean install -DskipTests`，必须看到 `Compiling N source files` 和 `BUILD SUCCESS`。

## 14. Feign 接口上写了类级 @RequestMapping，启动直接报错

症状：服务启动失败，堆栈里是

```text
java.lang.IllegalArgumentException: @RequestMapping annotation not allowed on @FeignClient interfaces
    at org.springframework.cloud.openfeign.support.SpringMvcContract.processAnnotationOnClass(SpringMvcContract.java:196)
```

任何 `@EnableFeignClients` 扫描到该接口的服务都会挂（比如 infra-server 一启动就退）。

原因：OpenFeign 4.x 不允许 `@FeignClient` 接口上有类级 `@RequestMapping`；路径前缀要用 `@FeignClient(path = "/api/xxx")`。

修：去掉接口类级 `@RequestMapping`，前缀挪进 `@FeignClient(path=...)`；提供方 Controller 自己写类级 `@RequestMapping` 同前缀（`@FeignClient(path)` 不被 Spring MVC 继承）。这是 master 提交 `9b937dc 调整Spring MVC不识别@FeignClient注解` 的统一改法。

## 15. target/classes 里的 application.yml 是旧版

症状：切了分支、拉了新配置，重启服务后配置没生效——比如网关登录路由 404，但源码 `application.yml` 里明明有 `/api/auth/**`。

原因：只重启服务、没重新构建，`target/classes/application.yml` 还是上一次构建的副本。

查：

```powershell
Get-Item 'zhiwei-gateway\target\classes\application.yml' | Select-Object LastWriteTime, Length
Get-Item 'zhiwei-gateway\src\main\resources\application.yml' | Select-Object LastWriteTime, Length
```

两个时间不一致就是没重新构建。

修：回项目根跑 `mvn install -DskipTests`（不必 clean，避免删掉 target 后服务没法跑），构建后 `target/classes/application.yml` 的时间应更新。

## 16. 前端已拆独立仓库，本地 `zhiwei-frontend/` 不再随父仓库更新

11-06 的 `e8866c3` 把 `zhiwei-frontend/` 移出父仓库，父仓库 `.gitignore` 里加了 `zhiwei-frontend/`。后果：

- `git pull` 父仓库**不会**更新前端代码，本地那份可能停在拆仓前的状态
- `git status` 看不到前端改动（已被忽略，不是没改动）
- 根 `AGENTS.md` 的技术栈表里仍引用 `zhiwei-frontend/AGENTS.md` 和 `packages/zhiwei-ui-shared/AGENTS.md`——这两个路径在父仓库里指向的是「被忽略的本地目录」，新 clone 的人根本没有

要拿前端代码，单独 clone 独立仓库（远程地址见第 8 章）。

## 17. 云效文档里的 JSON 工具类叫 `YdmapJson`，代码里实际是 `ZhiWeiJson`

按文档去 grep `YdmapJson` 一无所获，真实类在 `zhiwei-common/src/main/java/cloud/zhiwei/common/ZhiWeiJson.java`，全仓库 24 处引用都是它。文档没跟着改名，别以为是自己找错。

## 18. 逻辑删除是 `deleted = id`，唯一索引不带 `deleted` 就会「删了还撞键」

删掉的记录还在表里，所以 `UNIQUE KEY (code)` 会挡住「删掉再建同名」。症状是接口报 `Duplicate entry`，前端提示「XX 已存在」，但用户明明已经删了。

所有唯一索引都必须是 `(业务列, deleted)`。批量修复脚本：`sql/system/20261106_01_zhiwei_system_fix_unique_index.sql`（6 张 system 表）+ `sql/base/20261106_02_zhiwei_base_join_uk_with_deleted.sql`（关联表）。详见第 3 章第七节。

## 19. 操作日志表一直是空的，但服务一切正常

引了 security starter 的服务会自动注册操作日志拦截器，**但前提是它自己提供了 `OperateLogWriter` 实现**。没提供时 `ObjectProvider.getIfAvailable()` 返回 null，`OperateLogAutoConfiguration` 直接不注册拦截器——功能降级，服务照常启动，不会报错。

所以新服务要记操作日志，得自己写一个 Writer（参考 `SystemOperateLogWriter` / `InfraOperateLogWriter`），不加就等于没开，不是框架漏了。

## 20. JWT 签名密钥只有代码里的默认值，没有任何配置覆盖

`SecurityAutoConfiguration` 里：

```java
@Value("${zhiwei.security.jwt.secret:zhiwei-cloud-default-secret-key-change-in-production!!}")
private String jwtSecret;
```

三个服务的 12 个 `application*.yml` 全部 grep 过 `jwt` / `security` / `secret`——**一处都没有**，Nacos 里的 dev 配置也是空的。也就是每次启动都落在这个默认值上。

后果：仓库是公开的，知道这串字符就能自己签一个任意 `userId` 的 token 直接调接口。生产环境必须用环境变量 / Nacos 覆盖这个 key，别指望代码里的提示语（`change-in-production`）会自动生效。

## 21. 「未登录访问健康检查返回 401」是旧结论，现在应该是 200

早期实测三个服务未登录 curl 健康接口都返回 401，据此写了「401 说明服务活着」。但 `8e7e93b`（11-01）起 `SecurityAutoConfiguration` 就有白名单，`/api/system/health`、`/api/infra/health` 都是 `permitAll()`，无 Token 的 `JwtAuthenticationTokenFilter` 也直接放行 → 正确结果是 **200 + JSON**。

再看到 401，先怀疑跑的是旧编译产物（`target/classes` 没重建，见坑 #13、#15），别当成正常现象。详见第 2 章第五步、第 5 章第十一节。
