## 概念卡

### 数组下标与循环边界（越界的来源）

- 是什么: 长度 7 的数组，合法下标是 0..6。循环条件写 `i <= b`（b = length）时 `i` 会取到 7。
- 为什么: 一旦循环体里出现 `a[i+1]`，下标需求比"遍历一遍"多一格，所以循环的上界必须**留一格**：`i < a.length - 1`。
- 关键机制: 越界不是"值算错了"，是根本不允许读那个位置——`ArrayIndexOutOfBoundsException: Index 7 out of bounds for length 7`。
- 最小示例: 单层循环里写 `i <= a.length` 且访问 `a[i+1]`，必崩。
- 我的理解偏差: 用户以为 `i <= b`（b 是长度）就是"从头到尾"，没意识到 b 本身已经不是合法下标了；IDEA 报的 `'if' 语句具有空体: 6` 被忽略。
- 待验证: 把边界改成 `i < a.length - 1`，确认不再抛异常，且每轮结束打印数组看最大值"沉"到末尾。

### 两个变量的值互换（为什么需要临时变量）

- 是什么: 想把 `a[i]` 和 `a[i+1]` 换个位置，直接 `a[i] = a[i+1]; a[i+1] = a[i];` 不行。
- 为什么: 第一句赋完，`a[i]` 原来的值就被覆盖了，第二句赋回去的是刚写进来的同一个值，两格变成一样。
- 关键机制: 交换需要第三个"暂存"位置先把其中一个原值存起来——这就是临时变量的全部作用。
- 最小示例: 拿三个杯子想：A 装满水、B 装满油，想对调必须借第三个空杯。
- 我的理解偏差: 用户这版代码里连交换都没写出来，属于"知道要换、不知道用什么换"。
- 待验证: 自己用临时变量写一次交换，在交换前后各打印一次数组。

### 内外层不能共用同一个循环变量

- 是什么: 外层 `for (int i = 0; ...)` 里面又写 `for (; i <= b - 1; i++)`，两层用的是同一个 `i`。
- 为什么: 内层唯一能做的是把 `i` 一直加到 `b-1`；回到外层做 `i++` 时，`i` 已经基本到顶了，外层条件立刻不成立——**外层等于只跑了一趟**，"控制趟数"这个功能当场失效。
- 关键机制: 每层循环需要一个自己的计数器；习惯写法是外层 `i`、内层 `j`。内层用 `int j = 0` 重新起算，外层 `i` 就不会被动。
- 最小示例: 跑一遍看输出：`从大到小的顺序是: 5` / `15 12` / `12 52` / `52 33` / `33 54`——每行只吐一个交换快照，说明只走了一趟。
- 我的理解偏差: 用户照"原来那层循环当内层"的指示照做了，但把原来那层里的变量名 `i` 一起留下了；根源是给提示时没点明"换变量名"，见易错点最后一条。
- 待验证: 换成外层 `i`、内层 `j`，看打印出的趟数是否变成 6 趟。

### while 循环（与 for 的分工）

- 是什么: `while (条件) { 循环体 }`——只有条件，没有"初始化"和"每轮递增"那两格；这两件事得自己在外面/里面写。
- 为什么: 循环次数的决定方式不同。次数已知（遍历数组）用 `for`；次数要看情况才知道（一直扫到某趟没有交换）用 `while`。
- 关键机制: `for (int i=0; i<n; i++)` 与 `int i=0; while (i<n) { ...; i++; }` 等价——**递增必须自己补**，不补就死循环。
- 最小示例: `int i = 0; while (i < 3) { System.out.println(i); i++; }` 打印 0 1 2；把 `i++` 删掉就无限打印 0。
- 机制归属: 这里只记录「问过、给了什么」，循环机制的系统讲解在 [Java-控制流](../Java-控制流/Java-控制流.md)（那边有 for 三段式与执行顺序），本主题不重复维护同一份机制说明。
- 变体: `do { ... } while (条件);` 先执行一次再判断，**末尾有分号**，适合"至少要试一次"的场景（如读取直到成功）。
- 我的理解偏差: 用户把 while 当成 for 的另一套写法在问，还没把它和冒泡排序里"要不要提前结束"联系起来。
- 待验证: 用 while + 一个 `boolean` 开关写"某趟一次交换都没发生就跳出"，看能否少跑几趟。

### 冒泡排序为什么要两层循环

- 是什么: 内层负责"相邻两两比较、把当前最大的往后顶"；外层负责"这件事重复几轮"。
- 为什么: 一趟走完只保证**一个**元素到位（最大的那个）。7 个数要几趟才全有序？——这是留给用户推的问题。
- 关键机制: 外层第 k 趟结束后，末尾 k 个元素已经是有序的；所以内层上界可以每趟缩小 k，这就是"提前结束/优化"的入口。
- 最小示例: 暂无（等用户自己写出来再补）。
- 我的理解偏差: 用户一版里只有一层循环，还没意识到"一趟不够"。

## 易错点

- **症状**：编译/运行时 `ArrayIndexOutOfBoundsException: Index 7 out of bounds for length 7`。**原因**：循环写 `i <= b` 又访问 `a[i+1]`。**做法**：上界留一格，`i < a.length - 1`。
- **症状**：IDEA 警告 `'if' 语句具有空体: 6`。**原因**：`if (条件)` 后面直接跟 `;`，或没写 `{}` 导致 println 落在 if 外面。**做法**：`if (cond) { ... }` 永远带花括号。
- **症状**：交换后两格值相同或数组越来越怪。**原因**：直接连续赋值覆盖了原值。**做法**：借用临时变量。
- **症状**：只有一层循环，数组永远排不完。**原因**：一趟只能让一个元素到位。**做法**：外层再套一层，控制趟数。

- **症状**：外层循环看起来套上了，但实际只跑一趟（输出只有 5 行、每行一个数）。**原因**：内外两层共用同一个循环变量，内层把它加到顶，外层条件立刻失效。**做法**：外层 `i`、内层 `j`，变量名分开。
- **症状**：要求从大到小，结果是从小到大（或反之）。**原因**：`if (a[i] >= a[i+1])` 配"把右边换到左边"，等价于把大的放后面 = 升序。**做法**：降序用 `if (a[i] < a[i+1])`（小的换到前面）。
- **症状（第五版，IDEA 两条提示原文）**：第 7 行 `条件 'j < b' 始终为 'true'` + 第 15 行 `数组索引超出范围`。**原因**：内外层变量**角色写反**——外层用了 `j`、内层用了 `i`；外层条件 `j < b` 里 `b = a.length` 是定值 7、`j` 只会变大，永远成立（外层死循环）。**做法**：内部计数器（决定"走完整个数组"的那个）永远写在最内层的 `for (int j = 0; ...)` 里；外层计数器只比较"趟数"。
- **症状**：`int i = 0;` 写在两层循环外面。**原因**：内层计数器一旦放在循环外，就跑完一趟后停在上限、下一趟不再从 0 重新走（而外层却继续执行）。**做法**：内层计数器的声明+初始化必须写在内层 `for` 的括号第一段里，每趟自动重置。
- **症状**：文案写「从小到大」，结果却是降序（或反之）。**原因**：`if (a[i] >= a[i+1])` + 把右边换到左边 = 大的往后走 = 升序；想升序就该用 `>`（左边更大才换），想降序才用 `<`。**做法**：先定文案，再按文案选比较符号，两者必须配套。
- **症状（用户第三版实测）**：`Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 7 out of bounds for length 7`，`at test.main(test.java:7)`（第 7 行 = `if (a[i] >= a[i+1])`）。**原因**：内外两层共用变量 `i`。内层把 `i` 顶到 6，回外层 `i++` 变 7，而外层上界也写成 `<= b-1`，7 仍然进了判断 → `a[i+1]` = `a[8]`（先撞 `a[7]`）。**做法**：两层变量分开（外 `i`、内 `j`），且凡要访问 `a[j+1]`，内层上界一律写 `j < a.length - 1`。
- **症状（第七版，内层上界差 1）**：内层写 `for (int j = 0; j <= b - 1; j++)` 却访问 `a[j+1]`。**原因**：j 最大取到 6（b-1），`a[j+1]` 就是 `a[7]`，len=7 的下标只到 6。**做法**：凡循环体访问 `a[j+1]`，条件必须收在 `j < b - 1`（等价 `j <= b - 2`）；只有访问 `a[j]`、不碰 `a[j+1]` 的循环才能写到 `j <= b - 1`。
- **症状（第八版实测）**：运行后只打出「从小到大的顺序是: 」，紧接着 `ArrayIndexOutOfBoundsException: Index 7 out of bounds for length 7`，`at test.main(test.java:8)`。**原因**：文案在第 5 行、循环之前打印，所以它一定先出现；数字在循环体内打印，而异常发生在第 8 行 `a[j+1]`（j=6 时取 `a[7]`），数字一个都没打出来。**做法**：看到"文案有、数字没有"，先看异常堆栈的行号——问题在打印循环体的那一行，不在打印语句本身。
- **提示方的错（负责记录，不只是用户的坑）**：给 L2 时说"原来那层 for 当成内层留着，一行都别改，除了右边界"——把"变量名要换"漏了，直接导致用户写出内外同名的 `i`，外层失效。以后同类指示必须写清"变量名也要换"。
