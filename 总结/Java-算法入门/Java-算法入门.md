## 概念卡

### 数组下标与循环边界

- 是什么: 长度 7 的数组合法下标是 0..6。循环条件写 `i <= length` 时 `i` 会取到 7。
- 关键机制: 循环体里一旦访问 `a[i+1]`，上界必须**留一格**：`i < a.length - 1`。越界不是值算错，是那个位置根本不允许读。
- 坑: 以为 `i <= b`（b 是长度）就是"从头到尾"，忘了 length 本身不是合法下标。

### 两个变量的值互换

- 是什么: 直接 `a[i] = a[i+1]; a[i+1] = a[i];` 换不了。
- 关键机制: 第一句赋完原值就丢了，第二句把刚写进去的值再赋回去，两格变成一样。必须借第三个变量暂存。
- 最小示例: 三个杯子——A 装水、B 装油，对调必须借第三个空杯。

### 内外层不能共用同一个循环变量

- 是什么: 外层 `for (int i = 0; ...)` 里又写 `for (; i <= b - 1; i++)`，两层同一个 `i`。
- 关键机制: 内层把 `i` 加到顶，回外层 `i++` 后条件立刻不成立，**外层只跑一趟**，"控制趟数"当场失效。每层要各自的计数器：外 `i`、内 `j`。
- 坑: 内层用 `int j = 0` 时，声明必须写在内层 `for` 的括号第一段里，否则跑完一趟停在上限、下一趟不重置。

### 冒泡排序为什么要两层循环

- 是什么: 内层"相邻比较、把当前最大的往后顶"，外层"这件事重复几轮"。
- 关键机制: 一趟只保证**一个**元素到位。n 个元素要 n-1 趟——最后一趟只剩一个元素、天然有序，多跑一趟是白跑。

### while 与 for 的分工

- 是什么: `while (条件)` 只有条件，起点和递增都得自己写。
- 关键机制: `for (int i=0; i<n; i++)` 等价于 `int i=0; while (i<n) { ...; i++; }`——**递增不补就是死循环**。次数已知用 `for`，次数要看情况（某趟没交换就停）用 `while`。
- 变体: `do { ... } while (条件);` 先执行一次再判断，末尾有分号。
- 机制的系统讲解在 [Java-控制流](../Java-控制流/Java-控制流.md)，本主题不重复。

## 易错点

- **越界** `ArrayIndexOutOfBoundsException: Index 7 out of bounds for length 7` → 循环写 `i <= b` 又访问 `a[i+1]`。上界留一格：`i < a.length - 1`。
- **内层上界差 1** → `for (int j = 0; j <= b - 1; j++)` 却读 `a[j+1]`，j=6 时读 `a[7]`。凡访问 `a[j+1]`，条件必须 `j < b - 1`。
- **交换后两格相同** → 连续赋值覆盖原值。借临时变量。
- **外层只跑一趟**（输出只有几行、每行一个数）→ 内外层共用变量。外 `i`、内 `j` 分开。
- **排序方向反了** → `a[i] >= a[i+1]` 配"右边换到左边"是升序；降序要用 `a[i] < a[i+1]`。先定文案再选符号。
- **`if` 语句空体** IDEA 警告 → `if (条件)` 后直接跟 `;` 或没写 `{}`。永远带花括号。
- **"文案有、数字没有"** → 先看异常堆栈行号。文案在循环前打印，所以一定先出现；数字在循环体里，异常发生在更后面。

**选择题**

1. `int[] a = {5,15,83,12,52,33,54};` 循环体里要比较相邻两个元素 `a[i]` 和 `a[i+1]`，`i` 的上界应该写成什么？
   - A. `i <= a.length`
   - B. `i <= a.length - 1`
   - C. `i < a.length - 1`
   - D. `i < a.length`
   - 答案: C
   - 判定: C。长度 7 的数组合法下标是 0..6。体内要读 `a[i+1]`，`i` 最大只能到 5（此时读 `a[6]`），所以条件是 `i < 6`，也就是 `i < a.length - 1`。A 让 i 取到 7，直接越界。B 让 i 取到 6，体内 `a[i+1]` 就是 `a[7]`，同样越界。D 也让 i 到 6，一样崩。
   - 踩坑场景: 运行报 `ArrayIndexOutOfBoundsException: Index 7 out of bounds for length 7`，盯着报错行看不出问题——其实是循环上界多了 1。

   **术语**

   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | 越界 | 访问超出合法下标范围的数组元素 | 去不存在的房间敲门 |
   | 合法下标 | 0 到 length-1 之间的整数下标 | 房间里真实存在的门牌号 |
   | 上界留一格 | 体内用到 `a[i+1]` 时循环上限少算一格 | 走到倒数第二间就停 |

2. 想把 `a[i]` 和 `a[i+1]` 换个位置，直接写 `a[i] = a[i+1]; a[i+1] = a[i];` 会怎样？
   - A. 正常交换了
   - B. 两格都变成原来 `a[i]` 的值
   - C. 两格都变成原来 `a[i+1]` 的值
   - D. 抛出异常
   - 答案: C
   - 判定: C。第一句把 `a[i]` 覆盖成 `a[i+1]` 的值，`a[i]` 的原值当场丢失；第二句把刚写进去的那个值再赋回 `a[i+1]`，于是两格一样，都是原来的 `a[i+1]`。A 错，中间没有暂存，换不了。B 正好反了。D 错，下标合法，不会抛异常，只是结果错了。
   - 踩坑场景: 交换写完数组越排越怪，还以为是比较逻辑写反了。

   **术语**

   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | 临时变量 | 交换时先存一个原值的第三个变量 | 借一个空杯子 |
   | 覆盖 | 给变量赋新值，原值被冲掉 | 倒掉杯子里的旧水 |
   | 三杯水 | 交换两个值的经典比喻：A 水、B 油要换必须借第三个空杯 | 没有空杯就换不了 |

3. 外层 `for (int i = 0; ...)`，内层写成 `for (; i <= b - 1; i++)` 共用同一个 `i`，实际会发生什么？
   - A. 正常嵌套，跑完所有趟
   - B. 内层把 `i` 加到上限，回外层做 `i++` 后外层条件立刻不成立，外层只跑一趟
   - C. 编译报错，循环变量不能重复使用
   - D. 内层一次都不执行
   - 答案: B
   - 判定: B。内层结束时 `i` 已经基本到顶，外层再做一次 `i++` 就超出条件，外层直接退出——"控制趟数"的功能当场失效，实际只走一趟。A 错，看起来嵌套了但没起作用。C 错，语法上完全合法，编译器不管你怎么用变量。D 错，内层第一趟会正常执行完。
   - 踩坑场景: 输出每行只有一个数、只有寥寥几行，以为排序算法想错了，其实外层压根没跑起来。

   **术语**

   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | 嵌套循环 | 一层循环体里再套一层循环 | 大圈里套小圈 |
   | 循环变量 | 控制循环次数和下标的那两个变量 | 两个各自记步的计数器 |
   | 趟数 | 冒泡排序外层跑了几轮 | 整体扫过几遍 |

4. 想把数组排成从小到大，相邻比较时应该用哪个条件？
   - A. `if (a[i] > a[i+1])` 然后交换
   - B. `if (a[i] < a[i+1])` 然后交换
   - C. `if (a[i] == a[i+1])` 然后交换
   - D. 用哪个都一样，只看循环写得对不对
   - 答案: A
   - 判定: A。左边比右边大才交换，大的就往右挪，每趟最大的沉到末尾，结果是升序。B 恰好反了，是降序。C 只在相等时交换，相等换不换都没变化，数组永远排不出来。D 错，比较符号直接决定升序还是降序，这是核心，不是细节。
   - 踩坑场景: 文案写"从小到大"，跑出来却是从大到小——比较符号和交换方向没配套。

   **术语**

   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | 升序 / 降序 | 从小到大 / 从大到小 | 越往后越大还是越小 |
   | 交换方向 | 谁换到谁前面，决定最终的顺序 | 大的往哪边走 |
   | 沉降 | 每趟把当前最大（或最小）送到末尾固定下来 | 最重的沉到底 |

5. 7 个元素的数组做冒泡排序，外层最多需要几趟？
   - A. 6 趟
   - B. 7 趟
   - C. 3 趟
   - D. 1 趟
   - 答案: A
   - 判定: A。每一趟保证一个元素到位，最后一趟时只剩一个元素、天然有序，所以 n 个元素要 n-1 = 6 趟。B 多跑一趟，最后一趟交换一次都不会发生，白跑。C 是二分那种不断折半的场景才有的量级，跟冒泡无关。D 只跑一趟只有一个元素到位，其余全乱。
   - 踩坑场景: 外层写 `i < b`（b = 7）跑 7 趟，结果虽然对但多跑一轮，而且下标边界容易多算一格导致越界。

   **术语**

   | 术语 | 含义 | 通俗解释 |
   |---|---|---|
   | 一趟 | 内层完整扫过一遍数组 | 完整走一圈 |
   | 到位 | 某个元素已经排到它最终该在的位置 | 站对了位置不用再动 |
   | n-1 | n 个元素排序需要的最少趟数 | 最后一个不用管 |
