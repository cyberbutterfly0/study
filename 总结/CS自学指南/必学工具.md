### 1.2 Vim

- 是什么：多模态命令行文本编辑器，很多服务器自带；通过 ssh 连远程机器、没有图形界面时也能直接开发。
- 为什么学：手指不用离开键盘，光标移动不靠方向键；文件和面板切换方便，可同时开多份文件；宏能批量处理重复操作（多行缩进、批量加引号）；插件生态丰富。
- 上手路径：先读 missing-semester 的 editors 教程（英文吃力看 vim-galore 中文版）；装完 Vim 在命令行敲 `vimtutor` 练习；然后强迫自己日常开发都用 Vim（IDE 可装 Vim 插件）；适应后再按需改 `.vimrc`；想深入配置看 _Learn Vim Script the Hard Way_。
- 坑：学习曲线陡，作者花了好几周才适应；一上来就啃花哨的高级技巧容易放弃。另外 ESC 和 CTRL 离 home row 太远，建议把 CapsLock 映射成 Esc/Ctrl（更佳做法是点按 Esc、按住 Ctrl），Windows 用 Powertoys 或 AutoHotkey，macOS 用 Karabiner-Elements，Linux 用 xremap。
- 链接：https://missing.csail.mit.edu/2020/editors/ ｜ https://learnvimscriptthehardway.stevelosh.com/ ；参考书 Practical Vim、Modern Vim（Drew Neil）

### 1.3 Emacs

- 是什么：与 Vim 齐名的可扩展编辑器，内核不对用户设限，用 Emacs Lisp 可写任意逻辑的插件；终端版和图形界面版都有。
- 为什么学：全键盘操作、大量快捷键，编辑效率高；插件生态积累几十年，说法是「Emacs 表面是编辑器，其实是一个操作系统」；有 evil 插件可直接用 Vim 的基本操作，从 Vim 迁移成本很低。
- 上手路径：读中文教程《专业 Emacs 入门》（系统全面，讲基本逻辑的同时给出成套插件推荐，读完能得到接近 IDE 的配置）；然后日常用，遇到问题勤搜勤想。
- 坑：网上 Emacs 资料大多不细致、不准确，甚至有哗众取宠的；和对 Ctrl 键用得过多，对小手指不友好，强烈建议改键位映射（方法同 Vim 教程）。学习曲线同样陡。
- 链接：https://www.zhihu.com/column/c_1440829147212279808 ｜ evil 插件 https://github.com/emacs-evil/evil

### 1.4 Git

- 是什么：分布式代码版本控制工具，Linus 嫌当时主流的中心式版本控制又难用又收费，为维护 Linux 自己写的。
- 为什么学：管理代码版本、支撑多人协作；设计优雅但内部逻辑不直观，不熟悉时很容易因误用命令把代码搞丢。
- 上手路径：missing-semester 的 version-control 教程（视频可看尚硅谷 Git 教程）→ 读 Pro Git 第 1 至 5 章 → Learn Git Branching 交互式练分支 → 在实践里反复巩固，并学怎么写 Commit Message → 想造轮子看 wyag 教程，或 build-your-own-x、project-based-learning 两个仓库。
- 坑：内部逻辑靠「熟能生巧」学不会，必须花时间理解，所以不建议一知半解就上手用；初学者最容易因误操作丢代码。
- 链接：https://git-scm.com/book/en/v2 ｜ 交互练习 https://learngitbranching.js.org/

### 1.5 GitHub

- 是什么：在线代码托管平台，把本地 Git 仓库托管上去供多人开发浏览；现在更是一个体量极大的开源社区，从 PyTorch 这类框架到几十行的脚本、乃至技术书籍都能找到。
- 为什么学：托管自己的仓库、与人协作；逛别人的项目能直接拿到可用的代码和教程；star 数是项目认可度的主要信号。
- 上手路径：没建过远程仓库就先跟 GitHub 官方教程走一遍建仓库、克隆的流程；想追新项目看 HelloGitHub（网站及同名公众号，定期收录近期流行或有趣的项目）。
- 坑：开源社区不是法外之地，很多开源软件不能随意复制、分发甚至贩卖；不了解开源协议就商用会有法律问题。
- 链接：https://docs.github.com/cn/get-started ｜ https://hellogithub.com/

### 1.6 GNU Make

- 是什么：用一份 `Makefile` 脚本描述整个编译流程，以及各目标文件与源文件之间依赖关系的构建工具。
- 为什么学：项目有成千上万个 C 源文件散在各子目录时，手工 gcc 不现实；大项目全量编译要半小时，只改一个分号也要重来，Make 只重编译受改动影响的部分。
- 上手路径：读《跟我一起写 Makefile》；之后融入日常开发，多看多模仿优秀开源项目里的 `Makefile`，总结出自己的 template。
- 坑：掌握起来相对容易，用好要不断练习，光会抄模板不理解依赖规则照样出问题。
- 链接：https://seisman.github.io/how-to-write-makefile/overview.html

### 1.7 CMake

- 是什么：类似 GNU make 的跨平台自动软件构建工具，用 `CMakeLists.txt` 定义构建规则，功能比 make 更多。
- 为什么学：各类软件构建上广泛使用，基本是 C/C++ 工程的事实标准。
- 上手路径：强烈建议先学 GNU Make、熟悉 `Makefile` 再来；看 CMake 官方 Tutorial；或看上海交大 IPADS 组约一小时的新人培训视频。
- 坑：`CMakeLists.txt` 比 `Makefile` 更抽象，理解和使用的难度都更大；Visual Studio、CLion 这类 IDE 能自动生成它，但只会点按钮不行，基本用法仍须掌握。
- 链接：https://cmake.org/cmake/help/latest/guide/tutorial/index.html ｜ 视频 https://www.bilibili.com/video/BV14h41187FZ

### 1.8 LaTeX

- 是什么：基于 TeX 的排版系统，LaTeX 由 Lamport 开发、TeX 由 Knuth 开发；和所见即所得的 Word 相反，用户只管写内容，排版交给软件。
- 为什么学：写论文不学也得学；没有排版经验的人也能写出排版专业的论文和文章。
- 上手路径：本地环境配不好就用 Overleaf 在线编辑（自带模板，免配环境）→ 读 Overleaf 的 Part-1/2/3 三篇教程 → 最好的练法是写论文，退一步从一门数学课用它写作业开始。补充读物：lshort-zh-cn、TEX Live 指南、刘海洋《LaTeX 入门》（当工具书查）、现代 LaTeX 入门讲座。
- 坑：环境配置比较头疼（页面原话），本地装不上就别硬扛，直接转 Overleaf。
- 链接：https://www.overleaf.com/latex/learn/free-online-introduction-to-latex-part-1 ｜ 中文入门 https://mirrors.ctan.org/info/lshort/chinese/lshort-zh-cn.pdf

### 1.9 Docker

- 是什么：用轻量级「容器」而不是整台操作系统来承载应用，应用连同环境配置打包成一个 image，可跑在任意平台的 container 里。
- 为什么学：用别人的软件最大的障碍是配环境，配环境的折磨会消解对编程本身的兴趣；虚拟机笨重，为单个应用模拟整个操作系统不划算，容器省掉了所有人的时间成本。
- 上手路径：读官方文档，下载桌面端先用图形界面；关键是动手用。想深入理解就自己写一个迷你 Docker；系统课看 KodeKloud 的 Docker for the Absolute Beginner（配套练习和免费云环境）。
- 坑：只看文档不动手就学不会；KodeKloud 的 Kubernetes 等云相关课程要付费（Docker 那门免费且带实验环境）。
- 链接：https://docs.docker.com/ ｜ https://kodekloud.com/courses/docker-for-the-absolute-beginner/

### 1.10 Scoop

- 是什么：Windows 下的命令行包管理器，统一安装并管理常见开发软件。
- 为什么学：Windows 下搭开发环境没有统一标准，各家安装方式差异巨大；Scoop 省掉手动下载、配环境变量这些步骤，`scoop install python`、`scoop install nodejs` 就能装好。
- 上手路径：确认有 PowerShell 5.1+（Win10 及以上自带）→ `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` → `irm get.scoop.sh -outfile 'install.ps1'` → `.\install.ps1 -ScoopDir 'C:\Scoop'`；之后照官方文档或 Quick Start 用。
- 坑：中文用户名会让用户目录也变中文，按默认方式装到用户目录可能造成部分软件执行错误，所以要用 `-ScoopDir` 装到自定义目录；没有镜像源（软件都从官方链接下载），网络差会反复失败；Java8、python2 已被移出 Main，需 `scoop bucket add versions` 再装。
- 链接：https://github.com/ScoopInstaller/Scoop/wiki/Quick-Start ｜ 安装说明 https://github.com/ScoopInstaller/Install

### 1.11 日常学习工作流

- 是什么：一篇由 @HardwayLinka 投稿的个人工作流复盘，核心是用双链笔记（Obsidian）+ 一套剪藏、转换、翻译、复习工具，把碎片知识收进自己的知识库。
- 为什么学：知识来源复杂细碎（文档手册、博客、新闻），更新又快，需要一套流程把网页、论文、电子书、课程整合起来方便查阅复习。
- 上手路径：先接受信息源可信度排序 源代码 > 官方文档 > 英文书籍 > 英文博客 > 中文博客；笔记选 Obsidian（本地、Markdown、插件生态活跃）；网页剪藏用简悦，mobi/azw3 等格式用 calibre 转 pdf；跨端收藏用 Cubox，个人小站用 RSS（RSSHub Radar 发现源 + Feedly 订阅）；划词翻译用 Quicker + 沙拉查词；英文视频用 Language Reactor 导字幕、Media Extended 在笔记里跳转到视频时间点、Annotator 跳转到 pdf 原文；复习用 Obsidian 的 Anki 插件做间隔重复卡片。
- 坑：作者的原话是不要为了虚无的满足感把工具硬拼进自己的工作流；另外 N 手资料有信息损失，也容易有错，不能只靠中文博客。
- 链接：https://obsidian.md/（全流程的核心工具）

### 1.13 毕业论文

- 是什么：不是工具，是作者 2022 年本科毕业后写的 Word 写毕业论文经验，附北大研究生学位论文写作指南和自己做的模板。
- 为什么学：多数人对 Word 的掌握只到调字体、保存导出，一到格式要求就卡住；作者当年就是硬扛过来的，所以整理了这份开箱即用的文档。
- 上手路径：三步——先拿到学院的格式要求和模板（学院没给就参照北大研究生论文格式要求，作者按其要求做了模板可直接取）；再花半小时学够用的 Word 排版（有模板就学用模板，没模板就学做模板），别去啃十几小时的教学视频；最后动笔写。
- 坑：作者学院的模板格式混乱、几乎毫无用处；论文段落格式用 Word 调比转 LaTeX 更方便，所以别盲目为了排版上 LaTeX。
- 链接：https://github.com/PKUFlyingPig/Thesis-Template（含写作指南 pdf 与模板 docx）

### 1.14 信息检索

- 是什么：把搜索引擎当数据库来用的查询技巧合集，外加本地与开源代码搜索工具；前提是编程靠 STFW（search the web）和 RTFM（read the manual）。
- 为什么学：碰到问题的第一件事是翻文档和 FAQ，而不是直接搜索或找人问；搜得准能直接省掉大量时间。
- 上手路径：优先用英文搜（英文资料质量高、名词准确，中文分词还容易出歧义）→ 把问题提炼成关键词，别搜整句（`vcpkg 集成到 工程 全局` 而不是长句）→ 搜不到就换同义词（工程→项目）→ 上高级语法：`"线性代数"` 精准匹配、`-词` 排除、`+词` 包含、`filetype:pdf`、`site:stackoverflow.com` → GitHub 用 `in:name` / `in:readme` / `stars:>100` / `language:java` / `user:` 等，或直接用高级搜索页 → 找代码用 ack、The Silver Searcher、The Platinum Searcher 或 Searchcode。
- 坑：整句和过于具体的问题，机器分词更可能出错；中文搜索分词不准会搜不出东西；百度排序差但中文收录比 Bing 多，中文问题确实找不到时反而该用它；知乎、简书、CSDN 的中文笔记是别人嚼过的，正确率不保证。
- 链接：https://github.com/search/advanced ｜ 搜索引擎原理 https://zhuanlan.zhihu.com/p/301641935
