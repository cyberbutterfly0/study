### #1 在一堆文件里搜某个字符串

- 问: 我想在一整个文件夹的文本文件里找某个字符串，Windows 自带怎么搜？
- 结论: 用 PowerShell 的 `Select-String`，比资源管理器搜索快且能只搜指定类型。
- 步骤:
  1. 打开 PowerShell，`cd` 到目标目录（或直接在命令里写全路径）。
  2. 只搜某种文件：`Get-ChildItem -Recurse -Filter *.md | Select-String -Pattern '要找的词'`
  3. 要显示行号：加 `| Select-Object Path,LineNumber,Line`
  4. 要忽略大小写（默认就忽略）或区分大小写：`Select-String -CaseSensitive`
- 为什么: 资源管理器的搜索走索引服务，内容索引常常没开，所以"明明有却搜不到"；`Select-String` 是直接读文件内容，不依赖索引。
- 坑:
  - `-Filter` 只能给一个模式，多类型用 `-Include *.md,*.txt` 配合 `-Recurse`。
  - 中文内容乱码时，先确认文件本身编码；`Select-String` 按默认编码读，老 GBK 文件可能匹配不上。

### #2 在 IntelliJ IDEA 里新建 Java 文件

- 问: 我应该怎么样在 idea 里面建立 java 文件（截图里右键"新建"已经展开了）
- 结论: Java 没有单独的"新建 .java 文件"，**Java 类**那一项就是它——IDEA 会顺带把包声明和 public class 骨架一起生成。
- 步骤:
  1. 在左侧项目视图里选中**蓝色的源码目录**（一般是 `src/main/java`）或它下面的某个包，右键 → 新建(N) → Java 类。
  2. 输入的类名**不带 `.java` 后缀**，首字母大写（如 `UserService`），回车。
  3. 弹窗上方可选 Kind：Class / Interface / Enum / Record / Annotation，按需要挑。
  4. 编辑器里光标在任意位置时，按 `Alt + Insert` 是同一个菜单，不用回左侧右键。
- 为什么: IDEA 是按"包结构 = 目录结构"管理 Java 的，只有被标记为 Sources Root（蓝色）的目录才允许新建类，文件名与 public 类名必须一致。
- 坑:
  - 菜单里**没有"Java 类"**：目录不是蓝色 → 右键该目录 → Mark Directory as → Sources Root；仍是灰色则模块没配 JDK → File → Project Structure → SDKs。
  - `Ctrl + Shift + Alt + Insert` 建的是**临时文件（scratch）**，不落进项目目录，别拿它当正式代码。
  - Kotlin 项目默认把"Kotlin 类/文件"放前面；Maven 模块先把 `src/main/java` 目录建出来再标记 Sources Root。
- 相关: [Java-集合框架](../Java-集合框架/Java-集合框架.md)（这是"工具怎么用"，不等于会写 Java，概念问题走那边）

### #3 git 下来的空 Java 项目怎么起步

- 问: 这是我从云端 git 下来的未开始项目（tcm-admin），我应该怎么样开启编写
- 结论: 四步——判断项目类型（看根目录有没有 `pom.xml` / `build.gradle`）→ 配 JDK → 建 `src/main/java` 并标记 Sources Root → 建第一个类按 `Ctrl+Shift+F10` 跑起来。
- 步骤:
  1. 先看仓库根：有 `pom.xml` 是 Maven，有 `build.gradle(.kts)` 是 Gradle，都没有就是**裸 Java 模块**。你截图里 `tcm-admin.iml` 写的是 `type="JAVA_MODULE"`、`<orderEntry type="inheritedJdk" />`，属于最后一种。
  2. Maven/Gradle 项目：右键 `pom.xml` → Add as Maven Project（或右侧 Maven 面板 → Reload All Maven Projects）；裸模块跳过这步。
  3. File → Project Structure → Project：SDK 选 JDK，Language level 跟 SDK 对齐（版本看 README）。
  4. 建 `src/main/java`（测试再加 `src/test/java`），右键 → Mark Directory as → Sources Root / Test Sources Root，目录变蓝。
  5. 在蓝色目录下右键 → 新建 → Java 类，包名填 `com.xxx.yyy`，写个 `main`，`Ctrl+Shift+F10` 运行。
  6. 写完提交：左下 Git 面板 → Commit → Push。
- 为什么: IDEA 靠"被标记为 Sources Root 的目录"决定哪些 `.java` 参与编译、靠项目 SDK 决定用哪个 javac，这两样没配好，写多少都编译不了。
- 坑:
  - **git 不跟踪空目录**：刚建好的 `src/main/java` 是空的，`git commit` 根本不会记录它，队友 pull 下来看不到这个结构。要么紧接着在里面建第一个类再提交，要么放一个 `.gitkeep` 占位文件。
  - **先读 README**，怎么初始化、要哪个 JDK 版本一般写在那儿。
  - 没标记 Sources Root：类会建到模块根目录，或 `.java` 图标变灰不被识别。
  - Maven 依赖拉不下来：Settings → Build Tools → Maven → settings.xml 换国内镜像。
  - `.idea/` 和 `.iml` 通常该在 `.gitignore` 里，别随手提交。
- 相关: [#2 新建 Java 类](#item-2)
- 回: [↑ 速查表](#速查表)

### #4 团队 git 项目怎么开始写代码（阿里云 Codeup）

- 问: 这是我要和别人一起编写的项目，云端管理是阿里云 Codeup（仓库 tcm-admin），怎么开启编写
- 结论: 协作仓库不能直接往 master 推。顺序是：动手前先 pull → 配置类文件排除出仓库 → 在自己的分支上写 → push 自己的分支 → 在 Codeup 网页发**合并请求**合回 master。
- 步骤:
  1. 动手前先更新：IDEA 里 `Ctrl + T`（或命令行 `git pull`），保证起点是云端最新。
  2. 在自己的分支上写：这个仓库已有 `yzc` 分支（每人一个），`git checkout yzc` 后就在它上面改；新功能可以再开 `git checkout -b yzc-功能名`。
  3. 把 IDE 配置排除出仓库：`.idea/`、`*.iml` 加进 `.gitignore`（这个仓库的 `.gitignore` 是 Java 标准模板，**没忽略这两样**，不排除每次提交都得手动取消勾选）。
  4. 写代码 → `Ctrl + K` 提交 → `Ctrl + Shift + K` 推送 → 到 Codeup 网页发合并请求合回 `master`。
  5. 合并前再 pull 一次，冲突在自己的分支里解决。
- 为什么: master 是公共区域，直接推会打断别人；"分支写 + 合并请求合"把改动和合并分开，出问题能整体退回。
- 坑:
  - **`git status` 里有 `D 某文件` 时不要顺手 commit**——推上去等于删掉别人提交的文件。要删先在群里说。
  - 误删了怎么恢复：`Ctrl + K` 打开**提交面板** → 在"更改"列表里**右键那个文件 → Rollback**；命令行等价 `git restore --staged --worktree 文件名`（`--staged` 把删除从暂存区撤出，`--worktree` 把磁盘上的文件补回来）。注意 `Alt + 9` 打开的是 Git **日志**窗口，那里没有 Rollback。
  - 「仓库差异 / diff」窗口（双击提交里的文件打开的）**只能看历史内容，不能把文件"导入"回工作区**，恢复必须走上面的 Rollback 或命令。
  - 这个仓库的 remote 是 SSH 形式 `git@codeup.aliyun.com:...`，换机器要在 Codeup 个人设置里重新配公钥；用 HTTPS 则要配"克隆密码"。
  - Codeup 自动生成的 README（"3 分钟了解如何进入开发"）**不是项目说明**，项目结构得跟队友口头约定。
  - 仓库根目录直接放 `.java`（默认包）不合 Java 规范，正规是 `src/main/java/<包名>/` 再标记 Sources Root。
- 相关: [#3 空项目起步](#item-3)

### #5 把代码提交并推送到阿里云 Codeup

- 问: 代码在 IDEA 里写好了，怎么提交 git 到阿里云平台
- 结论: 提交面板**只勾要提交的源码** → 填提交消息 → 点「**提交并推送**」→ 推自己的分支 → 到 Codeup 网页发**合并请求**合回 master。
- 步骤:
  1. 先把 IDE 噪音挡掉：根目录 `.gitignore` 追加 `.idea/`、`*.iml`、`out/`（这个仓库的 .gitignore 是 Java 标准模板，这三样都没忽略）。
  2. `Ctrl + K`（或 `Alt + 9`）打开提交面板，只勾要提交的源码；**取消勾选** `.idea/`、`*.iml`、`out/`，以及状态是"删除"却不是你真想删的文件。
  3. 填提交消息（不能空），写清改了什么。
  4. 点左下角「**提交并推送**」；如果只点了「提交」，再按 `Ctrl + Shift + K` 推送。
  5. 推送对话框里确认目标是 **origin/自己的分支**（如 `yzc`），**别选 master**，点 Push。
  6. **只想让自己分支更新到云端**的话，到第 5 步就结束了；要合进主线再往下：到 Codeup 网页 → 「合并请求」→ 新建：源分支 `yzc` → 目标分支 `master`。
- 为什么: 提交（commit）只写本地仓库，推送（push）才上云端；先推自己的分支再走合并请求，master 始终保持在别人也能用的状态。
- 坑:
  - **提交落在"当前所在的那个分支"上**，不一定是你以为的分支。推之前先看 IDEA 右下角状态栏（或顶栏）的分支名——截图里是 `yzc`；在 master 上提交后直推推不动，在别人分支上提交等于把改动塞进别人的分支。
  - 提交面板**可能默认勾着"删除"状态的文件**（`D xxx`），不看清单就推 = 删掉队友的文件（这个仓库的 `test.java` 差点被这么删掉）。
  - `out/` 里是编译出的 `.class`，绝不能提交。
  - 提交消息为空会红字提示"指定提交消息"，提交不了。
  - 推送被拒（`non-fast-forward`）说明云端自己分支有别人的新提交，先 `Ctrl + T` 拉再推。
  - 命令行等价：`git add 文件` → `git commit -m "消息"` → `git push origin 分支名`。
- 相关: [#4 团队 git 项目起步](#item-4)
- 回: [↑ 速查表](#速查表)

### #6 VS Code 和 STM32CubeMX2 的 AI 助手在哪、怎么接

- 问: 我开发用 VS Code + STM32CubeMX2 1.1.1，这两个的 AI 接口在哪、怎么接？
- 结论（先看这段就够）:
  - **CubeMX2 里有，开箱可用**：内建的 **STM32 Sidekick**（1.1.0 起集成），Home 页右侧的按钮，问的是"官方文档怎么说、这个配置什么意思、引脚冲突没"这类知识问题。它**不写代码**。
  - **VS Code 里现在没生效**：你装的那个 `DeepSeek V4 for Copilot Chat` 只是"换模型的补丁"，宿主 `GitHub Copilot Chat` 没装，聊天面板都打不开，所以它现在是空转。
- 步骤 A：把 VS Code 的 AI 接上（二选一）
  - A1，走 Copilot 免费额度（推荐，和现有扩展配套）
    1. `code --install-extension GitHub.copilot --install-extension GitHub.copilot-chat`
    2. VS Code 左下角账号登录 GitHub，等 Copilot 状态变成可用
    3. `Ctrl + Alt + I` 打开 Chat，在模型选择器里选 DeepSeek，按扩展提示填 DeepSeek 的 API key 和模型名
  - A2，不碰 Copilot（更省事，按量付费）
    1. 装 **Continue** 或 **Cline** 扩展，它们直接吃 API key，不依赖订阅
    2. 设置里选 DeepSeek 作为 provider，填 API key，模型填 `deepseek-chat`
    3. 效果是同一个：一个能读写你工程的 AI 聊天框
- 步骤 B：用 CubeMX2 的 Sidekick
  1. 打开 CubeMX2 → Home 页右侧的 Sidekick 按钮（1.1.x 界面里就叫 Sidekick）
  2. 用 ST 账号登录（不登录功能受限，而且它有每日提问次数上限）
  3. 提问要带全型号和场景，例：「STM32F103C8T6 用 TIM2 输出 4 路 50Hz PWM，推荐怎么配」
  4. 它会给你一段摘要 + 官方文档链接，按链接回原文核对
- 为什么 A1/A2 二选一: 两者都是"VS Code 里的对话式 AI"，区别只在宿主。Copilot 那条路免费额度有限、配置多一步；Continue/Cline 那条要自己管 API key，但没有订阅门槛。学习期用 A2 更干净。
- 坑:
  - `DeepSeek V4 for Copilot Chat` 单独装是**不工作的**，必须配 Copilot Chat 宿主；装完先确认左侧活动栏出现 Copilot 图标。
  - Sidekick 给的是文档摘要，**不是正式答复**，涉及时序和电气参数一律回数据手册核对。
  - VS Code 支持 MCP（`.vscode/mcp.json`）可以喊 AI 去调编译、串口、烧录工具；有个第三方 `vscode-cube-mcp` 能包装 CubeMX 命令行让 AI 改 `.ioc`，但它按旧版 CubeMX 6.x 写的，**对 CubeMX2 是否兼容没验证**。
  - 学习阶段别先上自动化。先自己会配、会看现象，再让 AI 提速。
- 相关: [#3 空项目起步](#item-3)

### #7 把云端仓库克隆（clone）到本地

- 问: 怎么把这个项目导入本地？在 PowerShell 里敲 `git git@codeup.aliyun.com:.../zhiwei-cloud.git` 报 `is not a git command`
- 结论: 地址前面必须跟 `clone` 子命令——`git clone <仓库地址>`。你那条是把 URL 直接当成了 `git` 的子命令。
- 步骤:
  1. 在要放项目的父目录开终端（例如 `E:\study`）。
  2. `git clone git@codeup.aliyun.com:5f10495a6207a1a8b17f5729/study/zhiwei-cloud.git`，会在当前目录生成 `zhiwei-cloud` 文件夹。
  3. `cd zhiwei-cloud`，`git status` 或 `git branch -a` 确认分支。
  4. IDEA 打开：File → Open 选这个文件夹；或 File → New → Project from Version Control 直接粘地址让 IDEA 自己 clone。
  5. 打开后按 [#3](#item-3) 配 JDK、建源码目录。
- 为什么: 仓库地址只说明"东西在哪"，`clone` 才是"下载并建好本地 `.git`"的动作。`git@主机:路径` 是 SSH 地址走密钥认证，`https://...` 是 HTTPS 地址走账号/克隆密码。
- 坑:
  - `git` 后面必须跟子命令（clone / pull / push / status…），漏了就是 `is not a git command. See 'git --help'`。
  - `Permission denied (publickey)`：Codeup 账号没配 SSH 公钥，把 `~/.ssh/id_rsa.pub` 或 `id_ed25519.pub` 的内容贴到 Codeup → 个人设置 → SSH 公钥。
  - 目标目录已存在且非空会报 `destination path already exists`，换目录或先清空。
  - 克隆下来的仓库**不带 `.idea/`**，第一次打开要重新配 JDK 和源码目录，不是项目坏了。
- 相关: [#4 团队 git 项目起步](#item-4)

### #8 在 Maven 多模块工程里新建一个像 `zhiwei-module-pay` 的模块

- 问: 以 `zhiwei-module-pay` 为例，怎么搭一个这种文件夹？别人演示过但 IDEA 版本不同界面不一样
- 结论: 这不是 IDEA 特有的东西，是 **Maven 聚合模块**：一个普通目录 + 三个 `pom.xml` + 父 `pom.xml` 的 `<modules>` 里注册一行。IDEA 只是负责把它识别成模块，所以界面差异不用管——**直接复制现有模块改名**最稳，完全绕开向导。
- 结构（每层都有 `pom.xml`，三层缺一不可）:
  ```
  zhiwei-module-user/                ← 聚合层，packaging=pom，不写代码
  ├── pom.xml                          parent=zhiwei-cloud，<modules> 列下面两个
  ├── zhiwei-module-user-api/        ← 接口层，给别人依赖的 DTO / RPC 接口
  │   ├── pom.xml                      parent=zhiwei-module-user
  │   └── src/main/java/cloud/zhiwei/...
  └── zhiwei-module-user-server/     ← 实现层，Controller/Service/Mapper 都在这
      ├── pom.xml                      parent=zhiwei-module-user
      └── src/main/java/cloud/zhiwei/...
  ```
- 步骤 A：复制改名（推荐，跨 IDEA 版本都能用）
  1. 资源管理器里把 `zhiwei-module-pay` 整个目录复制成 `zhiwei-module-user`，两个子目录同步改名 `-api` / `-server`。
  2. 用编辑器批量替换三个 `pom.xml` 里的 `zhiwei-module-pay` → `zhiwei-module-user`（`<artifactId>`、`<name>`、子 pom 的 `<parent><artifactId>` 都要对上）。
  3. 打开根 `pom.xml`，在 `<modules>` 里加一行 `<module>zhiwei-module-user</module>`。
  4. 回 IDEA：右侧 Maven 工具窗口 → 点「Reload All Maven Projects」，新模块才出现。
- 步骤 B：IDEA 向导（界面随版本变，能不用就不用）
  - 新版（2022 以后）：Project 工具窗口右键项目根 → New → Module → 左侧选 **Maven** → 填名字 → Create。
  - 旧版（2019–2021）：File → New → Module → 选 **Maven** → 勾 `Create from archetype` → `org.apache.maven.archetypes:maven-archetype-quickstart`。
  - 向导生成的是**普通 jar 模块**，`<parent>` 是空的：生成后必须手改 pom，把 `<parent>` 指向 `zhiwei-cloud`、`<packaging>` 改成 `pom`（聚合层），否则版本和依赖管理全对不上。
  - 对话框里的**父项（Parent）**要选对：建和 `zhiwei-module-pay` 平级的业务模块 → 选 **`zhiwei-cloud`**（根聚合 pom），继承根 pom 的版本、依赖管理、Java 版本；选 `zhiwei-framework` 或某个 `-api` 就变成别人的子模块，结构就乱了。
  - 新版这个向导选「Java + 构建系统 Maven」只生成**单个模块**（默认 jar、带 `src/main/java`），不会像 pay 那样自动生成 `-api`/`-server` 两层；要做成三层得先建聚合层，再在它目录里 New → Module 建两个子模块。
  - 向导不一定会自动往根 pom 的 `<modules>` 里写，建完打开根 pom 手动确认/补一行。
- 步骤 C：已经建成单模块了，想改成 pay 同构的三层（整段粘进 PowerShell 跑，先备份）
  ```powershell
  $root = 'E:\study\zhiwei-cloud'
  $old  = Join-Path $root 'zhiwei-module-member'
  $new  = Join-Path $root 'zhiwei-module-member-new'

  Copy-Item $old "$old.bak" -Recurse -Force                              # 备份现有单模块
  Copy-Item (Join-Path $root 'zhiwei-module-pay') $new -Recurse -Force   # 照 pay 复制一份
  Rename-Item (Join-Path $new 'zhiwei-module-pay-api')    'zhiwei-module-member-api'
  Rename-Item (Join-Path $new 'zhiwei-module-pay-server') 'zhiwei-module-member-server'
  Get-ChildItem $new -Recurse -Filter pom.xml | ForEach-Object {          # 三个 pom 改名
      ((Get-Content $_.FullName -Raw).Replace('zhiwei-module-pay','zhiwei-module-member')) |
          Set-Content $_.FullName -Encoding UTF8
  }
  Remove-Item $old -Recurse -Force
  Rename-Item $new 'zhiwei-module-member'
  ```
  跑完回 IDEA：Maven 面板 Reload；确认根 pom 的 `<modules>` 里有 `<module>zhiwei-module-member</module>`、没有 `<module>untitled</module>`。
- 步骤 D：只用「新建」得到和 pay 一致的文件夹——结论是**新建 3 次**，一次「新建模块」只能得到一个普通模块
  - `zhiwei-module-pay` 之所以长那样，是因为它本身就是 **3 个 Maven 模块**：一个聚合层 `zhiwei-module-pay` + 两个子模块 `zhiwei-module-pay-api` / `zhiwei-module-pay-server`。没有任何一次「新建模块」能直接生成这个结构。
  - 先处理掉现有单模块：Project 窗口右键 `zhiwei-module-member` → 删除（提示时勾上删除磁盘文件）；想保险就先把目录复制到别处再删。

  | 轮次 | 右键的对象 | 名称 | 位置 | 父项 |
  |---|---|---|---|---|
  | 1 | 项目根 `zhiwei-cloud` | `zhiwei-module-member` | `E:\study\zhiwei-cloud` | `zhiwei-cloud` |
  | 2 | `zhiwei-module-member` | `zhiwei-module-member-api` | `E:\study\zhiwei-cloud\zhiwei-module-member` | `zhiwei-module-member` |
  | 3 | `zhiwei-module-member` | `zhiwei-module-member-server` | 同上 | `zhiwei-module-member` |

  - 三轮都取消勾「添加示例代码」（否则生成 `Main.java`，里面的 `IO.println` 在 JDK 21 编译不过）。
  - 第 1 轮建完（或拿现有单模块改）：打开 `zhiwei-module-member/pom.xml`，在 `<artifactId>` 后面加 `<packaging>pom</packaging>`；再删掉它的 `src` 目录——聚合层不放代码。
  - 第 2、3 轮建之前先 Reload 一次 Maven，「父项」下拉里才会出现 `zhiwei-module-member`；没有就选「无」，建完手动把 pom 的 `<parent>` 写成 `zhiwei-module-member`。
  - 每轮建完检查**上一层**的 `pom.xml`：`<modules>` 里要出现刚建的模块名，IDEA 有时不会自动写。
  - 注意第 2、3 轮的「位置」字段：IDEA 可能默认填成项目根 `E:\study\zhiwei-cloud`，必须手动改成 `...\zhiwei-cloud\zhiwei-module-member`，否则会建成和 member 平级的模块。
  - 全部建完 Reload，Project 视图应该和 `zhiwei-module-pay` 一样：聚合目录下只有 `pom.xml` + 两个子模块，源码在子模块的 `src/main/java/...`。
- 为什么分 api / server: `api` 只放别的模块要用的接口和 DTO，依赖越少越好；`server` 是重依赖的实现。这样其他模块只依赖 `-api`，不会因为依赖 `-server` 造成循环依赖。
- 坑:
  - 父 `pom.xml` 的 `<modules>` 里没加 = Maven 根本不认这个模块，IDEA 里看不到；只建目录、没建 `pom.xml` 就只是个普通文件夹。
  - 目录名要和 `<artifactId>` 对得上；子模块的 `<parent><artifactId>` 必须指到上一层的聚合模块，不然报 `Non-resolvable parent POM`。
  - 这个工程根 pom 写的是 `java.version=27` / `maven.compiler.release=27`，但 `zhiwei-module-pay` 里三个子 pom 写的是 `release 17`（archetype 模板残留），照抄时统一按根 pom 的来。**注意**：IDEA 里项目 JDK 是 21，根 pom 的 27 在 JDK 21 上编译会直接报 `invalid target release: 27`，第一次编译前要先把根 pom 的 `java.version` 改成 21 或改成项目实际装的 JDK。
  - 这三个 pom 都是 archetype 生成的空壳（`App.java` 打印 Hello World、`FIXME change it to the project's website`），说明它是脚手架不是成品；真做业务要清掉这些默认文件。
  - 改完 pom 不 Reload，新建的 `src/main/java` 不会变蓝（不被当源码目录）。
  - `.mvn/maven.config`、`.mvn/jvm.config` 是空文件，属于 archetype 默认产物，别当成配置错误。
  - `找不到模块 'untitled'`：根 `pom.xml` 的 `<modules>` 里残留了 `<module>untitled</module>`，但 `untitled` 目录已经不存在（向导新建后又删/改名留下的）。删掉那一行，再清 `.idea/misc.xml` 的 ignoredFiles 和 `.idea/compiler.xml` 里的 `module name="untitled"`，然后 Reload。不清 `.idea` 里的残留可能反复报。
  - IDEA 新版「Java 生成器」和 Maven Archetype 给的示例文件**不一样**：新版给 `Main.java`（`static void main()` + `IO.println`），Archetype 给 `App.java`（`public static void main(String[] args)` + `System.out.println`）。都是 Hello World 示例，删掉换真代码即可，不是结构错误。
  - 新版模板里的 `IO.println` 是 **Java 25** 的 API，项目 JDK 是 21 时编译不过；示例类直接删掉最省事。
  - 「我的文件夹层数比别人的多」不是建错：**单模块**的源码放在自己的 `src/main/java/包名/...` 下，Project 视图会逐层展开 `src → main → java → 包 → 类`；**聚合模块**（如 `zhiwei-module-infra`）自身不放代码，源码在 `-api`/`-server` 子模块里。这个工程的 `zhiwei-module-infra-api`/`-server` 目前连 `src` 都没有（空壳），所以看着浅；`zhiwei-module-pay-api`/`-server` 有 `src`，展开后和单模块一样深。

### #10 在 Windows 上安装 Maven

- 结论：下载官方 bin.zip 解压到 `E:\apache-maven-3.9.16`，设用户变量 `MAVEN_HOME`、把 `bin` 目录追加进用户 `Path`，重开终端验证。
- 版本：装的是 **Maven 3.9.16**（满足项目 README 的 3.9+；官方最新 3.10.0 是 2026-10 才发的，教学工程求稳用 3.9 线）。
- 本机踩到的坑（2026-10-21）：
  - `Invoke-WebRequest` 下载报 `Authentication failed, see inner exception`；`curl.exe` 报 `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS`。原因是沙箱进程拿不到 Windows 凭据，schannel 的 TLS 握手过不去，跟网络/代理无关。
  - 改用 Node 的 `https.get` 下载成功（Node 用 OpenSSL 自带 CA，不走 schannel）：`node download.js <url> <out>`。
  - 阿里云镜像 `https://mirrors.aliyun.com/apache/maven/maven-3/3.9.16/binaries/apache-maven-3.9.16-bin.zip` 能下；该镜像没有 `.sha512`，官方 dlcdn 的 sha512 也拉不到，跳过校验，靠解压后 `mvn -v` 验证完整。
- 步骤：
  1. 解压：`Expand-Archive -Path .\apache-maven-3.9.16-bin.zip -DestinationPath 'E:\' -Force`，得到 `E:\apache-maven-3.9.16`
  2. 设用户环境变量：`MAVEN_HOME=E:\apache-maven-3.9.16`；用户 `Path` 末尾追加 `E:\apache-maven-3.9.16\bin`
  3. 重开终端，`mvn -v` 输出 `Apache Maven 3.9.16` + `Java version: 27.0.1` 即成功
- 已验证：`mvn -v` → Maven 3.9.16，Maven home `E:\apache-maven-3.9.16`，Java 27.0.1（runtime `E:\JDK27`，说明 `JAVA_HOME` 已经是 JDK27）。
- 卸载/恢复：删目录 `E:\apache-maven-3.9.16`；删用户变量 `MAVEN_HOME`；从用户 `Path` 里删掉 `E:\apache-maven-3.9.16\bin`。
- IDEA 里想用这份：Settings → Build, Execution, Deployment → Build Tools → Maven → `Maven home path` 选 `E:\apache-maven-3.9.16`（不选就用 IDEA 自带的）。

### #11 在 IDEA 里拉取别人分支的更新、提交推送、发合并请求

- 结论：三件事分开做——**拉更新**用 Fetch + Merge into Current，**提交**用 Ctrl+K 提交 + Ctrl+Shift+K 推送，**合并进主线**走网页合并请求（Codeup 的 Merge Request）。
- 一、把别的分支的更新拿到自己分支（如 `master` → 你的 `c-1.0`）：
  1. `Alt+9` 打开 Git 工具窗口 → 点顶部 **Fetch**（向下双箭头），先把远端拉到本地
  2. 在 Log 里右键 `origin/master` → **「Merge into Current」**（等价：菜单 `Git → 合并`，选 `origin/master`）
  3. 有冲突会弹三栏合并窗口：**两边内容都要保留**（尤其 `pom.xml` 的 `<modules>`，别默认只留一边），改完点「应用更改」
  4. 合并完 `Ctrl+K` 提交这次合并
- 二、提交并推送自己的分支：
  1. `Ctrl+K`（提交）：只勾要提交的源码，填提交消息，点「提交」
  2. `Ctrl+Shift+K`（推送）→ 选自己的分支（如 `origin/c-1.0`）→ Push
  3. 也可以 `Ctrl+K` 后直接点「提交并推送」
- 三、把自己的分支合并进 master（团队流程）：
  1. 浏览器打开 Codeup 项目 → 左侧 **「合并请求」** → **「新建合并请求」**
  2. 源分支选自己的（如 `c-1.0`），目标分支选 `master`
  3. 填标题说明 → 提交 → 等负责人审批合并
  4. 团队允许直推时才能本地做：切到 master → 合并自己分支 → push；但 master 一般有保护规则，直接 push 会被拒
- 坑：
  - 别点「**将 c-1.0 变基到 origin/master**」（rebase）——会改写你的提交历史，新手别用
  - 合并前工作区要干净：有未提交改动先 `Ctrl+K` 提交，或 Git 窗口「储藏更改」，否则切分支/合并会被拦
  - 冲突点「应用更改」前核对：`pom.xml` 的 `<modules>` 两边模块都要在，漏一边会导致后面的模块找不到
  - 只推自己的分支（`origin/c-1.0`），别直接推 master（绕过 review，且多数被保护规则拒绝）
  - 顺序别反：先合并最新 master 进来 → 验证能构建 → 再 push → 最后发合并请求

### #12 用 Docker 启动项目依赖的中间件（Redis + Nacos）

- 结论：进项目根目录敲一句 `docker compose up -d`，就把 Redis + Nacos 两个容器拉起来；用 `docker compose ps` 确认，浏览器开 `http://localhost:8848/nacos` 验证。
- 前提：Docker Desktop 已启动（管理员 PowerShell 里 `docker version` 能看到 Server 段）。命令用 `docker compose`（新版内置 v2 插件），不是旧的 `docker-compose`。
- 一、启动：
  1. `cd E:\study\zhiwei-cloud`（换成你自己的项目路径）
  2. `docker compose up -d` —— `-d` 表示后台运行；首次执行会自动拉 `redis:7.4-alpine` 和 `nacos/nacos-server:v2.4.3` 两个镜像
  3. 只想先拉镜像、不启动：`docker compose pull`
- 二、验证（三步都过才算成功）：
  1. `docker compose ps` —— 应看到 `zhiwei-redis`、`zhiwei-nacos` 两个容器状态是 `Up`（Nacos 冷启动要 20~60 秒，可能先 `Up` 后短暂 unhealthy，再变正常）
  2. `docker compose logs -f nacos` —— 日志里出现 `Nacos started successfully` 才算真的起来了（`Ctrl+C` 退出日志，不会停容器）
  3. 浏览器开 `http://localhost:8848/nacos` —— 能出登录页就通了；账号密码默认都是 `nacos`
- 三、日常操作：
  - 停止、保留数据：`docker compose stop`
  - 停止并删除容器、保留数据卷：`docker compose down`
  - 连数据卷一起删（清空数据）：`docker compose down -v`
  - 只重启 Nacos：`docker compose restart nacos`
- 原理一句：`docker-compose.yml` 把每个中间件的镜像、端口、环境变量、数据卷写死，`up -d` 按文件一次性把容器全建好，不用一个个 `docker run` 记参数。
- 坑：
  - 端口被占会直接启动失败：6379（Redis）、8848 / 9848（Nacos）。查占用：`netstat -ano | findstr :8848`，再按 PID 结束进程
  - Nacos 连的是外部 PolarDB（地址写在 `docker-compose.yml` 的 `MYSQL_SERVICE_HOST`），本机不用装 MySQL，但要能连通那个地址，否则 Nacos 起不来
  - 首次拉镜像慢：Docker Desktop → Settings → Docker Engine 里配镜像加速，或换网络重试
  - `docker-compose`（带横杠）是 v1，新版 Docker 已不带它，只认 `docker compose`（空格）
  - `up -d` 报错先看最后几行，再用 `docker compose logs <服务名>` 定位具体是哪个容器的问题
